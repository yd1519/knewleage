- TAA 不是一个固定标准算法：不同游戏在 Velocity、Depth、History Validation、Neighborhood Clipping、Sharpen、Reactive Mask、Upscaling 上有不同设计。本文给出可复现的教学方案并标注近似和局限。

## 一、什么是 Aliasing？为什么游戏画面会有锯齿？

### 1. Aliasing 的本质是什么？

连续场景的空间或时间信号经过有限采样后，若信号频率超过采样率能表达的范围，原本的高频内容会“折叠”成错误的低频模式，从而出现锯齿、摩尔纹、闪烁、爬行的阴影边缘或时间不稳定。

抗锯齿（Antialiasing）的核心不是简单模糊，而是在**有限采样预算内更合理地过滤与重建信号**。

### 2. Nyquist 定理怎么关联到像素采样？

对理想一维带限信号，采样频率要大于最高信号频率的两倍才能在理想条件下正确重建。图像是二维信号，渲染还包括时间维度和几何 Visibility Discontinuity，因此实际情况更复杂。

假设像素间距为 `Δx`，对应采样频率：

$$
f_s=\frac{1}{\Delta x},
\qquad
f_{\mathrm{Nyquist}}=\frac{f_s}{2}.
$$

如果一组黑白条纹在屏幕上的变化比一个像素可以表达的频率更高，就可能出现莫尔纹。增加原始贴图分辨率**不一定**能改善，反而可能增加高频能量。

### 3. 锯齿只有三角形轮廓一种吗？

不是，常见至少有以下几类：

| Aliasing 类型 | 典型表现 | 常见来源 |
|---|---|---|
| Geometric/Edge Aliasing | 斜线出现阶梯、远处栅栏断裂 | 三角形 Coverage 的离散采样 |
| Texture Aliasing | 远处棋盘闪烁、摩尔纹 | Minification 过滤不足、缺少 Mipmap |
| Shader/Specular Aliasing | 金属高光亮点乱跳 | 高频 Normal、尖锐 BRDF、程序噪声 |
| Shadow Aliasing | 阴影边缘爬行和格子 | Shadow Map 分辨率、PCF/CSM 不稳定 |
| Alpha-Test Aliasing | 树叶、草、小孔洞消失或闪烁 | Cutout Threshold 的二值判定 |
| Temporal Aliasing | 相机移动时细线闪烁、影像抖动 | 帧间采样未正确重建/历史不稳定 |

### 4. Spatial Aliasing 与 Temporal Aliasing 有什么区别？

Spatial Aliasing 发生在单帧空间采样中，通常表现为边缘阶梯与高频纹理混叠；Temporal Aliasing 发生在帧与帧之间，物体/相机运动使可见结果不稳定。

**一个单帧静态截图看起来边缘够平滑，不代表视频一定稳定。** 游戏抗锯齿必须考虑时间连续性。

### 5. 为什么直接高斯模糊整张图不是真正的高质量 AA？

大范围 Blur 可以抑制部分高频，但会无差别损害文字、UI、纹理细节与高光清晰度，且无法可靠恢复缺失的几何 Coverage 和运动信息。

高质量 AA 应区分何处发生边缘/走样、该怎样采样或利用历史重建，而不只是降低全图锐度。

### 6. Sample、Pixel、Fragment 和 Texel 有什么区别？

- Pixel：Render Target 的最终图像位置。
- Sample：像素内部的一个具体覆盖/深度/颜色采样点。
- Fragment：光栅化产生的候选片元，MSAA 下一个 Fragment 可关联多个覆盖样本。
- Texel：纹理资源中存储的离散数据，不等同于屏幕 Sample。

理解这些不同层次，是后续解释为什么 MSAA 不自动解决 Specular Aliasing 的前提。

## 二、Sampling / Reconstruction：抗锯齿到底在近似什么？

### 1. 一个像素的理想颜色是像素中心的颜色吗？

从图像形成和 Pixel Footprint 的角度，可将理想像素值理解为连续图像经适当 Pixel Reconstruction/Low-Pass Filter 后在像素位置上的结果，而不是简单取中心点：

$$
\boxed{
C_{\mathrm{pixel}}=
\int_{\mathbb R^2}
C(x,y)\,h(x-x_p,y-y_p)\,\mathrm dx\,\mathrm dy.
}
$$

其中 `h` 是归一化滤波核，`(xp,yp)` 为像素中心。具体实时渲染器不会真的对连续图像做解析积分。

### 2. 为什么 Supersampling 有用？

对一个像素覆盖的多个位置计算/近似场景颜色，再按核聚合，可以更好捕获斜线和子像素几何的覆盖变化。

若用 `N` 个样本估计适当积分：

$$
\widehat C_{\mathrm{pixel}}=
\frac1N\sum_{i=1}^{N}C(x_i,y_i)
$$

是等权 Box 型估计的一种简化，样本设计、Coverage 和重建核决定实际质量；**不是所有抗锯齿都恰好使用均匀等权 Box Filter**。

### 3. 为什么增加样本数仍不能消除所有锯齿？

因为场景并非严格带限，有阴影可见性、镜面高光、透明 Cutout、程序化细节等高频变化。有限样本仍可能欠采样，此外还受采样模式、Shader Filtering、LOD、数值稳定性影响。

### 4. 为什么 AA 与 Mipmap 不是互相替代？

Mipmap 主要处理纹理 Minification 时的预过滤；SSAA/MSAA/TAA 处理的是 Rendered Image/Geometry/Time 中其他层面的采样问题。

Mipmap 可以减少远处纹理闪烁，但不会自动让三角形边界 Coverage 平滑；MSAA 可以平滑边界，却不会自动对高频 BRDF 进行预积分。

## 三、SSAA：Super-Sampling Antialiasing

### 1. SSAA 的基本思路是什么？

以高于目标输出的分辨率渲染场景，再以合适的低通/重建滤波核 Downsample 到目标分辨率。

例如要输出 1920×1080，可以在 3840×2160 处渲染，再降采样。这是每个维度 2 倍、总像素数 4 倍的 `4x` 空间 Supersampling。

### 2. SSAA 为什么效果通常很好？

它对高分辨率时被实际执行/表示的各种场景变化进行更密采样：

- 几何边缘 Coverage。
- Shader 和材质光照变化。
- 部分透明/Alpha-Test 细节。
- 纹理与阴影等空间信号。

这并不等于保证解决所有高频与时间混叠，但覆盖面通常比仅做几何边缘 AA 更广。

### 3. SSAA 为什么昂贵？

二维尺寸按因子 `s` 放大后，像素数量大致乘 `s²`：

$$
\boxed{
N_{\mathrm{renderPixels}}=s^2 N_{\mathrm{outputPixels}}.
}
$$

`s=2` 即约 4 倍像素数，影响 GBuffer/HDR/Depth、Pixel/Compute Work、Bandwidth、Postprocessing 等。还可能增加资源尺寸和显存压力。

### 4. SSAA 和把显示器分辨率调高是同一个概念吗？

不完全相同。SSAA 的关键是**最终 Downsample 到固定目标显示网格**并使用合适的 Filter。输出显示分辨率直接改变，可能连 UI、Viewport、显示设备采样也发生变化。

### 5. Downsample 使用简单 Box Average 一定最好吗？

不是。Box 易实现但频域响应有限，可能存在模糊或残余走样。高质量 Reconstruction Kernel（如合适的 Tent/Catmull-Rom/Lanczos 及抗振铃策略）可改善视觉效果，但可能出现 Overshoot/Ringing，需要具体权衡。

## 四、MSAA：为什么它不是“每个像素运行 4 次 Pixel Shader”？

### 1. MSAA（Multisample Antialiasing）主要做什么？

MSAA 在一个 Pixel 内维护多个**Coverage/Depth/Stencil Sample**，利用 Sample Mask 决定三角形覆盖了哪些采样点。最终 Resolve 综合每 Sample 的贡献，使几何边缘过渡更平滑。

**常见情况下 Fragment Shader 仍可以按较低频率执行并将结果共享给多个 Coverage Sample。** 是否按 Sample Shading 频率执行依 Shader 状态、显式 Sample 输入与 API 规定。

### 2. MSAA 4x 具体意味着什么？

一个 Pixel 使用四个样本位置进行几何覆盖/深度等操作；如果只画一块跨过该 Pixel 的三角形，它可能覆盖 1、2、3 或 4 个 Sample。

比如白色三角形覆盖四个样本中的一个，背景为黑色，简化 Resolve 后：

$$
C=\frac14 C_{\mathrm{foreground}}
+\frac34 C_{\mathrm{background}}.
$$

实际 Resolve/颜色样本值取决于着色频率、混合、样本覆盖和具体格式，并非所有场景仅由覆盖数量决定。

### 3. MSAA 是怎么降低斜边锯齿的？

单 Sample Rasterization 对三角形是否覆盖像素中心做二值判断；MSAA 在多个子像素位置判断 Coverage，使边界像素携带更细粒度的覆盖率信息，在 Resolve 后形成平滑过渡。

### 4. MSAA 为什么通常不能很好解决 Shader Aliasing？

如果 Fragment Shader 只在 Pixel Frequency 执行一次，高频 Specular/Normal/程序纹理信号仍可能只被单点采样；即使有 4 个 Coverage Samples，也没有相应获得 4 个独立的 BRDF 采样。

启用 Sample Shading 可更细粒度地计算颜色，但显著增加 Shader Work，并且也无法保证完全消除所有高频。

### 5. MSAA 的 Coverage、Depth、Color Sample 都一定存四份吗？

不应做绝对假设。API 抽象上是多样本图像，Coverage/Depth/Stencil 和颜色语义可以具有多样本表示；实际硬件常使用 Tile/Compression/Shared Shading/特殊存储优化。显存和带宽成本取决于格式、Sample Count、压缩以及具体 GPU。

### 6. 什么是 Centroid Interpolation？

在 MSAA 边缘处，像素中心可能不在当前三角形内部，如果直接在像素中心插值 UV 可能取到几何外推值。

Centroid Interpolation 会选择三角形覆盖区域内合适的位置用于插值，降低边界纹理取样等问题，但不能保证每个 Sample 都有独立的正确材质值。

### 7. 什么是 Per-Sample Shading？

某些 API/Shader 状态允许按 Sample 频率执行 Fragment Shader（或设定最小 Sample Shading 比例），而不仅仅共享 Pixel Frequency 结果。

OpenGL 可以使用 `glMinSampleShading` 等相关状态（需要对应版本/能力）控制最小采样频率，但具体着色次数不应仅根据 Sample Count 武断断言。

### 8. 为什么 MSAA 与 Deferred Rendering 结合有难度？

Deferred Renderer 的 GBuffer 可能包含 Albedo、Normal、Roughness、Depth 等多样本属性。如果边缘处四个 Sample 来自不同三角形，就需要保留或重建**每 Sample 材质/表面信息**，而非简单 Resolve 各 GBuffer 后做一次 Lighting。

对 GBuffer 法线、粗糙度等直接线性 Resolve 可能造成非物理材质混合。常见工程策略包括按样本的 Deferred Shading、Edge-Aware 特殊处理、混合 Forward Path 或转向 TAA/后处理方案。

### 9. 透明物体能用 MSAA 吗？

可以对 Coverage、深度及样本混合产生影响，但**Alpha Blending 不等于几何 Coverage**，常见 MSAA 不能自动解决透明物体排序与多层混合。Alpha-to-Coverage 可将部分 Alpha 转为多样本覆盖近似，对叶片等 Masked Geometry 特别有用。

## 五、Alpha-to-Coverage、Sample Mask 与 Resolve

### 1. Alpha-to-Coverage（A2C）是什么？

根据 Shader 输出的 Alpha，为 MSAA 样本生成/调制 Coverage Mask，使透明程度以子像素覆盖样本比例的形式体现，而不是简单地在一个像素位置硬性 `discard`。

典型用途：植物叶片、草、栅栏等 Cutout/Masked Geometry。

### 2. 为什么 A2C 能减少植被闪烁？

传统 Alpha Test 在单点判断阈值时是 0/1，细叶片在远距离可能忽隐忽现。A2C 使用多个样本的部分覆盖表示中间 Alpha，有助于改善轮廓锯齿。

但低 Sample Count 时 Coverage 级别仍是离散的，可能有颗粒/抖动；不同驱动的 Alpha-to-Coverage 映射方式可能不同。

### 3. A2C 是否等同于透明 Alpha Blending？

不是：

- A2C：改变覆盖哪些 Sample，常用于几何/Masked 类的近似覆盖。
- Alpha Blending：按照混合方程计算颜色与目标的组合。
- 多层半透明：还需考虑排序或 OIT 等。

A2C 可能在同一像素中的多个多样本对象之间改善可见性，但并不完整解决所有半透明光学传输。

### 4. MSAA Resolve 到底在做什么？

Resolve 将 Multisampled Attachment 转换为普通 Single-Sample 纹理。对颜色附件，常见思路为合并 Sample Colors；Depth/Stencil Resolve 的支持及选取规则则依 API 和具体方式，不应该无条件假设等于平均深度。

### 5. OpenGL 的一个 Color MSAA Resolve 思路

~~~cpp
// Preconditions:
//  - msaaFBO contains a complete multisampled color attachment.
//  - resolvedFBO contains a matching single-sample color attachment.
//  - dimensions and formats are compatible under GL rules.

glBindFramebuffer(GL_READ_FRAMEBUFFER, msaaFBO);
glBindFramebuffer(GL_DRAW_FRAMEBUFFER, resolvedFBO);

glBlitFramebuffer(
    0, 0, width, height,
    0, 0, width, height,
    GL_COLOR_BUFFER_BIT, GL_NEAREST);
~~~

这是对整个区域进行多样本 Color Resolve 的常用 API 路径之一。具体的 FBO 状态、Attachment Sample Counts、Integer Format、格式兼容和颜色空间设置都必须检查。不能在不满足规则时将 `GL_LINEAR` 强行当作 MSAA Resolve 核。

### 6. 为什么 HDR Resolve 和 sRGB 需要注意计算顺序？

对正确物理意义的颜色混合/平均，应在适当的线性空间处理，再进行 Tone Mapping 和显示编码。不要把 sRGB 编码后的值直接做简单算术平均，还将结果解释为线性能量平均。

## 六、FXAA：基于图像边缘的快速后处理

### 1. FXAA（Fast Approximate Anti-Aliasing）做了什么？

FXAA 不要求多样本 GBuffer。它在屏幕图像中检测局部高对比度边缘，沿边缘方向搜索/滤波，使锯齿边缘更平滑。

常在 Final Image 或接近最终颜色的某一 Pass 上运行，速度快、集成成本低。

### 2. FXAA 怎么确定边缘方向？

一个简化的思路：先使用 Luma 对局部像素进行比较，估计梯度和边缘的主方向，再沿边缘进行有限的局部采样。

但完整 FXAA 实现包含局部阈值、边缘方向搜索、对子像素纹理噪声的处理等，不等同于“对任何高对比度像素做 3×3 平均”。

### 3. 为什么 FXAA 容易让文字和细节变模糊？

它只能看到**已经光栅化后的颜色**，无法严格知道当前高对比度变化是几何边缘、文字边缘还是应该保留的纹理细节。误判时会修改本来不该滤掉的高频信号。

### 4. FXAA 能解决严重的 Temporal Shimmering 吗？

通常不擅长。FXAA 每帧主要根据当前图像工作，没有历史重投影机制；对远处一像素宽的细线即使每帧滤得更柔，仍可能在相机移动时出现明显的时域闪烁。

### 5. FXAA 为什么在前向低成本渲染器仍有价值？

实现简单、无需 Motion Vector/History、可直接对单样本颜色做后处理。对 UI 不敏感或追求性能的平台，很容易作为质量模式之一。

但若已有稳定的 TAA/高质量 Spatial Upscaling，叠加 FXAA 可能造成重复平滑。

## 七、SMAA：边缘检测与模式识别

### 1. SMAA 与 FXAA 的区别？

SMAA（Subpixel Morphological Antialiasing）也可采用屏幕空间形态学边缘处理，但更强调边缘模式/搜索、Area/Lookup Texture 和针对几何形状的覆盖估计。

在许多画面中，它可以比简单 FXAA 更有选择性地平滑边缘，但具体质量取决于 SMAA 模式、输入图像和实现参数。

### 2. SMAA 1x 的典型三个阶段？

~~~text
Current Color
      |
      v
Edge Detection
      |
      v
Blending Weight Calculation
  (pattern searches + area/search data)
      |
      v
Neighborhood Blending
      |
      v
AA Color
~~~

### 3. SMAA 能否利用 MSAA 或时间信息？

存在不同变体/模式，例如结合额外样本或时间复用的设计。不能将所有 SMAA 实现都描述成“永远只需要一个后处理 Pass 的 SMAA 1x”。

### 4. 为什么边缘检测常考虑 Luma、Color 或 Depth？

- Luma：实现较简洁，适合亮度边缘。
- Color：可以找到某些亮度接近但颜色不同的边缘。
- Depth：可以帮助识别几何/遮挡边界，但无法捕获所有颜色/材质边缘。

不同策略的误检/漏检特点不同。若只依赖 Depth，可能漏掉纯材质或颜色纹理的高对比边缘。

### 5. SMAA 是否能替代 Mipmap/Specular AA？

不能。它主要对已经形成的屏幕空间图像做边缘处理，高频纹理或极尖锐高光已发生的采样混叠未必能被恢复。

## 八、四种常见 Spatial AA 的比较

### 1. SSAA、MSAA、FXAA、SMAA 的直观对照

| 技术 | 在哪里处理 | 主要改善 | 常见成本/弱点 |
|---|---|---|---|
| SSAA | 高分辨率渲染 + Downsample | 几何、部分 Shader、纹理空间走样 | Pixel Work 和带宽显著增加 |
| MSAA | 光栅化 Sample Coverage/Depth | 几何边缘 | Shader/纹理/镜面高频不一定改善 |
| FXAA | 当前颜色后处理 | 屏幕高对比边缘 | 容易模糊细节，时域问题仍在 |
| SMAA 1x | 边缘检测 + 形态学混合 | 规则几何与屏幕边缘 | 缺历史信息，漏掉部分时域闪烁 |

### 2. 哪种方法最“正确”？

没有无条件最优。SSAA 最直接但贵；MSAA 在 Forward 和几何边缘上很有效；FXAA/SMAA 便于作为低成本后处理；TAA 则用跨帧采样和历史重建换取稳定性，但需要处理 Ghosting/Blur。

选型应结合 Forward/Deferred、分辨率、移动性能、透明材质、UI、帧预算及目标画风。

## 九、TAA：Temporal Antialiasing 的核心思路

### 1. 为什么 TAA 可以利用多帧提升画质？

传统单帧 AA 只知道当前帧有限的像素样本。TAA（Temporal Antialiasing）让不同帧的摄像机投影在子像素位置轻微变化，从而随时间积累不同位置的采样信息。

只要能将上一帧的历史颜色正确**重投影到当前像素对应的表面**，多个帧的样本就有机会近似提高采样密度并降低时间闪烁。

### 2. TAA 基础管线是什么？

~~~text
Frame t:
Camera Projection + Subpixel Jitter
                    |
                    v
         Current HDR Scene Color
              Depth + Velocity
                    |
                    v
   History Reprojection (previous UV)
                    |
                    v
        History Validation
 (disocclusion, depth, reactive, bounds)
                    |
                    v
 History Neighborhood Clip / Clamp
                    |
                    v
 Current + Validated History Blend
                    |
                    v
     TAA Output / History for t+1
~~~

通常 History 会以 Ping-Pong Render Targets 保存，避免同一时刻在同一资源上进行冲突的读写。

### 3. TAA 只有一个简单的“当前帧 10% + 历史帧 90%”吗？

不是。加权混合只是最后一步。如果没有正确的 Motion Vector、历史有效性判断、颜色 Clamp、抗 Ghosting 和一致的 Jitter 约定，即使固定权重为 0.9 也会出现严重残影。

一个最简的概念公式：

$$
\boxed{
C_t^{\mathrm{out}}=
(1-\alpha_t)\,\widetilde C_{t-1}
+\alpha_t\,C_t^{\mathrm{current}}.
}
$$

`alpha_t` 是当前帧权重（这里越大越偏向新颜色），`C_history~` 是经重投影、有效性处理、必要颜色/曝光修正后的历史采样结果。

### 4. TAA 为什么可能比 FXAA 更稳定？

TAA 不局限于当前帧已经出现的屏幕像素。跨帧 Jitter 会改变细线、高光、纹理与边缘的采样位置，正确 History Accumulation 可以将其平均，从而减少运动中的闪烁和爬行。

但错误的 History Accumulation 同样会制造 Ghosting/Blur，不能保证 TAA 在每个场景都优于其它 AA。

### 5. 为什么 TAA 需要 Motion Vector？

如果相机或物体运动，同一个世界空间表面点通常对应不同屏幕 UV。直接用当前 Pixel UV 采样上一帧颜色，将混合到**不同的表面**。

Motion Vector 就是把当前像素映射回其上一帧屏幕位置的线索，通常在 GBuffer 或独立 Velocity Pass 生成。

### 6. TAA 为什么可以看作时域重建，而不是单纯平滑？

不同帧通过 Jitter 取得不同子像素位置的样本，历史积累是在尝试**重建一个更稳定的空间信号**。如果只是没有抖动地一直取完全相同的采样位置，单纯历史平均无法凭空获得更多几何子像素信息，只能平均噪声/变化。

## 十、Projection Jitter：怎么让每帧采不同子像素？

### 1. 什么是 Camera Jitter？

每帧轻微移动摄像机的投影采样位置，通常以目标 Render Resolution 的**子像素单位**指定，使几何边缘和高频内容相对 Pixel Center 发生细小位移。

Jitter 不等于真正移动 Camera World Transform；最好在**投影**层引入受控偏移，保持场景几何和物理 Camera Pose 的定义不变。

### 2. 如何把像素单位 Jitter 转为 NDC？

假设 Render Target 宽高为 `W,H`，子像素偏移为 `j_px=(jx,jy)`，单位为 Pixel：

$$
\boxed{
\mathbf J_{\mathrm{uv}}=
\left(\frac{j_x}{W},\frac{j_y}{H}\right),
\qquad
\mathbf J_{\mathrm{ndc}}=
2\mathbf J_{\mathrm{uv}}.
}
$$

这里采用本篇 UV 与 NDC Y 同向的约定。若 Render Target 使用向下的 Y UV，必须调整符号及屏幕映射。

### 3. 为什么修改 Clip XY 时要乘 Clip W？

希望透视除法之后产生恒定的 NDC 偏移：

$$
\frac{x_c+J_x w_c}{w_c}
=\frac{x_c}{w_c}+J_x.
$$

因此可以在 Vertex Shader 中：

~~~glsl
vec4 clip = uProjection * uView * worldPosition;
clip.xy += uJitterNDC * clip.w; // uJitterNDC = 2*jitterPx/renderSize
gl_Position = clip;
~~~

这段代码示意的是**最终 Clip Space 添加恒定 NDC Shift**。如果通过修改 Projection Matrix 的某些元素实现，必须考虑矩阵行列约定、Clip W 符号和 API 坐标系，不能无条件复制某个矩阵下标。

### 4. 为什么每帧需要一组不同的 Jitter？

如果每帧 Jitter 完全一样，时间序列不会从不同子像素位置获得新信息；在静态场景里相当于重复采同一位置。

使用有限长度循环序列或低差异序列可以在合理范围内更均匀覆盖像素区域，降低不规则的空间采样误差。

### 5. Halton 2,3 序列为什么常用于 TAA？

Halton Sequence 基于不同底数的 Radical Inverse（常用 2 和 3），生成低差异二维分布。把 `[0,1)` 的序列减去 0.5，就能得到以像素中心为原点的约 `[-0.5,0.5)` 采样偏移：

$$
\boxed{
\mathbf j_i=
\left(\phi_2(i)-\frac12,\,
\phi_3(i)-\frac12\right).
}
$$

常见实现从 `i=1` 开始，避免某些序列定义中 `i=0` 的特殊原点；序列长度和是否加随机扰动由项目决定。

### 6. 一个可直接测试的 C++ Halton 实现

~~~cpp
#include <glm/glm.hpp>
#include <cstdint>

float Halton(std::uint32_t index, std::uint32_t base)
{
    float result = 0.0f;
    float factor = 1.0f / static_cast<float>(base);

    while (index > 0)
    {
        result += factor * static_cast<float>(index % base);
        index /= base;
        factor /= static_cast<float>(base);
    }
    return result;
}

glm::vec2 GetTAAJitterPixels(std::uint32_t frameIndex)
{
    const std::uint32_t i = (frameIndex % 8u) + 1u;
    return glm::vec2(Halton(i, 2u), Halton(i, 3u)) -
           glm::vec2(0.5f);
}

glm::vec2 GetJitterNDC(
    std::uint32_t frameIndex, glm::vec2 renderResolution)
{
    return GetTAAJitterPixels(frameIndex) * 2.0f /
           renderResolution;
}
~~~

**前提：** Resolution 的两个维度必须大于零；Halton `base≥2`。这里采用 8 帧循环只是教学例子，不代表所有 TAA 系统必须使用 8 个样本。

### 7. 为什么 Jitter 一定要和 Motion Vector、History UV 使用一致的定义？

因为当前帧的几何投影被 Jitter 改变，上一帧也被不同的 Jitter 改变。如果 Velocity 计算完全忽略两次 Jitter，而 History Reprojection 却直接按**抖动后的 Color UV**采样，静态几何也会发生错位。

解决思路有两类：

- Velocity 表示两次**包含 Jitter 的 UV 差**，直接用于重投影。
- Velocity 使用两次**非抖动的投影**，然后显式在重投影中加上 Previous/Current Jitter 差。

**二选一，不能混用。**

### 8. Camera Jitter 是否应该影响 Shadow CSM、UI 与屏幕空间噪声？

通常不应让 Jitter 无意破坏原本稳定的系统：

- UI 通常在最终输出分辨率绘制，不跟随 3D 子像素投影 Jitter。
- CSM 计算 Stable Light Projection 时常采用未抖动的 Camera Frustum。
- SSAO/SSR/Contact Shadow 等 Screen-Space Pass 需要清楚是否使用 Jittered Depth/Projection。
- Motion Vectors、Depth Reconstruction 必须使用正确的本帧投影约定。

## 十一、Motion Vector：从当前位置追到上一帧

### 1. Motion Vector 的数学定义是什么？

对当前像素代表的**同一场景表面点**，令当前与上一帧的纹理坐标分别为 `uv_t` 和 `uv_{t-1}`。本文统一：

$$
\boxed{
\mathbf v_{\mathrm{uv}}=
\mathbf{uv}_t-\mathbf{uv}_{t-1}.
}
$$

那么 History Reprojection：

$$
\boxed{
\mathbf{uv}_{\mathrm{history}}=
\mathbf{uv}_{\mathrm{current}}-
\mathbf v_{\mathrm{uv}}.
}
$$

**注意符号约定：** 有些引擎使用 Previous−Current，此时 Shader 要改为加 Velocity。不能只凭资源名称猜测。

### 2. 为什么 Velocity 常用 RG16F 等格式？

Motion Vector 通常是二维连续值，既可能很小又可能很大。浮点的双通道格式能储存子像素精度与一定动态范围，常见选择如 `RG16F`；但是格式需根据屏幕尺寸、动态范围、带宽和是否编码/压缩决定。

### 3. 两次 Clip Position 怎样计算 UV Velocity？

对同一表面点的当前/上一帧 Clip 坐标：

$$
c_t=P_t V_t M_t p_{\mathrm{local}},
\qquad
c_{t-1}=P_{t-1}V_{t-1}M_{t-1}p_{\mathrm{local}}.
$$

使用本篇**抖动后坐标**约定：

$$
\mathbf{uv}_t=
\frac12\left(\frac{c_{t,xy}}{c_{t,w}}+\mathbf 1\right),
\qquad
\mathbf{uv}_{t-1}=
\frac12\left(\frac{c_{t-1,xy}}{c_{t-1,w}}+\mathbf 1\right).
$$

两者相减得到 `velocityUV`。只计算 Current View Projection 与 Previous View Projection 的矩阵还不够：若物体自己运动，上一帧必须使用**对应的 Previous Model Transform/Deformation**。

### 4. 为什么只用 Camera Transform 生成 Motion Vector 不正确？

相机不动但角色跑动时，像素对应的表面点仍在屏幕上移动；如果 Velocity 只由 Camera Motion 产生，这些像素会错误地使用原屏幕位置的历史颜色，导致角色拖尾。

Skinned Mesh 还要知道上一帧对应的 Bone Transforms；仅有上一帧的 Object Matrix 也无法表示骨骼、布料、Morph、风吹草等顶点形变。

### 5. GLSL Vertex Shader 怎样输出 Current/Previous Clip？

~~~glsl
#version 450 core

layout(location=0) in vec3 aPosition;

uniform mat4 uCurrentModel;
uniform mat4 uPreviousModel;
uniform mat4 uCurrentViewProjectionJittered;
uniform mat4 uPreviousViewProjectionJittered;

out vec4 vCurrentClip;
out vec4 vPreviousClip;

void main()
{
    vec4 local = vec4(aPosition, 1.0);

    vCurrentClip =
        uCurrentViewProjectionJittered * uCurrentModel * local;
    vPreviousClip =
        uPreviousViewProjectionJittered * uPreviousModel * local;

    gl_Position = vCurrentClip;
}
~~~

**工程重点：** 若使用 Skinning/Morph/Wind，`local` 必须替换为当前/上一帧对应的形变位置。上一帧位置的插值/裁剪在三角形边界和几何变更时还有不连续情况，这只是最小教学示例。

### 6. Fragment Shader 中怎样输出 UV Motion？

~~~glsl
#version 450 core

in vec4 vCurrentClip;
in vec4 vPreviousClip;
layout(location=0) out vec2 outVelocityUV;

void main()
{
    // The normal valid path assumes both W values are positive.
    if (vCurrentClip.w <= 1e-6 ||
        vPreviousClip.w <= 1e-6)
    {
        outVelocityUV = vec2(0.0);
        return;
    }

    vec2 currNDC = vCurrentClip.xy / vCurrentClip.w;
    vec2 prevNDC = vPreviousClip.xy / vPreviousClip.w;

    outVelocityUV = 0.5 * (currNDC - prevNDC);
}
~~~

`outVelocityUV` 是归一化 UV 位移；如果 History 需要像素位移则乘 Render Resolution。如果产生前后 Clip 在两个不同的 Jitter 约定下，不能直接使用这个差。

**局限：** 这里演示基础的平滑插值 Motion Vector。对跨越 Near Plane 的几何、当前新出现区域、细小 Subpixel Geometry 或屏幕空间对象，需要专门有效性与边界处理，而不是统一写 0 并认为 History 可用。

### 7. 为什么 Motion Vector 不等于 Optical Flow？

Motion Vector 通常来自**渲染器已知的几何和矩阵**，是对对应表面投影位移的估计；Optical Flow 通常从图像亮度变化推断运动，不需要直接知道几何。

二者都可描述屏幕运动，但对透明、遮挡、无纹理区域和运动中的光照变化具有不同误差特性。

### 8. Skybox 和 Camera Rotation 怎样处理 Velocity？

对于无限远 Skybox，平移不应像有限距离物体那样产生视差，但摄像机旋转会改变方向投影。可由 Previous/Current View Rotation 与 Projection 得到 Sky Velocity，或由独立 Sky Pass 处理 History。

简单将天空全部 Velocity 设 0，在相机旋转时可能产生明显的天空拖尾。

## 十二、History Reprojection 与双缓冲

### 1. TAA 是如何从上一帧采样 History 的？

假设当前 Pixel UV 为 `uv`，Velocity Texture 中存本篇的 `currentUV-previousUV`：

~~~glsl
vec2 velocityUV = texture(uVelocity, uv).xy;
vec2 historyUV = uv - velocityUV;
vec3 historyColor = texture(uHistory, historyUV).rgb;
~~~

但真实 TAA 不应立刻混合，还要确认 History UV 有效、相应表面没有被新几何遮挡，并进行合适的 History Validation/Clamping。

### 2. 为什么 History 不能每帧覆盖原图后直接在同一个 Texture 中读写？

当一个 Pass 同时读 History 又写同一个纹理同一子资源，若没有规定的同步/反馈机制，可能触发 Resource Read-Write Hazard 或未定义的 Texture Feedback 行为。

一个稳妥的数据组织是 Ping-Pong：

~~~text
Frame t:
  History A (read-only) -> TAA Pass -> History B (write)
Frame t+1:
  History B (read-only) -> TAA Pass -> History A (write)
~~~

History A/B 的格式、有效尺寸及曝光状态必须匹配当前算法。

### 3. 什么是 History Invalidation？

当上一帧历史**无法对应当前有效表面/采样位置**，或整个渲染状态发生不兼容变化时，应减小历史贡献甚至完全丢弃。

典型情况：

- Camera Cut / Teleport。
- 视口/渲染分辨率突然改变且没有重采样/转换历史。
- FOV/Projection 明显变化，旧 Velocity/History 无法正确映射。
- 物体突然出现或某区域刚刚露出（Disocclusion）。
- 动态材质/动画变化无法由 Motion Vector 完整描述。
- 预曝光/颜色空间变化未正确补偿。

### 4. 为什么判断 historyUV 在 [0,1] 内还不够？

这个条件只表示历史纹理**有合法采样位置**，不表示当前位置和该历史像素属于同一表面。物体遮挡关系改变时，该 UV 可能采到上一帧背景，产生 Ghosting。

因此需要 Depth/Normal/Object ID、运动/邻域/颜色差异、Reactive Mask 等更多线索。

### 5. 为什么上一帧 History 采样常使用 Bilinear/Catmull-Rom？

HistoryUV 通常不落在整数像素中心，需要重建连续的 History Color。Bilinear 方便但可能变软；Catmull-Rom 或其它锐利重建核可保留更多细节，但需要更多样本或特殊实现，并可能产生 Ringing/Overshoot。

History Filter 的选择与 Neighborhood Clip、Sharpen 和最终画质强相关。

### 6. 为什么应避免把曝光变化误判为新的物体颜色？

若上一帧与当前帧使用不同 Pre-Exposure 或色彩缩放定义，同一真实光照也可能得到不同的 Texture Numeric Values。

应把 History 转换到当前帧使用的统一线性 HDR 量纲再比较/混合；否则明暗适应可能导致残影和闪烁。

## 十三、TAA 的 Ghosting、Blur 和 Shimmering

### 1. Ghosting 是什么？

物体移动后画面中留下不合理的历史轮廓、拖影或颜色残留，就称 Ghosting。

常见原因：错误 Velocity、Disocclusion、新遮挡面、History 过重或 History Clamp 不足。

### 2. 为什么高历史权重容易产生 Ghosting？

固定 `alpha=0.05` 代表每帧只更新 5% 新颜色；历史中的错误颜色会以 `0.95` 的衰减因子慢慢消失。

如果对象已经离开某 Pixel，但该 Pixel 仍错误采到对象颜色，可能需要几十帧才能完全淡去，表现为明显残影。

### 3. 为什么低历史权重也有问题？

让 `alpha` 很大意味着更相信当前单帧，Ghosting 可能减少，但多帧平均的抗走样能力下降，细线、阴影和反射闪烁会重新变得明显。

这是 TAA 最重要的取舍：**稳定性 vs 响应速度/清晰度**。

### 4. Blur 是怎么产生的？

历史 Reprojection 使用纹理过滤，本身可能反复引入低通；Velocity 不准、样本位置错位、过宽的 Neighborhood Clamp 和过重历史平均又会将真实细节扩散。

过强的 Sharpen 虽然能在静态图提升清晰感，但也会加强 Ringing、噪点和 Shimmering。

### 5. Shimmering 和 Ghosting 是相反的现象吗？

它们是不同伪影，可能在同一个画面同时存在：

- Shimmering：高频内容跨帧不稳定，细线、高光或阴影闪烁。
- Ghosting：历史像素错误积累，呈现多余拖尾。
- Blur：空间细节缺失，画面显得软。
- Flicker：明暗/图案快速变化，可能来自多种原因。

TAA 参数优化不只是“残影多就减少 History”，还必须找到 Velocity、Jitter 或信号欠采样的真实来源。

## 十四、History Validation：Disocclusion 与错误重投影

### 1. Disocclusion 是什么？

上一帧某个背景点被前景物体挡住，这一帧由于前景移动而**首次暴露**。这个背景点在上一帧的颜色缓冲中可能没有可用历史样本。

如果强行 Reproject，会取到别的物体颜色，出现背景拖影。

### 2. 为什么比较当前 Depth 与历史 Depth 有用？

将当前 Receiver/Pixel 对应的世界点变换到上一帧视角，得到预期上一帧 Depth；再与 History Depth 在对应 UV 的值比较。

若两者差异明显，可能说明 History Color 对应不同几何表面，从而降低或拒绝历史：

$$
\boxed{
\text{validDepth}\approx
\left|z^{\mathrm{expected}}_{t-1}
-z^{\mathrm{stored}}_{t-1}\right|<\tau_z.
}
$$

其中两个深度必须使用**同一个上一帧设备深度定义或同一种线性距离定义**。阈值需考虑深度精度、投影非线性、斜面、采样滤波和运动。

### 3. 为什么只用当前深度与上一帧同 UV 深度直接比较会错？

当前与上一帧相机/物体姿态不同，两个 Depth Texture 的同一 UV 不一定是同一世界点；即使经过 Motion Reprojection，当前深度和上一帧深度通常仍处于**不同 View Projection 体系**。

应比较通过上一帧 Camera Transform 计算的**预期上一帧深度**与实际 History Depth，或使用设计明确的视空间/世界空间距离一致性度量。

### 4. 为什么法线变化也能用于 Reject History？

同一 UV 的 Depth 差可能很小，但两个表面具有不同法线或材质。比较当前法线与重投影位置的历史法线可以降低跨几何边界的颜色污染。

然而 Normal Map 高频变化很大时，严格阈值可能造成频繁误拒绝与闪烁，需结合距离/速度/材质来调节。

### 5. 为什么 Motion Vector Dilate（膨胀）有用？

细小或快速移动物体的像素边界上，当前 Pixel 的 Depth/Velocity 可能来自背景，而一个邻近 Pixel 来自快速运动前景。直接使用背景 Velocity 容易留下前景历史拖尾。

常见策略是在当前 Pixel 的局部 Depth Neighborhood 中选择代表**最近前景**的 Velocity，或者做 Velocity/Dilation Pass。注意：它是启发式，不能保证所有重叠对象的运动都正确。

### 6. Reprojection 失败时必须返回黑色吗？

不。更合理的回退往往是**直接使用当前帧的重建颜色**，而不是引入不存在的黑色阴影或未初始化值：

~~~glsl
if (!historyValid)
    return currentColor;
~~~

特殊 TAAU 若当前输出 Pixel 没有当前帧精确颜色，则需要从**低分辨率当前帧**按空间重建核取样，不能直接返回未经定义的值。

## 十五、History Neighborhood Clamp 与 Variance Clip

### 1. History Clamp 在做什么？

对当前帧目标像素周围的颜色采样建立一个合理范围，若重投影 History Color 偏离这个范围太远，就将其限制回来，以降低历史中“不可能属于当前局部图像”的颜色残留。

一个最简单的方法是按通道求 3×3 Neighborhood 的最小/最大值：

$$
C_{\min}=\min_{i\in\mathcal N} C_i,\qquad
C_{\max}=\max_{i\in\mathcal N} C_i.
$$

然后：

$$
\boxed{
C_{\mathrm{histClamped}}=
\mathrm{clamp}(C_{\mathrm{history}},C_{\min},C_{\max}).
}
$$

### 2. 为什么 per-channel Min/Max Clamp 不一定理想？

RGB 三个通道单独裁剪会允许本地像素实际上不存在的颜色组合；很亮/很暗的异常邻居也会把有效范围扩张得过宽。

此外强行 Clamp 可能阻止细小真实历史贡献积累，使某些高频区域仍闪烁。

### 3. Variance Clipping 是什么？

在当前 Neighborhood 中计算颜色均值和方差，构造基于标准差的范围：

$$
\mu=\frac1N\sum_i C_i,
\qquad
\sigma^2=\frac1N\sum_i(C_i-\mu)^2.
$$

一种常见形式：

$$
\boxed{
C_{\min}=\mu-\gamma\sigma,\qquad
C_{\max}=\mu+\gamma\sigma.
}
$$

`gamma` 控制 History Allowed Range 宽度。这里 RGB 可以逐通道计算，但也可以用 YCoCg/其他空间定义可裁剪区域。

### 4. Neighborhood Clamping 与 Neighborhood Clipping 的区别？

Clamping 常逐通道将历史点限制进 Axis-Aligned Box；Clipping 则可以从当前参考颜色到历史颜色连一条线，求其与 Box 的交点，把历史沿这条线拉回边界。

相较直接通道 Clamp，Box Clipping 在某些场景中更有利于保留当前与历史之间的颜色方向，但不是无条件更正确。

### 5. 为什么 TAA 常考虑 YCoCg 颜色空间？

YCoCg 将亮度相关分量和两个色度相关分量分离，有时比 RGB 更方便构造 Neighborhood Color Bound 和稳定控制色度残留。

它不是将 RGB 转换成准确物理 Photometric Luminance；需要明确这里的 Y 是**便于过滤的线性颜色组合**。若输入是 Linear HDR，还需要处理数值范围和负值/高亮情况。

### 6. Gamma/Variance Box 越窄一定越好吗？

越窄 History 越容易被 Reject/Clip，从而减少部分 Ghosting，但也可能损失长期 Subpixel 信息、增加 Flicker。越宽越有利于历史稳定，却更容易保留错误历史。

需要结合 Motion/Depth/Material Confidence 做自适应，而不是固定一个万能 Gamma。

## 十六、Adaptive Blending：怎样决定 Current Weight？

### 1. 为什么一个固定 Alpha 无法覆盖所有场景？

静止背景具有稳定 History，可以使用较高历史权重；快速移动的前景、刚暴露背景、闪烁粒子却应更信任当前帧。

可以按 Confidence 调整当前权重，例如：

$$
\boxed{
\alpha_t=
\mathrm{lerp}(\alpha_{\mathrm{stable}},1,c_{\mathrm{invalid}}).
}
$$

`c_invalid` 越接近 1，History 越不可信；`alpha_stable` 代表静态区域中当前颜色的较小基础权重。

### 2. Motion Magnitude 越大就应丢弃全部历史吗？

不一定。若几何运动但 Motion Vector 完全正确，历史仍可能有效；反而**速度梯度大、遮挡边界变化、历史 UV 出界**等情况更值得降低 History Confidence。

把 Motion Magnitude 当作强制 Reject 的唯一依据，会让快速运动物体变得闪烁。

### 3. Reactive Mask 用于什么？

Reactive Mask 标记当前颜色可能随时间快速变化、而 Motion Vector 无法完整描述的区域，例如透明粒子、动画材质、反射高光、屏幕空间效果或动态发光。

这些区域通常需要**提高当前帧贡献、减少错误历史累积**，避免拖尾。

### 4. Reactive Mask 为什么不是“所有透明像素设为 1”就足够？

透明物体可能含有不同运动层，背景与前景有不同的 Velocity 和 Depth。单一 Mask 只能提示 History 不可靠程度，不能完整解决多层运动与遮挡对应关系。

实际质量还取决于 Transparency Render Order、Separate Translucency、Velocity Output 和 Composition 策略。

### 5. 为什么历史颜色的亮度突变也值得关注？

镜面高光、爆炸光源或镜头曝光突然变化可能产生很大的颜色差异。若强行保留旧历史，拖影明显；若所有亮度变化都 Reject，也可能增加 Flicker。

应该先确定 HDR/Exposure 正确，再采用合理的 Luminance-Based Confidence/History Clip，避免把错误的颜色管理问题误当作 TAA 权重问题。

## 十七、一个简单但有约定的 GLSL TAA Pass

### 1. TAA Pass 需要什么输入？

本示例假设：

- 当前 HDR Color、Velocity UV、上一帧 History HDR、当前 Depth（可选增强）、上一帧 Depth（可选增强）。
- 当前 Color 与 History **已经调整到同一线性 HDR 曝光/Pre-Exposure 约定**。
- 当前输出/History Resolution 与当前 Color Resolution 相同（不是 TAAU）。
- VelocityUV = CurrentJitteredUV - PreviousJitteredUV。
- 上游负责对 History 的真正 Disocclusion 检查；本例只演示**边界检查、3×3 颜色 Clip 与权重控制**。

### 2. 一段可集成的基础 TAA Fragment Shader

~~~glsl
#version 450 core

layout(location=0) out vec4 outColor;
in vec2 vUV;

uniform sampler2D uCurrentHDR;
uniform sampler2D uVelocityUV;
uniform sampler2D uPreviousHistoryHDR;
uniform sampler2D uReactiveMask;
uniform bool uHistoryAvailable;
uniform float uBaseCurrentWeight; // e.g. 0.1

vec3 ClipHistoryToNeighborhood(vec2 uv, vec3 history)
{
    ivec2 sizePx = textureSize(uCurrentHDR, 0);
    vec2 texel = 1.0 / vec2(sizePx);

    vec3 minC = vec3( 1e20);
    vec3 maxC = vec3(-1e20);

    for (int y = -1; y <= 1; ++y)
    {
        for (int x = -1; x <= 1; ++x)
        {
            vec2 sampleUV = uv + vec2(x, y) * texel;
            vec3 c = texture(uCurrentHDR, sampleUV).rgb;
            minC = min(minC, c);
            maxC = max(maxC, c);
        }
    }

    return clamp(history, minC, maxC);
}

void main()
{
    vec3 current = texture(uCurrentHDR, vUV).rgb;
    if (!uHistoryAvailable)
    {
        outColor = vec4(current, 1.0);
        return;
    }

    vec2 velocityUV = texture(uVelocityUV, vUV).xy;
    vec2 previousUV = vUV - velocityUV;

    if (any(lessThan(previousUV, vec2(0.0))) ||
        any(greaterThan(previousUV, vec2(1.0))))
    {
        outColor = vec4(current, 1.0);
        return;
    }

    vec3 history = texture(uPreviousHistoryHDR, previousUV).rgb;
    history = ClipHistoryToNeighborhood(vUV, history);

    float reactive = clamp(texture(uReactiveMask, vUV).r, 0.0, 1.0);
    float weight = mix(
        clamp(uBaseCurrentWeight, 0.0, 1.0),
        1.0,
        reactive);

    vec3 result = mix(history, current, weight);
    outColor = vec4(result, 1.0);
}
~~~

**限制：** 这是用于理解和快速验证的教学级 TAA，不包含 Depth-Based Disocclusion、Variance Clipping、Velocity Dilation、Camera Cut、Upscaling、Sharpen 等；**不能把它等同于可直接用于量产游戏的 TAA**。

### 3. 为什么这里对当前颜色用 3×3 Neighborhood？

构造当前局部颜色范围，限制历史异常偏离。3×3 是较常见的起点，真实实现可使用 Cross Sampling、Variance Statistics、Luma Clamping 或更精细的 Reconstruction。

### 4. 为什么不能把 History Alpha 当作不透明度进行普通 Alpha Blending？

History Accumulation 的 `weight` 是时间滤波权重，不是材质的光学透明度。它可能取决于遮挡、速度、置信度，与 Straight/Premultiplied Alpha 的透射/覆盖语义完全不同。

### 5. 上述 Shader 有哪些要补齐的工程条件？

至少需要：

- 防止当前 Neighborhood 采样越界或依赖明确 Clamp Sampler。
- 识别当前像素与历史像素是否同一表面。
- 当前 Velocity/History 分辨率一致或有明确转换。
- Camera Cut、Resize、FOV Change 时清理 History。
- 处理 HDR Exposure/Pre-Exposure、透明、天空、NaN/Inf。
- 维护 Frame N 与 N-1 的一致矩阵、Jitter、Color Space。
- 测试 Shader 内 Fetch 频率、Cache 与性能。

## 十八、TAAU：Temporal Antialiasing Upsampling

### 1. TAAU 与普通 TAA 的主要区别？

普通 TAA 通常在当前渲染分辨率上融合历史并输出同分辨率的抗锯齿图像。TAAU（Temporal Anti-Aliasing Upsampling）把**Temporal Accumulation 与 Spatial Upscaling**结合，允许当前帧以较低的内部 Rendering Resolution 渲染，而历史与最终结果在较高的 Output Resolution 上维护。

例如内部渲染 `1600×900`，目标输出 `2560×1440`：

~~~text
Internal Render 1600x900
  Current HDR + Depth + Motion Vector
                   |
                   v
    TAAU Reprojection/Reconstruction
     History stored at 2560x1440
                   |
                   v
         Output 2560x1440
~~~

**注意：** 实际 TAAU 引擎在各种 Pass 的渲染尺寸、Velocity 尺寸和内部 History Layout 上可采取不同设计；这里描述的是常见架构原则。

### 2. 为什么 TAAU 不等于 Bilinear Upscale 后运行 TAA？

简单 Bilinear 首先对当前低分辨率信号做空间插值，可能丢失尚未恢复的高频信息；TAAU 可以把来自不同帧的**偏移子像素样本**作为高分辨率重建的一部分。

更高质量的 TAAU 还会利用高质量 Reconstruction Kernel、Confidence、Reactive Mask、History Clipping、Sharpen 和动态分辨率信息。

不过 TAAU 也不能凭空恢复未被任何时间样本观测到的真实细节，快速变化时常需要依靠当前帧重建而画质下降。

### 3. TAAU 最容易搞混的三个尺寸是什么？

| 名称 | 作用 | 典型值 |
|---|---|---|
| Input Render Resolution | 当前帧 3D 渲染与 GBuffer 的大小 | 1600×900 |
| Output Resolution | 要交付给后处理/显示的目标大小 | 2560×1440 |
| History Resolution | 保存上次重建结果所使用的尺寸 | 通常接近/等于 Output Resolution |

Motion Vector 可以以 **UV Units、Input Pixel Units、Output Pixel Units 或 NDC Units** 编码。必须先确认其单位，才能从 CurrentUV 得到 PreviousUV。

### 4. 如果 Motion Vector 是 Input Pixel 位移，怎样用于 Output History UV？

假设内部 Render Width/Height 为 `W_i,H_i`，Velocity 的单位是内部 Pixel：

$$
\boxed{
\mathbf v_{\mathrm{uv}}=
\left(\frac{v_{x,\mathrm{pixel}}}{W_i},
\frac{v_{y,\mathrm{pixel}}}{H_i}\right).
}
$$

再应用本篇的约定：

$$
\mathbf{uv}_{\mathrm{history}}=
\mathbf{uv}_{\mathrm{output}}-
\mathbf v_{\mathrm{uv}}.
$$

这个式子成立的前提是 Current OutputUV 与 Motion Vector 映射描述同一屏幕位置，已处理 Jitter、Viewport Scale/Bias、Y Origin 与历史分辨率变化。

**易错点：** 不能将输入像素单位的 Velocity 直接减在 `[0,1]` 的输出 UV 上。

### 5. 为什么低分辨率 Jitter 要以 Input Pixel 尺寸定义？

Projection Jitter 的目标是让**当前内部渲染网格**采样不同的子像素位置，因此像素偏移转 NDC 应使用 Input Render Resolution：

$$
\mathbf J_{\mathrm{ndc}}=
2\left(\frac{j_x}{W_i},\frac{j_y}{H_i}\right).
$$

如果改用 Output Resolution 分母，同样的 `j_px` 会产生更小的内部像素偏移，采样图案和预期覆盖范围改变。

### 6. 为什么 TAAU 在运动时特别困难？

在静态区域，多个历史样本可以复用；动态区域若出现 Disocclusion、非刚体形变、快速运动或粒子变化，旧样本可能不再有效。此时必须依赖当前低分辨率帧重建，高频信息不足更容易产生软化、走样或拖尾。

这也是 Temporal Upscaler 需要复杂 Reactive/Disocclusion/Lock 管理和空间重建逻辑的主要原因。

### 7. 一个只展示坐标语义的 TAAU Shader 伪代码

~~~glsl
// Concept only; not a complete production upscaler.
// outputUV is in the output/history normalized UV domain.
vec2 inputUV = MapOutputUVToInputUV(outputUV);

vec3 currentReconstructed =
    ReconstructCurrentLowResolution(inputUV);

vec2 velocityUV =
    ReadVelocityAndConvertToUV(inputUV);

vec2 historyUV = outputUV - velocityUV;

bool historyValid = ValidateHistory(
    outputUV, historyUV, inputUV);

vec3 history = historyValid
    ? ReadHighResolutionHistory(historyUV)
    : currentReconstructed;

vec3 clippedHistory = ClipHistoryAgainstCurrent(
    history, currentReconstructed, inputUV);

vec3 result = BlendCurrentAndHistory(
    currentReconstructed, clippedHistory, historyValid);
~~~

这里保留了原子流程；`MapOutputUVToInputUV` 等函数必须实现 Viewport/Resolution/Jitter 的完整坐标约定，不能将伪代码理解为可直接编译的 Shader。

## 十九、Dynamic Resolution、Upscaling 与历史有效性

### 1. 为什么实时游戏需要 Dynamic Resolution？

GPU 帧预算有限。复杂场景中可降低内部渲染分辨率以节省部分 Pixel/Compute Work，再通过 Spatial/Temporal Upscaling 输出目标分辨率，改善帧时间稳定性。

Dynamic Resolution 的控制通常根据 GPU Timings、目标帧时长、性能预算和质量上下限决定；不要只看 CPU FPS 瞬时值。

### 2. 动态分辨率变化会影响哪些资源？

可能影响 Current HDR、Depth、GBuffer、Velocity、SSAO、SSR、Volumetric、粒子、一些后处理和空间采样尺度。并非所有资源都必须跟随内部 Render Scale：UI、最终输出、History、某些反射与阴影资源可能有独立分辨率策略。

### 3. 为什么不能在内部 Render Resolution 变化后直接无条件复用 History？

虽然两个 History Sample 都位于归一化 UV 域，但如果 Projection Jitter、Velocity Unit、Reconstruction Footprint、Viewport Offset 和 Filter Scale 没有对应调整，就会把历史读到不一致的位置。

处理方案可以是重采样历史、适配坐标和 Footprint、短时间降低历史权重，或在变化剧烈时清空 History。

### 4. 什么是 Upscale Ratio？

定义 Output/Render 尺度：

$$
s_x=\frac{W_{\mathrm{out}}}{W_{\mathrm{in}}},
\qquad
s_y=\frac{H_{\mathrm{out}}}{H_{\mathrm{in}}}.
$$

当 `s_x,s_y>1` 时在对应方向上采样密度不足，需要重建。若两者不同，还需考虑非等比例 Viewport/Aspect Correction，不能假设永远使用单个标量 Scale。

### 5. 什么时候应该重置 TAA History？

典型触发条件：

- Camera Cut / Teleport。
- Output Resolution 与 History Format 的重大不兼容变化。
- Render Scale 突变且不支持历史重采样/权重调整。
- Viewport/Letterbox/Subrect 变化导致坐标映射无法延续。
- Projection/FOV 发生无法合理重投影的变化。
- 一些特定的场景载入、暂停恢复、Temporal Mode 切换。

**重点：** 不应把每一次轻微的 Render Scale 变化都机械地理解为“必须丢弃历史”；现代动态分辨率 Upscaler 可能专门支持这种变化。

### 6. Sharpen 应该放在哪里？

Sharpen 可用来抵消 Temporal Reconstruction 的部分软化，通常作为 Upscale 后或输出阶段的一个受控过程；但具体顺序与使用的重建滤波器有关。

过强 Sharpen 会造成 Halo、Ringing、放大噪点，甚至增强时域闪烁。不能把 Sharpen 看作 TAA 模糊的万能修复器。

## 二十、透明、粒子、动画与难以获得 Velocity 的信号

### 1. 为什么透明物体对 TAA 特别困难？

一个透明像素可以是多个表面层颜色的混合，但普通 Velocity Buffer 通常只能存**一个二维运动向量**。

当前像素可能同时含有前景玻璃、其后面的背景和粒子；若三者运动不同，单个 Velocity 无法为全部贡献找到正确的上一帧历史对应关系。

### 2. 为什么玻璃可能产生背景拖尾？

若透明像素的 History Reprojection 使用玻璃表面 Velocity，却把混合后的背景颜色也一起重投影，背景相对于玻璃的运动无法被正确表示。若使用背景 Velocity，又可能拖动玻璃的反射/颜色。

工程上可采用 Separate Translucency、Reactive Mask、特殊透明 Velocity/Resolve、Composition Weighting 等策略，但每种都有代价。

### 3. 粒子为什么经常使用 Reactive Mask？

爆炸、火焰、烟雾、闪光等颜色、Alpha、形状随时间迅速变化，几何 Motion Vector 无法完整表达内部颜色内容的变化。历史重用可能产生长拖尾，因此需要较高的 Current Weight 或专门的时域处理。

### 4. Alpha-Test 草和树叶的难点是什么？

几何只由少量大三角形表示，Leaf Shape 通过 Alpha Cutout 定义；细枝叶在远距离变成 Subpixel Signal，随着 Jitter 和 Motion 可能时隐时现。

可组合：

- 正确的 Alpha Coverage Mip 与法线过滤。
- MSAA + Alpha-to-Coverage（适用 Forward/MSAA 场景）。
- TAA/TAAU 跨帧积累。
- 适当的 Dithered Transparency 和 Temporal Pattern。
- 性能允许时采用更合适的 Geometry LOD。

### 5. 为什么 Animated Material 需要特殊历史策略？

流水纹理、滚动 UV、程序噪声、World Position Offset 即使 Object Matrix 不变，Shader 输出也可在表面上运动。将 Velocity 设为零并保留大量历史，会把不同时间的材质内容错误平均。

对于 Texture Animation，可考虑自定义 Motion Vector 或 Reactive/Temporal Weight；无法准确追踪的变化应降低历史信任度。

### 6. 为什么 Specular Highlight 会在 TAA 中出现拖尾？

Specular Color 随视线、法线、光源和 Roughness 变化，可比几何投影变化快得多。Motion Vector 能追踪几何点，却不一定能追踪**高光在表面移动的位置**。

因此 TAA 不能仅靠正确几何 Velocity 解决所有 Specular Ghosting；需要 History Clip、Specular AA、Luma/Reactive 机制及合理的采样。

### 7. Shadow PCF/PCSS 与 TAA 如何配合？

Shadow Sampling 可以采用空间随机核或时变样本，TAA 积累有机会降低阴影采样噪声。但 Shadow Map 自身不稳定、CSM Shimmering、错误 Bias 和错误 Motion Vector 会把阴影噪点带到 History，造成拖尾或闪烁。

前置 Shadow 稳定性仍很重要，不能完全依赖 TAA 隐藏 Shadow 系统的问题。

## 二十一、HDR、曝光、Tone Mapping 与 Pass 顺序

### 1. TAA 应放在 Tone Mapping 前还是后？

很多现代实时渲染管线选择在 **Linear HDR/Pre-Exposed Scene Color** 中执行 TAA，然后再做 Tone Mapping 和输出编码，便于保留 HDR 颜色信息并与后续 Upscaling/Bloom 等组合。

但这不是所有引擎唯一合法的 Pass 顺序。有些后处理 AA（如 FXAA）可能放在 Tone Mapping 后；某些 TAA/TAAU 实现也会对 HDR 颜色做内部亮度变换以改善稳定性。

### 2. 为什么 HDR 极亮像素容易让 TAA 不稳定？

HDR Sun Highlight、闪烁灯光或极亮镜面反射可能与邻近样本相差多个数量级。一旦由 Jitter 不同位置采到，History Average/Clamp 会在“保留亮点”和“压制异常”之间产生冲突。

需要合理的 HDR Color Filtering、Neighborhood Statistics、亮度/色度变换、Pre-Exposure 以及 Specular/Texture Aliasing 控制，不能简单 Clamp 到 `[0,1]` 解决。

### 3. Pre-Exposure 对 TAA History 具体有何影响？

设当前 Shader Color Numeric Value 约定为 `C_t^{stored}=C_t^{linear} * k_t`，上一帧历史为 `C_{t-1}^{stored}=C_{t-1}^{linear} * k_{t-1}`。

在同一物理照明数值语义下，要把上一帧存储值转换到当前尺度，需：

$$
\boxed{
C_{t-1}^{\mathrm{currentScale}}=
C_{t-1}^{\mathrm{stored}}
\frac{k_t}{k_{t-1}}.
}
$$

这个式子只针对明确定义为**乘法曝光缩放**的内部数值约定；不同引擎可能使用倒数、独立亮度编码或在其它阶段处理历史变换，不能照抄比值而不确认变量含义。

### 4. TAA 是否应该影响 UI/文字？

一般建议在最终输出目标分辨率绘制 UI，避免 UI 跟随 3D Jitter、Velocity 和历史平均而变得模糊或拖影。

但 3D World-Space UI、场景内贴花文字可能需要作为场景的一部分参与 AA；需根据 UI 的屏幕/世界空间语义决定。

### 5. 为什么 Sharpen、Bloom、Motion Blur 与 TAA 的顺序重要？

- Bloom 若处理锐利 HDR Highlights，可能因 TAA 不稳定产生闪烁；但过早模糊也可能破坏重建。
- Motion Blur 有意按速度积分颜色，而 TAA 的 Ghosting 是**无意错误重用历史**；二者应分别控制。
- Sharpen 可能恢复观感或增强噪声。
- Tone Map 改变色彩范围与对比度，影响 Edge Detection/History Confidence 的效果。

不同引擎在光照时域降噪、TAAU、Bloom、Motion Blur 的具体调度上会做性能和观感取舍。

## 二十二、Upscaling 方法分类：Spatial、Temporal 与学习型

### 1. Bilinear/Bicubic 与 Temporal Upscaling 的根本不同？

Spatial Upscaling 主要根据**当前帧局部像素**计算输出；Temporal Upscaling 还利用**历史帧、Motion Vector、Depth/Confidence 和子像素采样图案**。

Temporal Upscaling 的主要优势在静态或可可靠重投影的区域；劣势在 Disocclusion、快速运动、透明、高频动态内容。

### 2. FSR、DLSS、XeSS 与 TAAU 是否完全同类？

不能简单混成一种算法。不同版本可能采用 Spatial、Temporal 或学习型 Reconstruction，输入资源、模型、硬件支持、运行成本和质量策略都不一样。

| 技术/类别 | 概念重点 | 面试应解释的区别 |
|---|---|---|
| Bilinear/Bicubic | 单帧插值 | 不积累跨帧子像素样本 |
| Spatial Sharpen/Upscale | 当前帧重建与锐化 | 通常不依赖几何 Motion Vector |
| TAAU | 时间积累 + Upscale | History/Velocity/Depth/Jitter 一致性 |
| Temporal Super Resolution | 较复杂时间重建与历史管理 | Disocclusion、Reactive、Lock/Confidence |
| Learning-Based Upscaling | 使用训练模型/专门的重建系统（视具体产品版本） | 模型运行代价、输入与部署条件 |

**注意：** DLSS、FSR、XeSS 是会迭代的产品系列，不能不看版本就断言“某品牌永远只用一种具体算法”。本篇聚焦引擎共用原理，不代替各 SDK 最新接入文档。

### 3. TAAU 是否总是比原生分辨率渲染清晰？

不一定。它使用低分辨率 Current Samples，在静止场景和可信 History 中能积累更多细节；在快速运动和新显露区域信息有限时可能不如原生分辨率渲染。

评估应使用**时间序列视频**而不仅是一张截图。

### 4. Frame Generation 与 Temporal Upscaling 是一回事吗？

不是。Temporal Upscaling 的目标是重建每一帧的更高分辨率图像；Frame Generation/Interpolation 的目标是在已有帧之间生成或预测额外的输出帧。

它们可能共享 Motion Vector、History 等概念，但延迟、稳定性、运动估计和呈现目标不同。

## 二十三、RenderGraph、OpenGLRenderer 与调试验证

### 1. TAA/FXAA 在 RenderGraph 中大致如何组织？

~~~text
Depth / GBuffer / Velocity
               |
               v
  Opaque + Lighting + Selected Translucency
               |
               v
       Linear HDR Scene Color
               |
               v
 TAA / TAAU [current, velocity, depth,
            previous history, masks]
               |
               +---> Next Frame History (write)
               |
               v
      Output HDR / Upscaled HDR
               |
               v
  Exposure/ToneMap/Bloom/Sharpen (defined order)
               |
               v
        UI / Present
~~~

真实 RenderGraph 的 Bloom/ToneMap/Motion Blur 等 Pass 顺序依设计不同；图示只强调数据依赖和 History Ping-Pong。

### 2. 为什么 History 资源很特殊？

普通 FrameGraph 可能会在当前帧内计算临时资源的生命周期并复用内存，但 History 要跨越帧边界，不能在帧末错误释放或复用其仍需保存的内容。

还要考虑 Resize、Camera Cut、Temporal Mode 切换、多个 Viewport/Camera、Stereo Rendering 下**每个 View 的 History State** 是否独立。

### 3. OpenGL 中怎样防止 History Read/Write Feedback？

在 TAA Pass 中绑定 History A 为采样纹理，History B 为当前 Color Attachment。完成绘制后再交换二者的角色，确保本 Pass 不采样自己正在写入的同一 Texture Subresource。

若改变 Framebuffer、Viewport 或 Render Target Resolution，应同步更新 TAA Uniform 和下一帧的 History Metadata。

### 4. 为什么 RenderDoc 一张 Capture 不一定能解释 TAA Ghosting？

TAA 的错误依赖上一帧历史。单帧 Capture 能看到当前绑定的 History 和 Velocity，但不一定足以知道**历史是怎样在此前多帧积累出来的**。

推荐同时使用多帧截图/视频、Debug Visualization 和带时间戳的 History Reset/Weight 日志。

### 5. 最值得可视化的 Debug Buffer 有哪些？

| Debug Buffer | 用来验证 |
|---|---|
| Current Jitter (NDC/Pixel) | 是否按正确序列/单位移动投影 |
| Velocity UV / Pixel | 正负方向、分辨率缩放与运动层 |
| History UV | 是否回到同一个表面的上一帧屏幕位置 |
| History Validity | Camera Cut/Disocclusion 等是否正确拒绝 |
| Depth Difference | 当前点与历史遮挡面是否一致 |
| Color Clamp Min/Max | 是否过度接受/拒绝异常历史 |
| Temporal Current Weight | 哪里在快速响应当前帧 |
| Reactive Mask | 动态粒子/反射是否降低历史使用 |
| Before/After TAA | 区分 Shading 本身走样与 TAA 产生的伪影 |
| History Contribution | Ghosting 来源以及色彩/曝光问题 |

### 6. 为什么 Render Target 分辨率和 Viewport 不一致很危险？

例如一张 Texture 比当前使用的 Viewport 大，UV `[0,1]` 不再天然对应 Viewport 内部有效像素。若 TAAU 直接按 TextureSize 归一化而忽略 Rect Scale/Bias，会把 Velocity/History/Neighborhood 映射到错误位置。

渲染架构中应显式传递 InputRect、OutputRect、HistoryRect 的尺寸与偏移，不要默认所有 Render Targets 都全图有效。

### 7. GPU 上怎样比较 AA 方法的性能？

固定相机、光照、场景、Render Scale，分别测量：

- 主 Render Pass（MSAA 改变 GBuffer/Depth/Resolve Cost）。
- AA/Postprocess Pass 单独 GPU Duration。
- 帧总 GPU Time，而非只看某一个 Shader Dispatch。
- HDR/Velocity/History Buffer 的显存占用和读写带宽。
- Forward/Deferred 路径下多样本存储、材质计算和后处理成本。
- 在移动场景中画质是否有 Ghosting/Blur/Flicker。

**最关键：** MSAA 的成本常体现在多个前序 Render Pass 中；FXAA/TAA 的直接成本在后处理里更容易量化，但 TAA 还要求额外 Velocity/History 资源和若干渲染特性配合。

### 8. 工程选型：不同类型的项目该怎样组合？

| 场景 | 可优先评估的 AA 策略 | 需要重点验证 |
|---|---|---|
| Forward 低多边形 / VR | MSAA，必要时特殊 Shader AA | Sample Cost、透明、Stereo 稳定性 |
| Deferred 大型实时场景 | TAA 或 Temporal Upscaler | Velocity、History、Ghosting |
| 低端设备 / 简单渲染器 | FXAA 或 SMAA 1x | 性能、清晰度与运动时的边缘闪烁 |
| 高质量静态截图 | SSAA / 高采样累积 | 内存、时间与真实积分质量 |
| 内部低分辨率输出高清 | TAAU / TSR 类 | 动态分辨率、透明/粒子、响应速度 |
| 高反射、高纹理频率 | 组合 Specular AA、Mipmap、Temporal | 材质走样与错误历史抑制 |

**不要把这些视为绝对决策表。** 具体 UE/移动平台/硬件架构、VR 帧时延和目标画风都可能改变最优选择。
