# 计算机图形学秋招复习文档（二）：渲染管线与光栅化

**复习范围：** GPU 图形渲染管线、顶点与图元处理、齐次裁剪、背面剔除、透视除法、Viewport、三角形光栅化、边函数、重心坐标、透视校正插值、片元处理、深度与 Early-Z、MSAA 基础、软件光栅化实现及优化。

**面试目标：** 能完整解释一个三角形从顶点数据变成屏幕像素的过程；独立推导边函数、齐次裁剪与透视校正插值；实现支持裁剪、深度测试和透视正确 UV 的软件光栅器。

**前置知识：** [01-数学基础与空间变换](01-数学基础与空间变换.md) 中的 MVP、齐次坐标、投影矩阵与深度。

**排版约定：** 正文的简短表达式用行内代码，复杂推导用独立数学公式块，避免不支持行内 LaTeX 的阅读器显示原始命令。

**本文统一约定（重要）：**

- 列向量：`p_clip = P V M p_local`，矩阵从右向左作用。
- 默认传统 OpenGL Clip Space：`-w ≤ x,y,z ≤ w`，透视除法后 `z_ndc ∈ [-1,1]`；其他深度约定会明确说明。
- 数学二维平面通常用 `Y` 向上；软件光栅化示例使用左上角原点、`Y` 向下的屏幕坐标，相关边规则也以此为准。
- 只处理非退化三角形；进入 Rasterization 的图元已经正确完成齐次裁剪，顶点的 `w` 可安全相除。
- 本文的阶段顺序是便于理解的**逻辑管线**，真实 GPU 可以采用与之等价的并行、重排或优化实现。

## 一、图形渲染管线总览

### 1. Graphics Pipeline 主要解决什么问题？

它将 CPU 提交的顶点、索引、资源和绘制状态处理成最终的颜色与深度结果。

~~~text
CPU 场景更新 / 视锥和遮挡剔除 / Draw Call
                         |
                         v
GPU 顶点输入 / Input Assembly
                         |
                         v
                 Vertex Shader
                         |
                         v
        可选 Tessellation / Geometry 阶段
                         |
                         v
       Primitive Assembly / Clipping / Culling
                         |
                         v
        Perspective Divide / Viewport
                         |
                         v
          Rasterization / 属性插值
                         |
                         v
                 Fragment Shader
                         |
                         v
        Depth / Stencil / Blending 等操作
                         |
                         v
           Framebuffer / Render Target
~~~

这描述的是传统光栅化图形管线；Mesh Shader、Compute Shader 和 Ray Tracing 的调度方式并不完全相同。

### 2. CPU 和 GPU 在 Draw Call 里分别做什么？

CPU / 引擎侧主要负责可见对象选择、准备缓冲与纹理、绑定 Pipeline State、录制和提交命令、协调资源与同步。GPU 负责执行着色、图元处理、覆盖判断、插值和渲染目标写入等。

**Draw Call 不是执行一次 Vertex Shader。** 一个 Draw Call 可以处理很多顶点、图元和 Fragment；其开销既包括 CPU 提交也包括 GPU 工作。

### 3. 可编程阶段与固定功能阶段怎么区分？

| 类型 | 典型阶段 | 主要职责 |
|---|---|---|
| 可编程 | Vertex Shader | 顶点变换、蒙皮、Varying 输出 |
| 可编程 | Fragment Shader | 材质、光照、纹理与颜色计算 |
| 可选可编程 | Tessellation / Geometry | 细分、生成或修改图元 |
| 固定功能与管线状态 | Input Assembly、Clipping、Rasterization | 顶点装配、裁剪、覆盖与插值规则 |
| 固定功能与管线状态 | Depth、Stencil、Blending | 可见性与帧缓冲合成 |

固定功能不代表没有任何可配置项，FrontFace、CullMode、DepthFunc、BlendFunc 等都由管线状态控制。

### 4. 为什么软渲染与 OpenGL 同场景可能出现不同结果？

常见差异包括：Clip 深度范围、Viewport 坐标方向、裁剪/共享边规则、透视插值、Depth Compare、精度、MSAA Sample 位置、纹理过滤、sRGB、Blending 等。

对照测试之前，应固定各阶段约定，优先排查**几何与插值**，再排查光照材质。

## 二、顶点数据、索引与图元装配

### 1. Vertex 通常包含哪些属性？

| 属性 | 典型用途 |
|---|---|
| Position | 顶点位置与 MVP 变换 |
| Normal | 光照与材质计算 |
| Tangent / Bitangent Sign | 法线贴图切线空间 |
| UV | 纹理坐标 |
| Color | 顶点颜色或自定义数据 |
| Bone Weights / Indices | 骨骼蒙皮 |
| Instance Data | 实例变换或实例材质参数 |

**顶点身份不等于世界位置唯一。** UV Seam、硬法线边和材质切换可能要求同一位置拆成不同的顶点属性记录。

### 2. VBO / Vertex Buffer 与 EBO / Index Buffer 有什么区别？

Vertex Buffer 存属性，Index Buffer 存引用顶点的索引。同一顶点记录被多个三角形引用，有机会减少数据冗余并提高顶点缓存复用率。

**注意：** 索引绘制不保证顶点着色器对相同索引必然只运行一次；实际顶点复用取决于 Post-Transform Cache 等机制。

### 3. Triangle List 与 Triangle Strip 怎么比较？

- Triangle List：三个索引形成一个三角形，结构简单、常用。
- Triangle Strip：后续顶点可与之前的顶点组成新三角形，共享顶点较多，但需正确处理绕序与退化连接。
- Point / Line：生成点或线段；Patch 可作为 Tessellation 输入。

### 4. 为什么三角形是光栅化的基本单位？

三个非共线顶点唯一确定平面；三角形容易裁剪并通过重心坐标对平面属性插值。任意四边形可能非共面，因此通常先划分成三角形。

## 三、Vertex Shader 与空间变换

### 1. Vertex Shader 接收和输出什么？

~~~glsl
#version 450 core

layout(location = 0) in vec3 aPosition;
layout(location = 1) in vec2 aUV;
layout(location = 2) in vec3 aNormal;

uniform mat4 uModel;
uniform mat4 uView;
uniform mat4 uProjection;
uniform mat3 uNormalMatrix;

out vec2 vUV;
out vec3 vWorldNormal;

void main()
{
    gl_Position = uProjection * uView * uModel
                * vec4(aPosition, 1.0);

    vUV = aUV;
    vWorldNormal = uNormalMatrix * aNormal;
}
~~~

核心输出 `gl_Position` 是**齐次 Clip Space** 坐标，而不是已经除以 `w` 的 NDC 坐标。Varying 则会在图元光栅化时按指定语义插值。

### 2. 为什么 Vertex Shader 一般不直接输出 NDC？

如果提前丢失 `w`，跨近平面的三角形难以正确裁剪；同时也无法直接获得透视校正插值所需的 `1/w` 信息。

逻辑顺序：

~~~text
Local -> World -> View -> Clip -> Clipping -> NDC -> Window
                                    (Divide)   (Viewport)
~~~

### 3. Shader 里的坐标空间为什么容易用错？

例如在 Vertex Shader 中输出世界空间法线，却在 Fragment Shader 中拿它与观察空间光源方向点乘，结果就不正确。

每个 Varying 都应注明语义：World Position、View Position、Normal、UV 等；不要只靠变量名字猜测空间。

### 4. 每个顶点着色器 Invocation 能看到邻居顶点吗？

传统 Vertex Shader 主要处理当前输入顶点及可访问的缓冲资源，并不自动传入整个三角形。邻居关系通常由图元装配及后续阶段负责。

## 四、齐次裁剪 Clipping

### 1. 为什么必须先裁剪再透视除法？

透视投影具有 `w_clip = -z_view` 之类的关系；跨越近平面的线段可能经过 `w=0` 或改变符号。如果先做除法，会导致坐标发散或相机后方三角形翻转。

齐次 Clip Space 可直接依据平面不等式裁剪，之后再对有效几何做透视除法。

### 2. OpenGL 传统 Clip Space 的六个条件是什么？

$$
-w\le x\le w,\qquad
-w\le y\le w,\qquad
-w\le z\le w.
$$

把内侧定义为非负：

| 平面 | 有向距离函数 |
|---|---|
| Left | `d = w + x` |
| Right | `d = w - x` |
| Bottom | `d = w + y` |
| Top | `d = w - y` |
| Near | `d = w + z` |
| Far | `d = w - z` |

当 Clip 深度范围是 `[0,1]` 时，近裁剪条件通常改为 `z >= 0`，而不是 `z >= -w`。此外还可能有自定义裁剪平面。

### 3. 裁剪交点参数如何推导？

线段在齐次空间线性插值：

$$
P(t)=(1-t)P_0+tP_1,\qquad 0\le t\le1.
$$

线性裁剪平面函数对两个端点的值为 `d0`、`d1`，因此：

$$
d(t)=(1-t)d_0+td_1.
$$

令交点处 `d(t)=0`：

$$
\boxed{t=\frac{d_0}{d_0-d_1}.}
$$

用这个 `t` 同时插值裁剪位置和随顶点线性变化的 Varying。**不要在已透视除法的 NDC 边上用同样的参数去插值 Clip Space 属性。**

### 4. Sutherland-Hodgman 怎么裁剪凸三角形？

对多边形每条有向边 `A → B`：

| A 在平面内 | B 在平面内 | 输出 |
|---|---|---|
| 是 | 是 | B |
| 是 | 否 | 交点 |
| 否 | 是 | 交点、B |
| 否 | 否 | 无 |

依次对六个平面处理。输出可为零个顶点，也可有多于三个顶点；最后通过扇形三角化恢复三角形列表。

### 5. C++/GLM 的基础裁剪实现

代码采用传统 OpenGL 裁剪范围，处理齐次位置与 UV。为了说明核心算法，省略数值容差、非有限坐标和共享边防裂处理。

~~~cpp
#include <array>
#include <vector>
#include <glm/glm.hpp>

struct ClipVertex
{
    glm::vec4 clip;
    glm::vec2 uv;
};

float PlaneDistance(const glm::vec4& p, int plane)
{
    switch (plane)
    {
    case 0: return p.w + p.x; // Left
    case 1: return p.w - p.x; // Right
    case 2: return p.w + p.y; // Bottom
    case 3: return p.w - p.y; // Top
    case 4: return p.w + p.z; // Near, GL -1..1
    case 5: return p.w - p.z; // Far
    default: return -1.0f;
    }
}

ClipVertex LerpVertex(
    const ClipVertex& a, const ClipVertex& b, float t)
{
    return { glm::mix(a.clip, b.clip, t),
             glm::mix(a.uv, b.uv, t) };
}

std::vector<ClipVertex> ClipTriangle(
    const std::array<ClipVertex, 3>& input)
{
    std::vector<ClipVertex> polygon(input.begin(), input.end());

    for (int plane = 0; plane < 6 && !polygon.empty(); ++plane)
    {
        std::vector<ClipVertex> output;
        ClipVertex prev = polygon.back();
        float dPrev = PlaneDistance(prev.clip, plane);

        for (const ClipVertex& curr : polygon)
        {
            float dCurr = PlaneDistance(curr.clip, plane);
            bool aInside = dPrev >= 0.0f;
            bool bInside = dCurr >= 0.0f;

            if (aInside != bInside)
            {
                float t = dPrev / (dPrev - dCurr);
                output.push_back(LerpVertex(prev, curr, t));
            }

            if (bInside)
                output.push_back(curr);

            prev = curr;
            dPrev = dCurr;
        }
        polygon.swap(output);
    }
    return polygon;
}
~~~

如果裁剪后输出顶点数为 `N ≥ 3`，可把 `(v0, vi, vi+1)`（`i=1..N-2`）作为输出三角形。实际实现要处理重复交点、退化图元、浮点不一致和 `w=0` 边界。

## 五、图元绕序与 Backface Culling

### 1. 三角形正反面如何判断？

在二维平面上，顶点 `A,B,C` 的两倍有向面积为：

$$
D=(B_x-A_x)(C_y-A_y)
-(B_y-A_y)(C_x-A_x).
$$

`D` 的符号表示顶点绕序。若屏幕 `Y` 向上，`D>0` 是逆时针；若屏幕 `Y` 向下，视觉上的解释相反。

使用 FrontFace 状态指定正面绕序，CullMode 指定是否剔除正面或背面。真实 API 在窗口坐标与 Y 翻转等情况下有具体约定。

### 2. 为什么不能直接用顶点法线判断 Backface？

平滑顶点法线可能与真实几何面法线不同，法线贴图还会修改着色法线。Backface Culling 依据图元的**投影几何绕序**，而不是着色法线与光源或视线的点积。

### 3. 为什么负缩放或镜像可能导致面突然消失？

奇数次镜像会改变对象局部的绕序/定向，结合 Viewport/Projection 约定可能翻转最终屏幕绕序。如果 CullMode 不变，原本可见的正面可能被当成背面剔除。

### 4. Backface Culling、Frustum Culling、Occlusion Culling 区别？

- Backface：图元朝向剔除。
- Frustum：视锥外的几何或对象剔除。
- Occlusion：被其他几何遮住的对象/图元剔除。
- Depth Test：同一像素或 Sample 上可见性竞争。

它们粒度与算法不同，不应该混成一种“遮挡剔除”。

## 六、Perspective Divide 与 Viewport

### 1. 从 Clip Space 怎样进入 NDC？

$$
\mathbf p_{\mathrm{ndc}}=
\left(
\frac{x_c}{w_c},
\frac{y_c}{w_c},
\frac{z_c}{w_c}
\right).
$$

传统 OpenGL 默认 NDC 的三轴范围均为 `[-1,1]`。深度最终写入的范围还取决于 Depth Range。

### 2. NDC 到屏幕坐标如何转换？

如果 Viewport 左下角是 `(x0,y0)`、宽高是 `(W,H)`，窗口 `Y` 向上：

$$
x_s=x_0+\frac{x_{\mathrm{ndc}}+1}{2}W,\qquad
y_s=y_0+\frac{y_{\mathrm{ndc}}+1}{2}H.
$$

而本篇软件 Framebuffer 使用左上角原点、`Y` 向下的坐标：

$$
x_s=\frac{x_{\mathrm{ndc}}+1}{2}W,\qquad
y_s=\frac{1-y_{\mathrm{ndc}}}{2}H.
$$

### 3. 为什么像素中心经常用 `(x+0.5,y+0.5)`？

以每像素覆盖单位方格、像素索引为整数的模型，中心 Sample 位于半整数坐标。单采样光栅器通常在这个位置测试 Coverage。MSAA 会有多个 Sample Position，不能简单照搬。

### 4. Viewport 和 Scissor 有什么区别？

Viewport 将 NDC 变换为窗口坐标；Scissor 则限制允许写入/处理的矩形范围，两者不是同一个操作。

## 七、Edge Function：三角形覆盖测试

### 1. Rasterization 实际要做什么？

光栅化的核心是判断哪些 Sample 被三角形覆盖，并为后续 Fragment Shader 提供插值属性。软件渲染的基础步骤：

1. 转换顶点到 Screen。
2. 计算三角形 Bounding Box。
3. 在 Box 内遍历候选 Sample。
4. 用边函数确定是否覆盖。
5. 求重心权重，插值 Depth 和 Varying。
6. 执行片元着色、深度/模板/混合等。

### 2. Edge Function 的定义和几何意义是什么？

$$
E(A,B,P)=
(B_x-A_x)(P_y-A_y)
-(B_y-A_y)(P_x-A_x).
$$

它是两个二维向量的叉积标量，表示点 `P` 位于有向边 `A → B` 的哪一侧。值的绝对值等于由这两个向量构成的平行四边形面积。

### 3. 怎么用三条边判断内部？

当 `D=E(A,B,C)>0` 时：

$$
E(A,B,P)\ge0,\quad
E(B,C,P)\ge0,\quad
E(C,A,P)\ge0.
$$

但是软件/硬件最终还需指定**共享边上的相等情况**，不能无条件允许三个边都等于零，否则相邻三角形可能重复覆盖同一个 Sample。

### 4. 为什么 Bounding Box 很重要？

仅遍历：

$$
x_{\min}=\min(x_A,x_B,x_C),\quad
x_{\max}=\max(x_A,x_B,x_C),
$$

$$
y_{\min}=\min(y_A,y_B,y_C),\quad
y_{\max}=\max(y_A,y_B,y_C).
$$

再与 Viewport/Scissor 取交集。避免对完全不相关的屏幕区域做 Coverage Test。

### 5. 边函数为何能增量计算？

展开为：

$$
E(A,B,P)=\alpha x+\beta y+\gamma,
$$

$$
\alpha=A_y-B_y,\quad
\beta=B_x-A_x,\quad
\gamma=A_xB_y-B_xA_y.
$$

沿坐标单位步长：

$$
E(x+1,y)=E(x,y)+\alpha,\qquad
E(x,y+1)=E(x,y)+\beta.
$$

因此可以用加法代替遍历像素时每次重新计算叉积，且适合 Tile/SIMD。

### 6. 什么是 Top-Left Rule？

两个共享边三角形必须就“Sample 正好落在边上”采用一致规则，避免裂缝或双重覆盖。

**明确限定本篇软件示例的约定：** 屏幕 `Y` 向下；使用上面的 `E(A,B,P)`；三角形顶点已调整为 `D>0`。此时边的包含条件可写为：

~~~cpp
bool IsTopLeft(const glm::vec2& a, const glm::vec2& b)
{
    float dx = b.x - a.x;
    float dy = b.y - a.y;
    return dy < 0.0f || (dy == 0.0f && dx > 0.0f);
}
~~~

如果换成 `Y` 向上的坐标，或把边函数定义换成相反符号，必须同时修改该判定。真实 GPU 的 Rasterization Rule 还有亚像素精度与 Sample 位置约束。

### 7. 浮点边函数为什么可能产生裂缝？

共享边两侧若采用不同浮点舍入、裁剪交点或顶点坐标计算方式，即使使用相同理论规则，也可能出现覆盖差异。软件光栅器可考虑固定点亚像素坐标、整数边函数以及统一的顶点量化策略。

## 八、Barycentric Coordinates 与属性插值

### 1. 重心坐标的定义是什么？

任一与三角形 `A,B,C` 共面的点 `P`，可以写为：

$$
P=\lambda_A A+\lambda_B B+\lambda_C C,\qquad
\lambda_A+\lambda_B+\lambda_C=1.
$$

对非退化三角形，内部点的三个权重均非负。

### 2. 如何从边函数推导三个重心系数？

令 `D = E(A,B,C)`，则：

$$
\boxed{
\lambda_A=\frac{E(B,C,P)}{D},\quad
\lambda_B=\frac{E(C,A,P)}{D},\quad
\lambda_C=\frac{E(A,B,P)}{D}.
}
$$

验证：`P=A` 时 `λ_A=1`、其余为 0；`P=B`、`P=C` 同理。

### 3. 为什么不能随意把所有属性都屏幕线性插值？

屏幕重心权重给出二维投影三角形的仿射插值，但 3D 顶点属性（例如 UV、世界位置、普通 Varying）并非一般都在屏幕上呈仿射变化。

特殊情况：

- `noperspective` 属性故意使用屏幕线性插值。
- 顶点的 **NDC Z** 对于标准投影三角形可屏幕线性插值（第十节）。
- 深度相同、各顶点 `w` 相等时，普通透视校正与线性插值会退化为相同结果。

### 4. 为什么要处理退化三角形？

若 `D≈0`，重心公式分母过小或为零，可能导致 NaN 或巨大数值误差；应按实现的精度规则跳过退化图元。

## 九、Perspective-Correct Interpolation：必会推导

### 1. 为什么在屏幕上直接 Lerp UV 会错？

透视投影会让远处的空间距离压缩。屏幕线段的几何中点一般不是原始三维边的中点。使用屏幕线性 UV 会导致斜向地面的棋盘纹理被错误拉伸。

### 2. 透视校正插值公式是什么？

对屏幕空间重心系数 `λ_i`、顶点 Clip W `w_i` 和插值属性 `a_i`：

$$
\boxed{
a(P)=
\frac{
\displaystyle\sum_{i=0}^{2}\lambda_i\frac{a_i}{w_i}
}{
\displaystyle\sum_{i=0}^{2}\lambda_i\frac{1}{w_i}
}.
}
$$

先插值 `a_i/w_i`，再除以插值的 `1/w_i`。这就是软件光栅器必须保留 Clip W 的直接原因。

### 3. 一维线段怎么推导到这个公式？

在齐次 Clip Space，线段参数 `t`：

$$
P(t)=(1-t)P_0+tP_1.
$$

透视除法使屏幕坐标成为：

$$
x_{\mathrm{ndc}}(t)=
\frac{(1-t)x_0+t x_1}{(1-t)w_0+t w_1}.
$$

记屏幕线性参数为 `s`，则：

$$
x_{\mathrm{ndc}}(t)=
(1-s)\frac{x_0}{w_0}+s\frac{x_1}{w_1}.
$$

对非退化投影线段整理可得：

$$
\boxed{
t=\frac{s/w_1}{(1-s)/w_0+s/w_1}.
}
$$

对顶点属性 `a`，原始插值是 `a=(1-t)a0+t a1`，代回后得到：

$$
a=
\frac{(1-s)a_0/w_0+s a_1/w_1}
{(1-s)/w_0+s/w_1}.
$$

推广到屏幕三角形的三组重心权重，就得到上一节最终公式。

### 4. 数值例子：为什么屏幕中点不是 UV 中点？

令一条投影边的 `s=0.5`，顶点有 `w0=1`、`w1=2`，纹理坐标 `u0=0`、`u1=1`。

普通屏幕 Lerp 得 `0.5`，透视校正计算：

$$
u_{\mathrm{correct}}=
\frac{0.5\cdot0/1+0.5\cdot1/2}
{0.5/1+0.5/2}
=\frac13.
$$

它们明显不同。斜向远离相机的棋盘格是很好的测试案例。

### 5. GLSL 的 smooth、noperspective、flat 是什么？

| 修饰符 | 含义 | 典型用途 |
|---|---|---|
| `smooth`（默认） | 透视校正 | UV、颜色、世界空间位置 |
| `noperspective` | 屏幕空间线性 | 屏幕仿射量、特定效果 |
| `flat` | 不插值，使用图元指定顶点的值 | Material ID、整数索引 |

具体的类型限制、Provoking Vertex 和插值规则应以对应 GLSL/API 规范为准。

### 6. 为什么插值法线后还要 Normalize？

即使每个顶点法线都是单位长度，重心加权后的向量一般不再是单位向量。光照前通常执行：

~~~glsl
vec3 N = normalize(vWorldNormal);
~~~

同时检查法线与光照方向是否处于同一个坐标空间。

## 十、Depth Interpolation 与 Fragment Processing

### 1. Clip Z、NDC Z、Window Depth 有何区别？

- Clip Z：四维裁剪位置中的 `z_c`。
- NDC Z：`z_c / w_c`。
- Window Depth：NDC 深度经过 API Depth Range 等变换后的深度值，通常存入 Depth Buffer。

传统 OpenGL 默认深度映射：

$$
z_{\mathrm{window}}=\frac{z_{\mathrm{ndc}}+1}{2}.
$$

采用 `[0,1]` 裁剪深度约定时，在默认深度映射下通常可直接使用相应 NDC Z；要注意 Reversed-Z 与自定义 Depth Range。

### 2. 为什么 NDC 深度可以屏幕线性插值，UV 却需要透视校正？

**这是非常高频的陷阱。**

投影后顶点深度为 `z_ndc,i = z_clip,i / w_i`。对一个经标准投影的三角形，它在屏幕平面上是仿射函数：

$$
\boxed{
z_{\mathrm{ndc}}(P)=
\lambda_A z_{\mathrm{ndc},A}+
\lambda_B z_{\mathrm{ndc},B}+
\lambda_C z_{\mathrm{ndc},C}.
}
$$

而 UV 仍是投影前三角形上的属性，其正确结果要使用 `(Σλ uv/w)/(Σλ/w)`。

**不能拿已经求出的 NDC Z 再使用 UV 透视校正公式做第二次校正。** 对 Clip Z 使用透视校正后，再恢复除以 Clip W，可以得到一致的结果，但直接插值 NDC Z 更简单。

### 3. Fragment 与 Pixel、Sample 的区别是什么？

- Pixel：渲染目标可寻址的像素位置。
- Fragment：光栅化生成的候选片元，包含覆盖和插值信息。
- Sample：一个像素内参与覆盖、深度/模板等操作的采样位置。

同一像素可能被多个图元覆盖，产生多个 Fragment（Overdraw）。有 MSAA 时一个 Pixel 还可能包含多个 Coverage / Depth Sample。

因此不能说“Fragment Shader 一定每个像素恰好运行一次”。

### 4. Fragment Shader 的输入和输出是什么？

基本 GLSL：

~~~glsl
#version 450 core

in vec2 vUV;
uniform sampler2D uAlbedo;

layout(location = 0) out vec4 outColor;

void main()
{
    outColor = texture(uAlbedo, vUV);
}
~~~

真实 Shader 可能计算法线、BRDF、Shadow、HDR 颜色和多个 MRT，或根据 API 条件输出自定义深度。

### 5. Fragment Shader 输出颜色就一定能写入 Framebuffer 吗？

不一定。片元还可能受到 Scissor、Coverage、Depth / Stencil Test、`discard`、Blending、Color Write Mask、Sample Mask 等因素影响。

“片元着色完成”与“帧缓冲真的被更新”是不同的概念。

### 6. Early-Z 和 Late-Z 是什么？为什么不能保证永远 Early-Z？

- Early-Z：尽可能在昂贵的 Fragment Shader 之前拒绝深度不通过的片元。
- Late-Z：在 Shader 之后完成相关深度判定和/或写入。

修改 Fragment Depth、某些 `discard` / Coverage 行为、Shader 副作用等可能约束 Early-Z。GPU/API 对提前深度测试的优化细节各异。不要把 Early-Z 描述为固定且无条件的管线位置。

### 7. 为什么不透明物体经常 Front-to-Back 绘制？

这样可较早填充 Depth Buffer、减少后续不可见片元的昂贵着色工作。但排序也有成本：材质切换、PSO 切换、Draw Call 批次和带宽都要权衡。

透明物体具有混合顺序依赖，不能简单沿用不透明排序逻辑。完整内容见下一篇《深度测试与透明渲染》。

## 十一、MSAA 与覆盖采样入门

### 1. MSAA 4× 代表 Fragment Shader 一定运行四次吗？

**不一定。** 常见 MSAA 使用多个 Coverage/Depth/Stencil Sample，但 Shader 通常可以每片元执行一次并向多个 Sample 写入相关结果；Per-Sample Shading 可以在特定条件下增加 Shader 调用。

### 2. MSAA 为什么能改善几何边缘？

像素中心可能落在图元之外，但图元可能覆盖像素的部分面积。MSAA 通过多个样本点近似 Coverage，比单点测试更能描述三角形边缘。

### 3. MSAA 为什么不能根治 Shader Aliasing？

三角形完全覆盖一个像素时，纹理高频细节、Specular Highlight 或噪声仍然可能闪烁。MSAA 对几何覆盖类锯齿较有效；Shader Aliasing 往往还需纹理过滤、Specular AA、TAA 等技术。

后续《抗锯齿技术》会进一步对比 SSAA/MSAA/FXAA/TAA。

## 十二、从零实现软件 Rasterizer

### 1. 推荐的最小实现顺序是什么？

1. 绘制二维固定颜色三角形。
2. 加入 Bounding Box、Edge Function 和 Top-Left Rule。
3. 加入重心坐标与顶点颜色插值。
4. 加入 Model/View/Projection 与齐次裁剪。
5. 加入 Z-buffer。
6. 加入 Perspective-Correct UV 与简单纹理采样。
7. 加入 Backface Culling、深度调试与基本 Profiling。
8. 再考虑 Tile/Binning、多线程、SIMD、MSAA 与真实材质。

先固定几何与插值正确性，再做性能优化。

### 2. 软件渲染器的数据流怎么组织？

~~~text
Index/Vertex Buffer
      |
      v
Vertex Transform -> Clip Vertices
      |
      v
Homogeneous Clipping -> Convex Polygon
      |
      v
Fan Triangulation -> Clipped Triangles
      |
      v
Divide + Viewport -> Screen Vertices
      |
      v
Triangle Setup / Bounding Box / Edge Equations
      |
      v
Coverage & Barycentric
      |
      +---> Interpolate NDC Z -> Depth Test
      |
      +---> Interpolate UV/w & 1/w -> UV -> Texture
                                                  |
                                                  v
                                             Color Write
~~~

### 3. 软件光栅化核心循环的 C++ / GLM 示例

下方是一个**针对已完成齐次裁剪的三角形**的教学实现。约定：

- 左上角为屏幕原点、Y 向下。
- 单采样像素中心 `(x+0.5,y+0.5)`。
- 常规非 Reversed-Z，Depth Buffer 初始值为 `1`，DepthFunc 为 LESS。
- Clip Space 深度是传统 OpenGL `[-1,1]`。
- 省略 Stencil、Blending、MSAA、纹理过滤，以及数值异常处理。

~~~cpp
#include <algorithm>
#include <cmath>
#include <utility>
#include <vector>
#include <glm/glm.hpp>

struct RasterVertex
{
    glm::vec2 xy;       // Screen XY, +Y down
    glm::vec2 uvOverW;  // uv / clip.w
    float invW;         // 1 / clip.w
    float zNdc;         // clip.z / clip.w
};

struct FrameBuffer
{
    int width = 0;
    int height = 0;
    std::vector<glm::vec4> color;
    std::vector<float> depth; // filled with 1.0f
};

float Edge(const glm::vec2& a, const glm::vec2& b,
           const glm::vec2& p)
{
    glm::vec2 ab = b - a;
    glm::vec2 ap = p - a;
    return ab.x * ap.y - ab.y * ap.x;
}

bool IsTopLeft(const glm::vec2& a, const glm::vec2& b)
{
    float dx = b.x - a.x;
    float dy = b.y - a.y;
    return dy < 0.0f || (dy == 0.0f && dx > 0.0f);
}

bool InsideEdge(float value, bool inclusive)
{
    return value > 0.0f || (value == 0.0f && inclusive);
}

void RasterizeTriangle(
    RasterVertex a, RasterVertex b, RasterVertex c,
    FrameBuffer& fb)
{
    float area = Edge(a.xy, b.xy, c.xy);
    if (area == 0.0f)
        return;

    // 这里只归一化覆盖测试的顶点顺序。
    // 真正的 Backface Culling 应先根据配置独立判断。
    if (area < 0.0f)
    {
        std::swap(b, c);
        area = -area;
    }

    float minX = std::min({a.xy.x, b.xy.x, c.xy.x});
    float maxX = std::max({a.xy.x, b.xy.x, c.xy.x});
    float minY = std::min({a.xy.y, b.xy.y, c.xy.y});
    float maxY = std::max({a.xy.y, b.xy.y, c.xy.y});

    int x0 = std::max(0, static_cast<int>(std::floor(minX)));
    int x1 = std::min(fb.width - 1,
                      static_cast<int>(std::ceil(maxX)));
    int y0 = std::max(0, static_cast<int>(std::floor(minY)));
    int y1 = std::min(fb.height - 1,
                      static_cast<int>(std::ceil(maxY)));

    if (x0 > x1 || y0 > y1)
        return;

    bool includeAB = IsTopLeft(a.xy, b.xy);
    bool includeBC = IsTopLeft(b.xy, c.xy);
    bool includeCA = IsTopLeft(c.xy, a.xy);

    for (int y = y0; y <= y1; ++y)
    {
        for (int x = x0; x <= x1; ++x)
        {
            glm::vec2 p(x + 0.5f, y + 0.5f);

            float eAB = Edge(a.xy, b.xy, p);
            float eBC = Edge(b.xy, c.xy, p);
            float eCA = Edge(c.xy, a.xy, p);

            if (!InsideEdge(eAB, includeAB) ||
                !InsideEdge(eBC, includeBC) ||
                !InsideEdge(eCA, includeCA))
                continue;

            float lA = eBC / area;
            float lB = eCA / area;
            float lC = eAB / area;

            // NDC Z 可进行屏幕空间线性插值
            float zNdc = lA * a.zNdc +
                         lB * b.zNdc +
                         lC * c.zNdc;
            float depth = std::clamp(zNdc * 0.5f + 0.5f,
                                     0.0f, 1.0f);

            int idx = y * fb.width + x;
            if (!(depth < fb.depth[idx]))
                continue;

            // UV 则要进行 Perspective-Correct Interpolation
            float invW = lA * a.invW +
                         lB * b.invW +
                         lC * c.invW;
            if (invW <= 0.0f)
                continue;

            glm::vec2 uvOverW =
                lA * a.uvOverW +
                lB * b.uvOverW +
                lC * c.uvOverW;
            glm::vec2 uv = uvOverW / invW;

            // 先以可视化 UV 的颜色调试，再加入纹理采样
            fb.color[idx] = glm::vec4(uv.x, uv.y, 0.0f, 1.0f);
            fb.depth[idx] = depth;
        }
    }
}
~~~

**重要限制：** 这个代码假设 FrameBuffer 存储已正确分配，裁剪后的顶点没有非有限值，且坐标能安全地转换成整数。实际工程还需要固定点一致性、健壮裁剪与线程安全；本例不会替代 GPU 规范级光栅器。

### 4. 从 ClipVertex 如何得到 RasterVertex？

~~~cpp
RasterVertex ToRasterVertex(
    const ClipVertex& v, int width, int height)
{
    float invW = 1.0f / v.clip.w;
    glm::vec3 ndc = glm::vec3(v.clip) * invW;

    RasterVertex out;
    out.xy = glm::vec2(
        (ndc.x + 1.0f) * 0.5f * width,
        (1.0f - ndc.y) * 0.5f * height
    );
    out.uvOverW = v.uv * invW;
    out.invW = invW;
    out.zNdc = ndc.z;
    return out;
}
~~~

接上第四节的 `ClipTriangle`，当裁剪多边形有三个及以上顶点，按扇形产生三角形并调用光栅化函数。

### 5. 如何验证软件 Rasterizer？

| 测试场景 | 主要验证 |
|---|---|
| 完整画面内三角形 | Coverage、Bounding Box |
| 共线/重复顶点 | 退化处理 |
| 两三角形拼矩形 | 共享边 Top-Left 一致性 |
| 跨近平面三角形 | 齐次裁剪 |

| 倾斜棋盘格平面 | UV 透视校正 |
| 镜像模型 | 绕序、背面剔除 |
| 紧贴视口边界的图元 | 裁剪与边界 |
| 与 OpenGL 参考实现对比 | 各阶段数据流一致性 |

## 十三、Rasterization 性能优化

### 1. 为什么按三角形遍历像素可能很慢？

- 大 Bounding Box 中很多候选像素在三角形外。
- 每像素重复做边函数计算、除法和属性插值。
- 小三角形太多导致 Triangle Setup 开销大。
- 图元间 Overdraw 增加写入/着色成本。
- 像素访问和多个渲染目标可能引发带宽压力。
- 多线程无序写入 Color/Depth 产生竞争与 Cache 问题。

必须用 Profiling 识别瓶颈，而不是直接认定光栅化一定受 ALU 限制。

### 2. Tile / Binning 为什么有用？

1. 将屏幕划分为固定大小的 Tile（例如 `16×16` 或 `32×32`，仅作示例）。
2. 对三角形计算 Bounding Box，找出它可能覆盖的 Tile。
3. 把图元分配到对应 Tile 列表。
4. 按 Tile 调度工作，处理更局部的 Color/Depth 数据。
5. Tile 可以划分任务的像素写入所有权，降低并发冲突。

这不意味着桌面所有 GPU 与移动 GPU 都拥有同一种 Tile-Based Deferred Rendering 硬件架构。

### 3. SIMD 怎样加速 Edge Function？

边函数对屏幕坐标是线性的：`E(x,y)=αx+βy+γ`。

同一行多个 Sample 可以并行处理：

- 生成多个 X 位置组成 SIMD 向量。
- 并行计算三条边的 Coverage。
- 生成 Lane Mask。
- 对有效 Sample 执行深度与插值。
- 尽量合并 Color/Depth 的内存访问。

同时关注非规则覆盖导致的 Lane 空转、不同图元尺寸和分支开销。

### 4. 多线程 Rasterizer 怎么保证正确性？

一个实用策略是**每个 Tile 在同一时刻只由一个任务负责写入**，避免多个线程无保护地修改同一像素的深度与颜色。

还必须关注：

- 不透明片元的 Z-buffer 可见性。
- 透明 Blending 与顺序依赖。
- Tile Binning 阶段的任务调度和内存分配。
- Framebuffer 对齐、False Sharing 和同步开销。

不能简单“一个三角形一个线程”就认为得到正确且可扩展的并行方案。

### 5. GPU Vertex Bound / Pixel Bound / Bandwidth Bound 怎么区分？

| 可能瓶颈 | 排查线索 |
|---|---|
| CPU / Draw Call | 大量小批次，提交和状态绑定成本高 |
| Vertex / Primitive | 大量顶点、微小三角形、Vertex Shader 或 Setup 压力 |
| Fragment | 高分辨率、Overdraw、昂贵材质 Shader |
| Bandwidth / Texture | 大量 Texture Fetch、MRT 写入、缓存局部性差 |
| Blend / ROP | 大量 Color/Depth 写入、混合开销 |

可以控制场景规模、分辨率、Shader 成本和绘制批次做对照，并用 RenderDoc/厂商 GPU Profiler 验证。

## 十四、实际 GPU 与软件 Rasterizer 的差异

### 1. 硬件光栅化是否仅仅执行三条边函数？

边函数是很好的理论模型，真实 GPU 还涉及：

- Primitive Setup、子像素精度与粗粒度覆盖判定。
- Tile / Block、Sample Pattern 与 MSAA。
- Shader Lane/Quad、Helper Invocation。
- 屏幕空间导数、Mipmap LOD。
- Depth Compression、Hi-Z、Cache/ROP。
- 并发调度和资源 Hazard。

### 2. Fragment Shader 为什么常涉及 2×2 Quad？

纹理隐式 LOD 通常需要求 UV 对屏幕位置的偏导，例如 `dFdx`、`dFdy`。GPU 常通过小规模相邻片元组（典型是 `2×2 Quad`）估算导数，边缘处可能产生不真正写像素的 Helper Invocation。

### 3. 为什么动态分支中的导数可能有风险？

导数依赖邻域 Invocation 的信息。若分支导致相邻 Lane 执行不同代码，部分 Shader 语言/API 对导数有效性有限制，可能得到未定义或不可靠结果。可考虑在分支前计算导数或使用显式梯度采样。

### 4. Conservative Rasterization 是什么？

普通覆盖依赖设定的 Sample Position。Conservative Rasterization 采用更保守的规则检测与像素区域有交叠的图元（具体行为看 API 的模式和约定），可用于部分体素化和可见性算法。

## 十五、RenderDoc 与光栅化问题定位

### 1. 模型缺面、闪烁或形状异常，怎么排查？

1. Vertex/Index Buffer 数据是否正确。
2. Vertex Format、Stride、Offset 与 Shader 输入是否匹配。
3. MVP 矩阵与坐标约定是否一致。
4. Vertex Shader 输出 Clip 位置是否有效。
5. 是否遭到近平面裁剪、Backface Culling。
6. Viewport / Scissor / Depth 状态是否正确。
7. 着色属性是否有错误的空间或插值方式。

### 2. 棋盘格纹理斜面变形，应该优先查什么？

先检查软件 Rasterizer 是否错误使用屏幕线性 UV；核对是否保留 `uv/w` 与 `1/w`，并确认 Clip Vertex 经过正确裁剪。再看纹理地址模式和 Mipmap/LOD。

### 3. RenderDoc 的定位流程是什么？

捕获一帧 → 选择目标 Draw Call → 查看 Pipeline State → Mesh Viewer（顶点输入/VS 输出）→ Texture Viewer → Pixel History（适用时）→ Shader Debugging（适用时）。

对于软件渲染器，可以另外输出 Triangle ID、Edge 值、重心坐标、UV、深度等 Debug Buffer，逐像素与 GPU 参考图比较。

## 十六、秋招高频问题与追问

### Q1：请完整解释一个三角形从顶点到屏幕像素经历哪些阶段？

应从 Input Assembly、Vertex Shader、图元装配、裁剪、Culling、透视除法、Viewport、Rasterization、Fragment Shader 和深度/混合操作展开，并强调这是逻辑流程。

### Q2：Vertex Shader 的 gl_Position 是什么坐标？

齐次 Clip Space，不是已经除以 W 的 NDC。

### Q3：为什么要先裁剪再透视除法？

跨近平面图元可能经过 `w=0`，直接透视除法会失真或发散。

### Q4：传统 OpenGL 齐次裁剪的六个条件是什么？

`-w ≤ x,y,z ≤ w`，可写成 `w±x`、`w±y`、`w±z` 六个非负条件。

### Q5：跨近平面的三角形如何处理？

在 Clip Space 做多边形裁剪，生成交点与相应 Varying，再三角化并透视除法。

### Q6：为什么不能用顶点法线替代 Backface Culling？

法线是着色属性，背面剔除依据几何图元的屏幕绕序。

### Q7：如何判断 Sample 是否处于三角形内部？

用三条边的 Edge Function 判断同侧，再应用一致的边界包含规则。

### Q8：为什么共享边必须有 Top-Left Rule？

避免两个相邻三角形沿同一条边产生双重覆盖或空洞。

### Q9：Edge Function 为什么适合增量计算？

它是关于 X、Y 的一阶线性函数，移动一个像素只需增加固定差值。

### Q10：如何由 Edge Function 求重心坐标？

每个顶点的权重等于对边 Edge Function 值除以三角形总有向面积。

### Q11：为什么透视投影下 UV 不能直接屏幕 Lerp？

屏幕重心与透视投影前的几何重心不同；需使用 `a/w` 和 `1/w` 归一化插值。

### Q12：透视校正插值公式是什么？

$$
a(P)=
\frac{\sum_i \lambda_i a_i/w_i}
{\sum_i \lambda_i / w_i}.
$$

### Q13：为什么 NDC Z 可以屏幕线性插值？

对于标准投影三角形，NDC 深度在屏幕平面是仿射的；UV 等原始属性通常需要透视校正。

### Q14：smooth、noperspective、flat 分别指什么？

默认透视校正、屏幕线性插值、整个图元保持常量（取指定顶点值）。

### Q15：Fragment、Pixel、Sample 三者如何区分？

片元是图元产生的候选，像素是渲染目标位置，Sample 是覆盖与深度/模板等操作的采样位置。

### Q16：Early-Z 一定在 Fragment Shader 前吗？

不一定，取决于 GPU/API 与 Shader 深度、Coverage、Discard 和副作用等语义。

### Q17：MSAA 4× 就意味着 Fragment Shader 执行四次吗？

通常不一定；Coverage/Depth 样本数与 Shader Invocation 数不同，Per-Sample Shading 是另一种情况。

### Q18：为什么软件 Rasterizer 适合做 SIMD？

Edge Function、Depth 和属性插值天然能对多个像素并行计算。

### Q19：为什么做 Tile-Based Rasterization？

提升局部性、降低无关像素测试，方便按 Tile 调度并安全分配像素写入所有权。

### Q20：多线程逐三角形写 Depth Buffer 有什么风险？

多线程可能同时读写同一像素的 Depth/Color，产生数据竞争或无序覆盖。

### Q21：负缩放为何导致 Cull 异常？

镜像改变定向并可能翻转屏幕绕序，需要重新考虑 FrontFace/CullMode。

### Q22：为什么 GPU 渲染结果与软渲染不完全一致？

裁剪、样本规则、插值、深度精度、贴图采样、MSAA、sRGB 和混合等都可能不同。

### Q23：为什么 GPU Fragment Shader 需要 Helper Invocation？

为了在部分情况下计算屏幕空间导数和相关邻域操作，而不是让每个执行的 Invocation 都写入像素。

### Q24：如何判断一个场景是不是 Pixel / Fill-Rate Bound？

通过分辨率、Shader、Overdraw 与其他变量的对照实验结合 GPU Profiler 验证，不能只凭帧率猜测。

### Q25：让你介绍自己写的软光栅，你会从哪几层讲？

几何处理与裁剪 → Triangle Setup → Coverage/边规则 → 重心插值 → Depth/Color → Tile、SIMD、多线程优化 → 结果验证与性能分析。

## 十七、动手验证题

### 练习 1：手算重心坐标

在 Y 向上的二维平面：

~~~text
A=(0,0), B=(4,0), C=(0,4), P=(1,1)
~~~

计算 Edge Function 和权重，参考结果：

$$
\lambda_A=\frac12,\quad
\lambda_B=\frac14,\quad
\lambda_C=\frac14.
$$

### 练习 2：透视校正数值题

屏幕重心为 `λ=(0.5,0.25,0.25)`，顶点 `w=(1,2,4)`，属性 U 为 `u=(0,1,1)`。

屏幕线性结果为 `0.5`；透视校正结果为：

$$
u_{\mathrm{correct}}=
\frac{0.5\cdot0/1+0.25\cdot1/2+0.25\cdot1/4}
{0.5/1+0.25/2+0.25/4}
=\frac{3}{11}.
$$

### 练习 3：拼矩形的两个三角形

用两只共享对角线的三角形拼成矩形，分别关闭和开启 Top-Left Rule。统计每个样本被多少个三角形覆盖，检查是否有裂缝或多次覆盖。

### 练习 4：跨近平面裁剪

让一个三角形部分顶点满足 `z < -w`，使用齐次裁剪生成新的凸多边形，再三角化。与 OpenGL 参考图比较。

### 练习 5：棋盘格斜平面

将斜向远离相机的棋盘格分别用屏幕 UV 线性插值和透视校正插值绘制，观察哪一种符合透视规律。

### 练习 6：逐项优化 Soft Rasterizer

以固定场景作为 Baseline，分别测试增量 Edge、Tile Binning、Tile 级线程分配和 SIMD。记录执行时间、候选样本数量、Draw Calls、图元数和正确性差异。

## 十八、公式与关键结论速记

| 知识点 | 公式 / 结论 |
|---|---|
| 传统 GL Clip | `-w ≤ x,y,z ≤ w` |
| 透视除法 | `p_ndc = p_clip.xyz / p_clip.w` |
| Edge Function | `E(A,B,P) = (Bx-Ax)(Py-Ay) - (By-Ay)(Px-Ax)` |
| 两倍有向面积 | `D = E(A,B,C)` |
| 重心坐标 | `λA = E(B,C,P)/D`，其他循环置换 |
| 透视校正 | `a = sum(λi ai/wi) / sum(λi/wi)` |
| 深度插值 | `z_ndc = sum(λi z_ndc,i)` |
| 常规 GL 窗口深度 | `z_window = (z_ndc+1)/2` |
| Top-Left Rule | 共享边使用一致边界包含规则 |
| Early-Z | 可能提前深度拒绝，但不保证任何情况下都生效 |
| MSAA | Coverage/Depth Sample 与 Shader Invocation 不同 |
| 软渲染优化 | Binning、Tile、SIMD、增量 Edge、多线程 |
