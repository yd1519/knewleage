# 计算机图形学秋招复习文档（二）：渲染管线与光栅化

**复习范围：** GPU 图形渲染管线、顶点与图元处理、齐次裁剪、背面剔除、透视除法、Viewport、三角形光栅化、边函数、重心坐标、透视校正插值、片元处理、深度与 Early-Z、MSAA 基础、软件光栅化实现及优化。

**面试目标：** 能完整解释一个三角形从顶点数据变成屏幕像素的过程；独立推导边函数、齐次裁剪与透视校正插值；实现支持裁剪、深度测试和透视正确 UV 的软件光栅器。

**前置知识：** [01-数学基础与空间变换](01-数学基础与空间变换.md) 中的 MVP、齐次坐标、投影矩阵与深度。

**排版约定：** 正文的简短表达式用行内代码，复杂推导用独立数学公式块，避免不支持行内 LaTeX 的阅读器显示原始命令。

**本文统一约定（重要）：**

- 列向量：`p_clip = P V M p_local`，矩阵从右向左作用。
- 默认传统 OpenGL Clip Space：`-w ≤ x,y,z ≤ w`，透视除法后 `z_ndc ∈ [-1,1]`；其他深度约定会明确说明。
- 数学二维平面通常用 `Y` 向上；软件光栅化示例使用左上角原点、`Y` 向下的屏幕坐标，相关边规则也以此为准。
- 只处理非退化三角形；进入 Rasterization 的图元已经正确完成齐次裁剪，顶点的 `w` 可安全相除。
- 本文的阶段顺序是便于理解的**逻辑管线**，真实 GPU 可以采用与之等价的并行、重排或优化实现。

## 一、图形渲染管线总览

### 1. Graphics Pipeline 主要解决什么问题？

它将 CPU 提交的顶点、索引、资源和绘制状态处理成最终的颜色与深度结果。

~~~text
CPU 场景更新 / 视锥和遮挡剔除 / Draw Call
                         |
                         v
GPU 顶点输入 / Input Assembly
                         |
                         v
                 Vertex Shader
                         |
                         v
        可选 Tessellation / Geometry 阶段
                         |
                         v
       Primitive Assembly / Clipping / Culling
                         |
                         v
        Perspective Divide / Viewport
                         |
                         v
          Rasterization / 属性插值
                         |
                         v
                 Fragment Shader
                         |
                         v
        Depth / Stencil / Blending 等操作
                         |
                         v
           Framebuffer / Render Target
~~~

这描述的是传统光栅化图形管线；Mesh Shader、Compute Shader 和 Ray Tracing 的调度方式并不完全相同。

### 2. CPU 和 GPU 在 Draw Call 里分别做什么？

CPU / 引擎侧主要负责可见对象选择、准备缓冲与纹理、绑定 Pipeline State、录制和提交命令、协调资源与同步。GPU 负责执行着色、图元处理、覆盖判断、插值和渲染目标写入等。

**Draw Call 不是执行一次 Vertex Shader。** 一个 Draw Call 可以处理很多顶点、图元和 Fragment；其开销既包括 CPU 提交也包括 GPU 工作。

### 3. 可编程阶段与固定功能阶段怎么区分？

| 类型 | 典型阶段 | 主要职责 |
|---|---|---|
| 可编程 | Vertex Shader | 顶点变换、蒙皮、Varying 输出 |
| 可编程 | Fragment Shader | 材质、光照、纹理与颜色计算 |
| 可选可编程 | Tessellation / Geometry | 细分、生成或修改图元 |
| 固定功能与管线状态 | Input Assembly、Clipping、Rasterization | 顶点装配、裁剪、覆盖与插值规则 |
| 固定功能与管线状态 | Depth、Stencil、Blending | 可见性与帧缓冲合成 |

固定功能不代表没有任何可配置项，FrontFace、CullMode、DepthFunc、BlendFunc 等都由管线状态控制。

### 4. 为什么软渲染与 OpenGL 同场景可能出现不同结果？

常见差异包括：Clip 深度范围、Viewport 坐标方向、裁剪/共享边规则、透视插值、Depth Compare、精度、MSAA Sample 位置、纹理过滤、sRGB、Blending 等。

对照测试之前，应固定各阶段约定，优先排查**几何与插值**，再排查光照材质。

## 二、顶点数据、索引与图元装配

### 1. Vertex 通常包含哪些属性？

| 属性 | 典型用途 |
|---|---|
| Position | 顶点位置与 MVP 变换 |
| Normal | 光照与材质计算 |
| Tangent / Bitangent Sign | 法线贴图切线空间 |
| UV | 纹理坐标 |
| Color | 顶点颜色或自定义数据 |
| Bone Weights / Indices | 骨骼蒙皮 |
| Instance Data | 实例变换或实例材质参数 |

**顶点身份不等于世界位置唯一。** UV Seam、硬法线边和材质切换可能要求同一位置拆成不同的顶点属性记录。

### 2. VBO / Vertex Buffer 与 EBO / Index Buffer 有什么区别？

Vertex Buffer 存属性，Index Buffer 存引用顶点的索引。同一顶点记录被多个三角形引用，有机会减少数据冗余并提高顶点缓存复用率。

**注意：** 索引绘制不保证顶点着色器对相同索引必然只运行一次；实际顶点复用取决于 Post-Transform Cache 等机制。

### 3. Triangle List 与 Triangle Strip 怎么比较？

- Triangle List：三个索引形成一个三角形，结构简单、常用。
- Triangle Strip：后续顶点可与之前的顶点组成新三角形，共享顶点较多，但需正确处理绕序与退化连接。
- Point / Line：生成点或线段；Patch 可作为 Tessellation 输入。

### 4. 为什么三角形是光栅化的基本单位？

三个非共线顶点唯一确定平面；三角形容易裁剪并通过重心坐标对平面属性插值。任意四边形可能非共面，因此通常先划分成三角形。

## 三、Vertex Shader 与空间变换

### 1. Vertex Shader 接收和输出什么？

~~~glsl
#version 450 core

layout(location = 0) in vec3 aPosition;
layout(location = 1) in vec2 aUV;
layout(location = 2) in vec3 aNormal;

uniform mat4 uModel;
uniform mat4 uView;
uniform mat4 uProjection;
uniform mat3 uNormalMatrix;

out vec2 vUV;
out vec3 vWorldNormal;

void main()
{
    gl_Position = uProjection * uView * uModel
                * vec4(aPosition, 1.0);

    vUV = aUV;
    vWorldNormal = uNormalMatrix * aNormal;
}
~~~

核心输出 `gl_Position` 是**齐次 Clip Space** 坐标，而不是已经除以 `w` 的 NDC 坐标。Varying 则会在图元光栅化时按指定语义插值。

### 2. 为什么 Vertex Shader 一般不直接输出 NDC？

如果提前丢失 `w`，跨近平面的三角形难以正确裁剪；同时也无法直接获得透视校正插值所需的 `1/w` 信息。

逻辑顺序：

~~~text
Local -> World -> View -> Clip -> Clipping -> NDC -> Window
                                    (Divide)   (Viewport)
~~~

### 3. Shader 里的坐标空间为什么容易用错？

例如在 Vertex Shader 中输出世界空间法线，却在 Fragment Shader 中拿它与观察空间光源方向点乘，结果就不正确。

每个 Varying 都应注明语义：World Position、View Position、Normal、UV 等；不要只靠变量名字猜测空间。

### 4. 每个顶点着色器 Invocation 能看到邻居顶点吗？

传统 Vertex Shader 主要处理当前输入顶点及可访问的缓冲资源，并不自动传入整个三角形。邻居关系通常由图元装配及后续阶段负责。

## 四、齐次裁剪 Clipping

### 1. 为什么必须先裁剪再透视除法？

透视投影具有 `w_clip = -z_view` 之类的关系；跨越近平面的线段可能经过 `w=0` 或改变符号。如果先做除法，会导致坐标发散或相机后方三角形翻转。

齐次 Clip Space 可直接依据平面不等式裁剪，之后再对有效几何做透视除法。

### 2. OpenGL 传统 Clip Space 的六个条件是什么？

$$
-w\le x\le w,\qquad
-w\le y\le w,\qquad
-w\le z\le w.
$$

把内侧定义为非负：

| 平面 | 有向距离函数 |
|---|---|
| Left | `d = w + x` |
| Right | `d = w - x` |
| Bottom | `d = w + y` |
| Top | `d = w - y` |
| Near | `d = w + z` |
| Far | `d = w - z` |

当 Clip 深度范围是 `[0,1]` 时，近裁剪条件通常改为 `z >= 0`，而不是 `z >= -w`。此外还可能有自定义裁剪平面。

### 3. 裁剪交点参数如何推导？

线段在齐次空间线性插值：

$$
P(t)=(1-t)P_0+tP_1,\qquad 0\le t\le1.
$$

线性裁剪平面函数对两个端点的值为 `d0`、`d1`，因此：

$$
d(t)=(1-t)d_0+td_1.
$$

令交点处 `d(t)=0`：

$$
\boxed{t=\frac{d_0}{d_0-d_1}.}
$$

用这个 `t` 同时插值裁剪位置和随顶点线性变化的 Varying。**不要在已透视除法的 NDC 边上用同样的参数去插值 Clip Space 属性。**

### 4. Sutherland-Hodgman 怎么裁剪凸三角形？

对多边形每条有向边 `A → B`：

| A 在平面内 | B 在平面内 | 输出 |
|---|---|---|
| 是 | 是 | B |
| 是 | 否 | 交点 |
| 否 | 是 | 交点、B |
| 否 | 否 | 无 |

依次对六个平面处理。输出可为零个顶点，也可有多于三个顶点；最后通过扇形三角化恢复三角形列表。

### 5. C++/GLM 的基础裁剪实现

代码采用传统 OpenGL 裁剪范围，处理齐次位置与 UV。为了说明核心算法，省略数值容差、非有限坐标和共享边防裂处理。

~~~cpp
#include <array>
#include <vector>
#include <glm/glm.hpp>

struct ClipVertex
{
    glm::vec4 clip;
    glm::vec2 uv;
};

float PlaneDistance(const glm::vec4& p, int plane)
{
    switch (plane)
    {
    case 0: return p.w + p.x; // Left
    case 1: return p.w - p.x; // Right
    case 2: return p.w + p.y; // Bottom
    case 3: return p.w - p.y; // Top
    case 4: return p.w + p.z; // Near, GL -1..1
    case 5: return p.w - p.z; // Far
    default: return -1.0f;
    }
}

ClipVertex LerpVertex(
    const ClipVertex& a, const ClipVertex& b, float t)
{
    return { glm::mix(a.clip, b.clip, t),
             glm::mix(a.uv, b.uv, t) };
}

std::vector<ClipVertex> ClipTriangle(
    const std::array<ClipVertex, 3>& input)
{
    std::vector<ClipVertex> polygon(input.begin(), input.end());

    for (int plane = 0; plane < 6 && !polygon.empty(); ++plane)
    {
        std::vector<ClipVertex> output;
        ClipVertex prev = polygon.back();
        float dPrev = PlaneDistance(prev.clip, plane);

        for (const ClipVertex& curr : polygon)
        {
            float dCurr = PlaneDistance(curr.clip, plane);
            bool aInside = dPrev >= 0.0f;
            bool bInside = dCurr >= 0.0f;

            if (aInside != bInside)
            {
                float t = dPrev / (dPrev - dCurr);
                output.push_back(LerpVertex(prev, curr, t));
            }

            if (bInside)
                output.push_back(curr);

            prev = curr;
            dPrev = dCurr;
        }
        polygon.swap(output);
    }
    return polygon;
}
~~~

如果裁剪后输出顶点数为 `N ≥ 3`，可把 `(v0, vi, vi+1)`（`i=1..N-2`）作为输出三角形。实际实现要处理重复交点、退化图元、浮点不一致和 `w=0` 边界。

## 五、图元绕序与 Backface Culling

### 1. 三角形正反面如何判断？

在二维平面上，顶点 `A,B,C` 的两倍有向面积为：

$$
D=(B_x-A_x)(C_y-A_y)
-(B_y-A_y)(C_x-A_x).
$$

`D` 的符号表示顶点绕序。若屏幕 `Y` 向上，`D>0` 是逆时针；若屏幕 `Y` 向下，视觉上的解释相反。

使用 FrontFace 状态指定正面绕序，CullMode 指定是否剔除正面或背面。真实 API 在窗口坐标与 Y 翻转等情况下有具体约定。

### 2. 为什么不能直接用顶点法线判断 Backface？

平滑顶点法线可能与真实几何面法线不同，法线贴图还会修改着色法线。Backface Culling 依据图元的**投影几何绕序**，而不是着色法线与光源或视线的点积。

### 3. 为什么负缩放或镜像可能导致面突然消失？

奇数次镜像会改变对象局部的绕序/定向，结合 Viewport/Projection 约定可能翻转最终屏幕绕序。如果 CullMode 不变，原本可见的正面可能被当成背面剔除。

### 4. Backface Culling、Frustum Culling、Occlusion Culling 区别？

- Backface：图元朝向剔除。
- Frustum：视锥外的几何或对象剔除。
- Occlusion：被其他几何遮住的对象/图元剔除。
- Depth Test：同一像素或 Sample 上可见性竞争。

它们粒度与算法不同，不应该混成一种“遮挡剔除”。

## 六、Perspective Divide 与 Viewport

### 1. 从 Clip Space 怎样进入 NDC？

$$
\mathbf p_{\mathrm{ndc}}=
\left(
\frac{x_c}{w_c},
\frac{y_c}{w_c},
\frac{z_c}{w_c}
\right).
$$

传统 OpenGL 默认 NDC 的三轴范围均为 `[-1,1]`。深度最终写入的范围还取决于 Depth Range。

### 2. NDC 到屏幕坐标如何转换？

如果 Viewport 左下角是 `(x0,y0)`、宽高是 `(W,H)`，窗口 `Y` 向上：

$$
x_s=x_0+\frac{x_{\mathrm{ndc}}+1}{2}W,\qquad
y_s=y_0+\frac{y_{\mathrm{ndc}}+1}{2}H.
$$

而本篇软件 Framebuffer 使用左上角原点、`Y` 向下的坐标：

$$
x_s=\frac{x_{\mathrm{ndc}}+1}{2}W,\qquad
y_s=\frac{1-y_{\mathrm{ndc}}}{2}H.
$$

### 3. 为什么像素中心经常用 `(x+0.5,y+0.5)`？

以每像素覆盖单位方格、像素索引为整数的模型，中心 Sample 位于半整数坐标。单采样光栅器通常在这个位置测试 Coverage。MSAA 会有多个 Sample Position，不能简单照搬。

### 4. Viewport 和 Scissor 有什么区别？

Viewport 将 NDC 变换为窗口坐标；Scissor 则限制允许写入/处理的矩形范围，两者不是同一个操作。

## 七、Edge Function：三角形覆盖测试

### 1. Rasterization 实际要做什么？

光栅化的核心是判断哪些 Sample 被三角形覆盖，并为后续 Fragment Shader 提供插值属性。软件渲染的基础步骤：

1. 转换顶点到 Screen。
2. 计算三角形 Bounding Box。
3. 在 Box 内遍历候选 Sample。
4. 用边函数确定是否覆盖。
5. 求重心权重，插值 Depth 和 Varying。
6. 执行片元着色、深度/模板/混合等。

### 2. Edge Function 的定义和几何意义是什么？

$$
E(A,B,P)=
(B_x-A_x)(P_y-A_y)
-(B_y-A_y)(P_x-A_x).
$$

它是两个二维向量的叉积标量，表示点 `P` 位于有向边 `A → B` 的哪一侧。值的绝对值等于由这两个向量构成的平行四边形面积。

### 3. 怎么用三条边判断内部？

当 `D=E(A,B,C)>0` 时：

$$
E(A,B,P)\ge0,\quad
E(B,C,P)\ge0,\quad
E(C,A,P)\ge0.
$$

但是软件/硬件最终还需指定**共享边上的相等情况**，不能无条件允许三个边都等于零，否则相邻三角形可能重复覆盖同一个 Sample。

### 4. 为什么 Bounding Box 很重要？

仅遍历：

$$
x_{\min}=\min(x_A,x_B,x_C),\quad
x_{\max}=\max(x_A,x_B,x_C),
$$

$$
y_{\min}=\min(y_A,y_B,y_C),\quad
y_{\max}=\max(y_A,y_B,y_C).
$$

再与 Viewport/Scissor 取交集。避免对完全不相关的屏幕区域做 Coverage Test。

### 5. 边函数为何能增量计算？

展开为：

$$
E(A,B,P)=\alpha x+\beta y+\gamma,
$$

$$
\alpha=A_y-B_y,\quad
\beta=B_x-A_x,\quad
\gamma=A_xB_y-B_xA_y.
$$

沿坐标单位步长：

$$
E(x+1,y)=E(x,y)+\alpha,\qquad
E(x,y+1)=E(x,y)+\beta.
$$

因此可以用加法代替遍历像素时每次重新计算叉积，且适合 Tile/SIMD。

### 6. 什么是 Top-Left Rule？

两个共享边三角形必须就“Sample 正好落在边上”采用一致规则，避免裂缝或双重覆盖。

**明确限定本篇软件示例的约定：** 屏幕 `Y` 向下；使用上面的 `E(A,B,P)`；三角形顶点已调整为 `D>0`。此时边的包含条件可写为：

~~~cpp
bool IsTopLeft(const glm::vec2& a, const glm::vec2& b)
{
    float dx = b.x - a.x;
    float dy = b.y - a.y;
    return dy < 0.0f || (dy == 0.0f && dx > 0.0f);
}
~~~

如果换成 `Y` 向上的坐标，或把边函数定义换成相反符号，必须同时修改该判定。真实 GPU 的 Rasterization Rule 还有亚像素精度与 Sample 位置约束。

### 7. 浮点边函数为什么可能产生裂缝？

共享边两侧若采用不同浮点舍入、裁剪交点或顶点坐标计算方式，即使使用相同理论规则，也可能出现覆盖差异。软件光栅器可考虑固定点亚像素坐标、整数边函数以及统一的顶点量化策略。

## 八、Barycentric Coordinates 与属性插值

### 1. 重心坐标的定义是什么？

任一与三角形 `A,B,C` 共面的点 `P`，可以写为：

$$
P=\lambda_A A+\lambda_B B+\lambda_C C,\qquad
\lambda_A+\lambda_B+\lambda_C=1.
$$

对非退化三角形，内部点的三个权重均非负。

### 2. 如何从边函数推导三个重心系数？

令 `D = E(A,B,C)`，则：

$$
\boxed{
\lambda_A=\frac{E(B,C,P)}{D},\quad
\lambda_B=\frac{E(C,A,P)}{D},\quad
\lambda_C=\frac{E(A,B,P)}{D}.
}
$$

验证：`P=A` 时 `λ_A=1`、其余为 0；`P=B`、`P=C` 同理。

### 3. 为什么不能随意把所有属性都屏幕线性插值？

屏幕重心权重给出二维投影三角形的仿射插值，但 3D 顶点属性（例如 UV、世界位置、普通 Varying）并非一般都在屏幕上呈仿射变化。

特殊情况：

- `noperspective` 属性故意使用屏幕线性插值。
- 顶点的 **NDC Z** 对于标准投影三角形可屏幕线性插值（第十节）。
- 深度相同、各顶点 `w` 相等时，普通透视校正与线性插值会退化为相同结果。

### 4. 为什么要处理退化三角形？

若 `D≈0`，重心公式分母过小或为零，可能导致 NaN 或巨大数值误差；应按实现的精度规则跳过退化图元。

## 九、Perspective-Correct Interpolation：必会推导

### 1. 为什么在屏幕上直接 Lerp UV 会错？

透视投影会让远处的空间距离压缩。屏幕线段的几何中点一般不是原始三维边的中点。使用屏幕线性 UV 会导致斜向地面的棋盘纹理被错误拉伸。

### 2. 透视校正插值公式是什么？

对屏幕空间重心系数 `λ_i`、顶点 Clip W `w_i` 和插值属性 `a_i`：

$$
\boxed{
a(P)=
\frac{
\displaystyle\sum_{i=0}^{2}\lambda_i\frac{a_i}{w_i}
}{
\displaystyle\sum_{i=0}^{2}\lambda_i\frac{1}{w_i}
}.
}
$$

先插值 `a_i/w_i`，再除以插值的 `1/w_i`。这就是软件光栅器必须保留 Clip W 的直接原因。

### 3. 一维线段怎么推导到这个公式？

在齐次 Clip Space，线段参数 `t`：

$$
P(t)=(1-t)P_0+tP_1.
$$

透视除法使屏幕坐标成为：

$$
x_{\mathrm{ndc}}(t)=
\frac{(1-t)x_0+t x_1}{(1-t)w_0+t w_1}.
$$

记屏幕线性参数为 `s`，则：

$$
x_{\mathrm{ndc}}(t)=
(1-s)\frac{x_0}{w_0}+s\frac{x_1}{w_1}.
$$

对非退化投影线段整理可得：

$$
\boxed{
t=\frac{s/w_1}{(1-s)/w_0+s/w_1}.
}
$$

对顶点属性 `a`，原始插值是 `a=(1-t)a0+t a1`，代回后得到：

$$
a=
\frac{(1-s)a_0/w_0+s a_1/w_1}
{(1-s)/w_0+s/w_1}.
$$

推广到屏幕三角形的三组重心权重，就得到上一节最终公式。

### 4. 数值例子：为什么屏幕中点不是 UV 中点？

令一条投影边的 `s=0.5`，顶点有 `w0=1`、`w1=2`，纹理坐标 `u0=0`、`u1=1`。

普通屏幕 Lerp 得 `0.5`，透视校正计算：

$$
u_{\mathrm{correct}}=
\frac{0.5\cdot0/1+0.5\cdot1/2}
{0.5/1+0.5/2}
=\frac13.
$$

它们明显不同。斜向远离相机的棋盘格是很好的测试案例。

### 5. GLSL 的 smooth、noperspective、flat 是什么？

| 修饰符 | 含义 | 典型用途 |
|---|---|---|
| `smooth`（默认） | 透视校正 | UV、颜色、世界空间位置 |
| `noperspective` | 屏幕空间线性 | 屏幕仿射量、特定效果 |
| `flat` | 不插值，使用图元指定顶点的值 | Material ID、整数索引 |

具体的类型限制、Provoking Vertex 和插值规则应以对应 GLSL/API 规范为准。

### 6. 为什么插值法线后还要 Normalize？

即使每个顶点法线都是单位长度，重心加权后的向量一般不再是单位向量。光照前通常执行：

~~~glsl
vec3 N = normalize(vWorldNormal);
~~~

同时检查法线与光照方向是否处于同一个坐标空间。
