# C++ 秋招八股复习文档（六）：现代 C++ 特性

**复习范围：** C++11/14/17/20 的常用语言特性与标准库工具，包括移动语义、右值引用、完美转发回顾、auto、decltype、nullptr、统一初始化、枚举类、默认/删除函数、override/final、lambda、constexpr、if constexpr、结构化绑定、inline 变量、optional、variant、any、string_view、span、filesystem、Concepts、Ranges、三路比较、consteval/constinit、jthread 等。

**标准版本：** 以 C++11、C++14、C++17 为主线，补充 C++20。具体项目使用哪些特性，取决于编译器支持和项目设置的语言标准。

## 一、现代 C++ 的发展脉络

### 1. 为什么需要现代 C++？

现代 C++ 并不是推翻传统 C++，而是在尽量保留性能与控制能力的同时，改善资源管理、类型安全、泛型编程和代码表达能力。

典型目标包括：

- 用移动语义减少不必要的资源复制。
- 用智能指针、RAII 和更明确的所有权表达资源生命周期。
- 用 `auto`、范围 for 和 lambda 减少样板代码。
- 用 `nullptr`、`enum class`、强类型接口减少类型安全问题。
- 用 `constexpr`、`if constexpr`、Concepts 表达编译期计算与约束。
- 用 `optional`、`variant` 等类型显式表达状态。
- 用 `string_view`、`span` 表达不拥有数据的视图，减少不必要复制。

### 2. 主要版本和代表特性

| 标准 | 代表特性 |
|---|---|
| C++11 | 移动语义、右值引用、auto、decltype、nullptr、lambda、智能指针、范围 for、enum class、constexpr 初版、可变参数模板 |
| C++14 | 泛型 lambda、lambda 初始化捕获、返回类型推导、放宽 constexpr、变量模板 |
| C++17 | 结构化绑定、if constexpr、折叠表达式、inline 变量、optional、variant、any、string_view、filesystem、类模板实参推导 |
| C++20 | Concepts、Ranges、三路比较、指定初始化、consteval、constinit、span、协程、jthread 等 |

这些是常见代表，并非该版本全部新增内容。

### 3. 现代 C++ 与“零成本抽象”

C++ 常追求零成本抽象：抽象接口不应在不必要时引入额外运行时成本。但这并不意味着每种现代特性都完全没有成本。

例如，`std::function` 可能涉及类型擦除和额外存储，`std::variant` 需要存储能够容纳备选类型的空间，模板会增加编译时间与代码体积。因此应理解抽象的语义与成本，而不是只背“现代 C++ 更快”。

## 二、移动语义与右值引用

### 1. 为什么需要移动语义？

假设一个对象管理堆内存、文件句柄或其他资源。复制对象时，传统深拷贝可能需要重新分配资源并复制内容；如果源对象即将销毁，这种复制可能是不必要的。

移动语义允许对象在满足条件时，把资源所有权转移给另一个对象，而不必复制资源本身。

~~~cpp
std::string a = "a long string";
std::string b = std::move(a);
~~~

对于标准字符串，移动通常可以高效地转移内部资源。但不要依赖移动后对象一定为空；除非类型的契约明确保证，否则移动后的对象通常仍然有效，但其具体值可能处于未指定状态。

### 2. 左值、右值与值类别

理解移动语义时，必须区分表达式的值类别。C++11 之后常见分类为：

- **左值（lvalue）：** 有身份、可以持续指代某个对象的表达式。
- **将亡值（xvalue）：** 有身份、资源可被复用的右值类别表达式。
- **纯右值（prvalue）：** 用于初始化对象或计算值的表达式。
- **泛左值（glvalue）：** 左值与将亡值的统称。
- **右值（rvalue）：** 纯右值与将亡值的统称。

简单示例：

~~~cpp
int x = 10;
int& lref = x;            // x 是左值表达式
int&& rref = 10;          // 10 是纯右值
int&& moved = std::move(x); // std::move(x) 是将亡值表达式
~~~

注意：变量的声明类型与表达式值类别不是一回事。即使变量声明为右值引用，使用变量名形成的表达式通常仍是左值。

### 3. std::move 做了什么？

`std::move` 本质上是一个类型转换工具，通常把参数转换为对应的右值引用类型；它本身不搬运内存、不释放资源，也不保证发生移动。

~~~cpp
std::string a = "hello";
std::string b = std::move(a);
~~~

实际是否调用移动构造函数或移动赋值运算符，取决于目标类型有哪些可行重载，以及重载决议选择了什么函数。

例如，如果类型没有移动构造函数，可能会退回到接受 const 左值引用的拷贝构造函数；也可能因其他重载或类型约束导致编译失败。

### 4. 移动构造函数与移动赋值运算符

~~~cpp
class Buffer {
public:
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_)
    {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    Buffer& operator=(Buffer&& other) noexcept
    {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;

            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

    ~Buffer()
    {
        delete[] data_;
    }

private:
    char* data_ = nullptr;
    std::size_t size_ = 0;
};
~~~

这段代码用于说明资源转移思想，并非推荐的完整资源类写法；真实实现还要定义或删除复制操作，考虑异常安全，并优先评估使用标准容器或智能指针来避免手动管理资源。

移动构造用于构造一个新对象；移动赋值用于处理已经存在的目标对象，通常必须先妥善处理目标对象原有资源。

### 5. 移动操作为什么经常声明为 noexcept？

标准容器在扩容时可能需要搬移已有元素。如果移动构造可能抛异常，某些容器操作为了提供异常安全保证，可能选择使用拷贝构造（如果可用）而不是可能抛异常的移动构造。

因此，对确实能够保证不抛异常的移动操作，声明 `noexcept` 有助于标准库选择更合适的操作路径。

不要为了性能盲目添加 `noexcept`：如果函数实际可能抛出异常，一旦异常逃出 noexcept 函数，会调用 `std::terminate`。

### 6. 为什么 std::move(const 对象) 常常不能移动？

~~~cpp
const std::string source = "hello";
std::string target = std::move(source);
~~~

`std::move(source)` 的结果带有 const 限定，类型通常类似 `const std::string&&`。常见移动构造函数接受的是 `std::string&&`，不能绑定到 const 右值引用参数，因为移动通常需要修改源对象。

因此这个例子通常会选择拷贝构造（若可行），而不是常见的移动构造。

### 7. 编译器何时会生成移动操作？

移动构造和移动赋值是否隐式声明，受类的特殊成员函数情况影响。比如用户声明了析构函数、拷贝构造或拷贝赋值等操作时，隐式移动操作的生成规则会受到影响。

面试中应结合 Rule of Zero/Three/Five 回答：不要只记“编译器总会生成移动构造函数”。如果类不直接管理资源，优先让成员类型自动管理资源；只有确实需要自定义所有权语义时，再谨慎定义特殊成员函数。

### 8. 移动语义与完美转发的关系

移动语义关心资源是否能从某对象转移；完美转发关心泛型包装器如何保留实参的值类别和类型信息。

- `std::move(x)`：表达“可以把 x 当作右值类别使用”。
- `std::forward<T>(x)`：根据推导出的 T，有条件地保留实参原本的值类别。
- 两者都不保证一定执行移动操作。

完美转发的完整推导与引用折叠规则见第四节“模板与泛型编程”。

## 三、auto、decltype 与类型推导

### 1. auto 的基本用法

`auto` 让编译器根据初始化表达式推导变量类型。

~~~cpp
auto x = 10;       // int
auto y = 3.14;     // double
auto text = "hi";  // const char*
~~~

这里 `auto` 并不是动态类型。变量类型在编译期确定，初始化完成后仍是静态类型。

### 2. auto 的推导规则接近模板按值推导

~~~cpp
int x = 10;
const int cx = 20;
int& ref = x;

auto a = cx;   // int
auto b = ref;  // int
auto& c = cx;  // const int&
const auto d = x; // const int
~~~

按值声明的 `auto` 通常会忽略顶层 const 和引用属性，类似模板参数按值推导。使用 `auto&` 或 `const auto&` 则可以保留引用语义和对应限定。

指针指向对象的 const 属于类型内部的限定，不要与顶层 const 混为一谈。

### 3. auto 与花括号初始化

花括号初始化的类型推导存在特殊规则：

~~~cpp
auto a = {1, 2, 3}; // std::initializer_list<int>
auto b{1};          // C++11/14/17 中通常推导为 int
~~~

不要简单地说“auto 遇到花括号一定是 initializer_list”。复制列表初始化与直接列表初始化的规则不同；C++ 标准版本和初始化形式都会影响结果。

### 4. decltype 是什么？

`decltype(expression)` 根据表达式的类型和值类别规则确定类型，不会执行表达式。

~~~cpp
int x = 10;
decltype(x) a = 1;   // int
decltype((x)) b = x; // int&
~~~

最重要的区别：

- 当表达式是未加括号的 id-expression 或未加括号的类成员访问表达式等符合特殊规则的形式时，decltype 通常得到所命名实体的声明类型。
- 其他情况下，decltype 根据表达式的值类别推导：左值得到 T&，将亡值得到 T&&，纯右值得到 T。

因此 `decltype(x)` 与 `decltype((x))` 可能不同。

### 5. decltype(auto) 的用途

C++14 引入 `decltype(auto)`，允许变量或函数返回类型使用 decltype 规则推导。

~~~cpp
int x = 10;

decltype(auto) a = x;   // int
decltype(auto) b = (x); // int&
~~~

它适用于需要精确保留表达式类型、引用属性的泛型代码。但也更容易意外返回引用或产生悬空引用，因此不要把它当作普通 `auto` 的无脑替代品。

### 6. auto、decltype 与尾置返回类型

~~~cpp
template<class T, class U>
auto Add(T a, U b) -> decltype(a + b)
{
    return a + b;
}
~~~

尾置返回类型可以在参数列表之后写出返回类型，适合返回类型依赖参数的情况。

C++14 起，许多函数可以直接使用返回类型推导：

~~~cpp
auto Add(int a, int b)
{
    return a + b;
}
~~~

返回类型推导规则仍有要求，例如同一个函数的各个 return 路径通常必须推导出一致的返回类型。

### 7. auto 在范围 for 中的区别

~~~cpp
std::vector<std::string> values{"a", "b"};

for (auto value : values) {
    // value 是元素的副本
}

for (auto& value : values) {
    // value 引用原元素，可以修改
}

for (const auto& value : values) {
    // 避免复制，同时只读访问
}
~~~

元素对象较大时，按值循环可能产生复制成本。对只读遍历，`const auto&` 常是合适选择；但对于很小的标量类型，按值也可能更清晰且足够高效，应结合语义和类型判断。

## 四、nullptr、enum class 与类型安全

### 1. nullptr 与 NULL 的区别

`nullptr` 是 C++11 引入的空指针字面量，其类型为 `std::nullptr_t`，可以转换为各种指针类型。

~~~cpp
void Func(int);
void Func(char*);

Func(nullptr); // 选择指针重载
~~~

传统的 `NULL` 可能被实现为整数常量 0，因此在重载中容易产生歧义或选择意外的整数重载。现代 C++ 应优先使用 `nullptr` 表示空指针。

### 2. enum class 是什么？

~~~cpp
enum class Color {
    Red,
    Green,
    Blue
};

Color color = Color::Red;
~~~

强类型枚举（scoped enum）有以下特点：

- 枚举项限定在枚举作用域内。
- 不会像传统 enum 那样隐式转换为整数。
- 可以指定底层整数类型，例如 `enum class State : unsigned char`。
- 类型安全性更好，减少名称冲突和意外比较。

### 3. enum 与 enum class 的区别

传统枚举：

~~~cpp
enum OldColor {
    Red,
    Green
};

int value = Red; // 传统 enum 可以隐式转换为整数
~~~

强类型枚举：

~~~cpp
enum class NewColor {
    Red,
    Green
};

// int value = NewColor::Red; // 错误：不能隐式转换为 int
int value = static_cast<int>(NewColor::Red);
~~~

当需要整数表示时，应显式转换，并确认该转换符合业务语义。

### 4. 类型别名：using 与 typedef

两者都可以声明类型别名：

~~~cpp
typedef unsigned int uint;
using uint2 = unsigned int;
~~~

`using` 的一个重要优势是可以更自然地声明别名模板：

~~~cpp
template<class T>
using Vec = std::vector<T>;

Vec<int> values;
~~~

别名本身不会创建一个新的独立类型；它只是为已有类型提供另一个名字。

## 五、统一初始化与常见初始化陷阱

### 1. 花括号初始化的优势

C++11 引入统一初始化语法：

~~~cpp
int x{10};
std::vector<int> values{1, 2, 3};
~~~

花括号初始化可以避免部分窄化转换。例如把浮点数转换为整数的初始化可能直接被诊断为错误，而不是静默丢失精度。

### 2. 窄化转换

~~~cpp
int x = 3.14; // 允许，但会丢失小数部分
// int y{3.14}; // 错误：列表初始化不允许该窄化转换
~~~

这能帮助提前发现精度丢失，但也要理解规则具体适用于哪些初始化形式和常量表达式。

### 3. initializer_list 优先匹配陷阱

~~~cpp
std::vector<int> a(3, 7); // 3 个元素，每个元素为 7
std::vector<int> b{3, 7}; // 两个元素：3 和 7
~~~

当类有 `std::initializer_list` 构造函数时，列表初始化通常优先考虑该类构造函数，这会导致花括号和圆括号表达不同语义。

因此，不要认为花括号只是“更安全的圆括号”。对于容器构造尤其需要留意。

### 4. 委托构造函数

C++11 允许一个构造函数委托同类的另一个构造函数完成初始化：

~~~cpp
class User {
public:
    User() : User("anonymous") {}
    explicit User(std::string name)
        : name_(std::move(name)) {}

private:
    std::string name_;
};
~~~

委托构造可以减少重复初始化逻辑。委托目标构造函数完成后，委托构造函数的函数体才执行。

## 六、默认函数、删除函数与 override/final

### 1. =default 与 =delete

~~~cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};
~~~

- `= default` 请求编译器提供默认实现（前提是该函数可被定义）。
- `= delete` 明确禁止该函数被使用。

删除函数比只把函数放在 private 区域更直观；它能让接口意图明确，并让不允许的调用在编译期报错。

### 2. 删除特定重载

~~~cpp
void Process(int);
void Process(double) = delete;

Process(1);   // 可以
// Process(1.5); // 错误：匹配到被删除的重载
~~~

删除函数也可以用于阻止不希望发生的隐式转换或调用路径。

### 3. override 的作用

~~~cpp
struct Base {
    virtual void Update(int);
};

struct Derived : Base {
    void Update(int) override;
};
~~~

`override` 告诉编译器该函数必须重写基类的虚函数。如果参数列表或 cv/ref 限定等不匹配，编译器会报错。

它不改变虚函数本身的动态绑定机制，而是让重写意图得到编译器检查。

### 4. final 的作用

`final` 可用于阻止类继续被继承，或阻止某个虚函数在派生类中继续被重写：

~~~cpp
struct Base {
    virtual void Run();
};

struct Derived final : Base {
    void Run() final;
};
~~~

`final` 表达的是语言层面的限制，不应简单理解为“编译器一定会把函数内联”。

## 七、lambda 的现代用法

### 1. lambda 是闭包对象

~~~cpp
int factor = 3;
auto multiply = [factor](int value) {
    return factor * value;
};
~~~

lambda 表达式会产生一个闭包对象，其类型由编译器生成。捕获变量会成为闭包状态的一部分。lambda 不等于普通函数指针，尤其是有捕获时。

### 2. 值捕获与引用捕获

- `[x]`：按值捕获 x 的副本。
- `[&x]`：按引用捕获 x。
- `[=]`：默认按值捕获 odr-use 的局部变量。
- `[&]`：默认按引用捕获 odr-use 的局部变量。

引用捕获的关键风险是生命周期。如果 lambda 被保存到任务队列、异步回调或长期存活的对象中，必须确认它引用的对象仍然存活。

### 3. C++14 初始化捕获

C++14 允许在捕获列表中声明并初始化新的闭包成员：

~~~cpp
auto task = [value = std::make_unique<int>(42)] {
    return *value;
};
~~~

这使 lambda 可以直接拥有一个资源，也支持移动捕获：

~~~cpp
auto ptr = std::make_unique<int>(10);
auto task = [p = std::move(ptr)] {
    return *p;
};
~~~

由于 unique_ptr 不可复制，移动捕获让闭包取得其所有权。此后原来的 ptr 处于有效但通常为空的状态。

### 4. 泛型 lambda（C++14）

~~~cpp
auto add = [](auto a, auto b) {
    return a + b;
};

auto x = add(1, 2);
auto y = add(1.5, 2.5);
~~~

参数中的 `auto` 让 lambda 的调用运算符成为可按不同参数类型实例化的泛型形式。其机制与模板密切相关。

### 5. mutable lambda

按值捕获的变量默认不能在 lambda 的常量调用运算符中修改。加上 `mutable` 后，闭包可修改自身保存的捕获副本：

~~~cpp
int x = 1;
auto counter = [x]() mutable {
    return ++x;
};
~~~

外部的 x 不会因此改变。

### 6. this 与 *this 捕获

在类成员函数中，lambda 可能需要访问当前对象。

- `[this]` 捕获 this 指针，lambda 使用的是原对象。
- C++17 的 `[*this]` 按值捕获当前对象的副本（按对象类型的复制语义）。

若使用 `[this]`，lambda 的生命周期不能超过它所依赖的对象生命周期，否则可能访问悬空对象。使用 `[*this]` 时则需要考虑对象是否可复制，以及复制对象与原对象之间的语义差异。

### 7. lambda 与 std::function

`std::function<R(Args...)>` 可以类型擦除不同可调用对象，使它们通过统一签名保存和调用。但类型擦除可能有额外开销。

若只需在当前作用域保存一个具体 lambda，通常 `auto` 就足够；需要运行时存储不同可调用类型时，再评估 `std::function` 或其他方案。

## 八、constexpr、consteval 与 constinit

### 1. constexpr 的基本意义

`constexpr` 用于声明可用于常量表达式的变量或函数（具体要求随标准版本演进）。

~~~cpp
constexpr int Square(int x)
{
    return x * x;
}

constexpr int value = Square(5);
~~~

constexpr 函数不意味着每次调用都一定在编译期执行。如果调用参数在编译期未知，它也可以在运行时执行，只要调用语境允许。

### 2. constexpr 与 const 的区别

- `const` 表示对象不能通过该名称被修改，不自动意味着其值可用于编译期常量表达式。
- `constexpr` 对变量要求常量初始化，并用于表达编译期可求值的意图；对函数则允许其在满足条件时参与常量求值。

~~~cpp
int runtimeValue();

const int a = runtimeValue(); // 可能是运行时初始化的 const 对象
// constexpr int b = runtimeValue(); // 错误：不是常量表达式
~~~

### 3. constexpr 规则随标准演进

C++11 的 constexpr 函数限制较严格；C++14 放宽了函数体写法；C++17 又增加了 `if constexpr` 等机制。现代 constexpr 可以完成比早期标准更复杂的编译期计算，但仍受常量表达式规则约束。

### 4. if constexpr（C++17）

~~~cpp
template<class T>
auto GetSize(const T& value)
{
    if constexpr (std::is_integral_v<T>) {
        return sizeof(value);
    } else {
        return value.size();
    }
}
~~~

`if constexpr` 根据编译期条件选择分支。模板实例化时，被丢弃的分支不会像普通 if 分支那样针对当前实例进行常规实例化检查，因此可用于按类型选择不同实现。

但非依赖的语法错误仍可能在模板定义阶段被诊断；if constexpr 并不能隐藏任意错误。

### 5. consteval（C++20）

`consteval` 声明立即函数：对该函数的调用必须产生常量表达式结果，否则程序不合法。

~~~cpp
consteval int CompileTimeSquare(int x)
{
    return x * x;
}

constexpr int value = CompileTimeSquare(4);
~~~

与 constexpr 函数相比，consteval 更明确地要求调用在编译期求值。

### 6. constinit（C++20）

`constinit` 用于要求具有静态或线程存储期的变量进行静态初始化。它不等于 const，也不禁止变量在运行时被修改。

~~~cpp
constinit int globalCounter = 0;
~~~

它适合表达“这个对象必须静态初始化”的约束，帮助避免某些动态初始化顺序问题。它不能用于普通局部自动存储期变量。

## 九、C++17 的常用特性

### 1. 结构化绑定

结构化绑定允许把数组、pair、tuple 或符合要求的聚合对象中的成员绑定到多个名字。

~~~cpp
std::pair<int, std::string> item{1, "hello"};
auto [id, name] = item;
~~~

- `auto [a, b]` 通常创建被绑定对象的副本。
- `auto& [a, b]` 可绑定到原对象。
- `const auto& [a, b]` 常用于只读且避免复制的场景。

结构化绑定的适用对象和名称绑定规则有专门规定，不应把它理解为任意类对象都能无条件拆开。

### 2. inline 变量

C++17 允许定义 inline 变量，常用于头文件中的全局变量或类内静态数据成员：

~~~cpp
struct Config {
    inline static int version = 1;
};
~~~

inline 变量可以在多个翻译单元中按 ODR 规则出现相同定义，并代表同一个实体。它不意味着编译器一定把变量值内联替换到每个使用点。

### 3. std::optional

`std::optional<T>` 表示一个可能有值、也可能无值的 T。

~~~cpp
std::optional<int> FindId(bool found)
{
    if (found) {
        return 42;
    }
    return std::nullopt;
}
~~~

访问前应判断是否有值，或使用符合语义的访问接口：

~~~cpp
auto result = FindId(true);
if (result.has_value()) {
    int id = *result;
}
~~~

`optional` 适合表达“结果可能不存在”，比魔法数或单独的 bool 输出参数更清楚。但它不是通用错误处理系统；若要表达多种失败原因，可能需要其他结果类型或错误机制。

### 4. std::variant

`std::variant<Ts...>` 表示当前持有候选类型之一的类型安全联合体。

~~~cpp
std::variant<int, std::string> value = 10;
value = std::string("hello");
~~~

可用 `std::get<T>`、`std::get_if<T>` 或 `std::visit` 访问：

~~~cpp
std::visit([](const auto& item) {
    // 根据当前实际持有的类型执行相应操作
}, value);
~~~

访问错误的备选类型时，`std::get` 会抛出 `std::bad_variant_access`；`get_if` 则返回指针，未匹配时为空。

variant 不是传统意义上不受类型约束的 union：它会管理当前活动对象的生命周期，并维护当前持有的类型信息。

### 5. std::any

`std::any` 可以保存一个可复制构造的任意类型值，并在运行时查询其实际类型。

~~~cpp
std::any value = 42;
if (value.type() == typeid(int)) {
    int n = std::any_cast<int>(value);
}
~~~

与 variant 不同，variant 的备选类型集合在编译期确定；any 则不要求提前列出所有可能类型，但访问时必须知道实际类型。any 的使用会弱化静态类型约束，适合确实需要开放类型集合的场景，不应把它当作默认容器。

### 6. optional、variant、any 如何选择？

| 类型 | 适合表达 | 类型集合 |
|---|---|---|
| optional<T> | 一个 T 可能存在，也可能不存在 | 只有 T 或空状态 |
| variant<Ts...> | 当前是几种已知类型中的一种 | 编译期固定 |
| any | 运行时保存不同类型的值 | 不要求预先列出 |

选择时优先考虑语义是否明确、访问是否安全、是否需要运行时开放类型集合，而不是只看哪种写法最短。

### 7. std::string_view

C++17 的 `std::string_view` 是不拥有字符存储的只读视图，通常可避免创建临时 string。

~~~cpp
void PrintName(std::string_view name)
{
    std::cout << name;
}
~~~

它适合只读函数参数，但需要格外注意生命周期：

~~~cpp
std::string_view Bad()
{
    std::string local = "hello";
    return local; // 错误的设计：返回后 local 被销毁，view 悬空
}
~~~

string_view 不延长底层字符串的生命周期。它也不一定以空字符结尾，因此不能在没有额外保证的情况下把 `data()` 直接交给要求 C 风格 NUL 结尾字符串的接口。

### 8. 文件系统库 filesystem

C++17 引入标准文件系统库 `<filesystem>`，用于路径操作、文件状态查询、目录遍历和文件操作。

~~~cpp
namespace fs = std::filesystem;

fs::path path = "assets/textures/albedo.png";
if (fs::exists(path)) {
    auto size = fs::file_size(path);
}
~~~

文件系统操作可能失败或抛出异常，具体行为与操作和平台环境有关。引擎资源路径处理中，应区分路径拼接、规范化、资源定位和实际文件访问，不能假设所有路径规则在各平台完全相同。

## 十、C++20 常用特性概览

### 1. Concepts

Concepts 用于约束模板参数，让接口更清晰，并改善不满足要求时的错误诊断。

~~~cpp
#include <concepts>

template<std::integral T>
T Add(T a, T b)
{
    return a + b;
}
~~~

Concepts 参与模板约束与重载排序。它不只是给 SFINAE 换了一种语法；旧项目仍可能需要理解 enable_if、void_t 等传统技术。

### 2. Ranges

Ranges 为范围操作提供更统一的接口，与迭代器和视图结合，使部分算法可以直接接受范围。

~~~cpp
#include <algorithm>
#include <ranges>
#include <vector>

std::vector<int> values{3, 1, 2};
std::ranges::sort(values);
~~~

Ranges 包含视图、范围适配器和范围算法等内容。视图通常是轻量的非拥有抽象，但具体类型的所有权与生命周期语义各不相同，不能把所有 range view 都一概当成拥有数据的容器。

### 3. 三路比较运算符 <=>（spaceship）

C++20 引入三路比较运算符 `<=>`，可以表达小于、等于或大于的比较结果，并支持相关比较运算符的生成规则。

~~~cpp
#include <compare>

struct Version {
    int major;
    int minor;
    auto operator<=>(const Version&) const = default;
};
~~~

默认化的三路比较会按成员顺序比较，具体生成哪些比较运算符还受类成员和语言规则约束。它不能自动让所有类型都具有合理比较语义；成员本身必须支持相应比较。

### 4. 指定初始化

C++20 支持对聚合类型使用指定初始化：

~~~cpp
struct WindowConfig {
    int width;
    int height;
    bool fullscreen;
};

WindowConfig config{
    .width = 1280,
    .height = 720,
    .fullscreen = false
};
~~~

C++ 的指定初始化与 C 的设计有区别，使用顺序和聚合类型规则需要符合 C++ 语法要求。不能把它当成适用于所有类、所有构造函数的通用命名参数系统。

### 5. std::span

C++20 的 `std::span<T>` 表示一段连续元素的非拥有视图，可以把数组、vector 等连续存储范围以统一接口传入函数。

~~~cpp
void Process(std::span<const int> values)
{
    for (int value : values) {
        // 只读处理
    }
}
~~~

span 不拥有底层内存，也不会自动延长 vector 或数组的生命周期。底层数据失效后，span 也不能继续安全访问。

与 string_view 相比，string_view 面向字符序列；span 面向连续元素序列，可以表示任意元素类型的范围。

### 6. jthread 与 stop_token

C++20 的 `std::jthread` 是支持自动请求停止并在析构时管理线程生命周期的线程类型。与需要手动 join 的普通 `std::thread` 相比，它能让某些线程管理代码更安全。

~~~cpp
#include <thread>

std::jthread worker([](std::stop_token stopToken) {
    while (!stopToken.stop_requested()) {
        // 执行可协作停止的工作
    }
});
~~~

停止请求是协作式的：线程函数必须检查 stop_token 或通过相应机制响应请求。它不会强行终止正在运行的线程。

### 7. 协程的基本认识

C++20 引入语言级协程支持，包括 `co_await`、`co_yield` 和 `co_return` 等关键字。协程可以暂停并在之后恢复执行，常用于异步任务、生成器和调度框架。

但 C++20 并没有直接提供一个适用于所有场景的统一任务类型或完整异步运行时；实际使用往往依赖库、promise 类型和调度器设计。

## 十一、常见现代 C++ 误区

### 1. std::move 一定会移动吗？

不会。它主要是类型转换，最终由重载决议决定是否调用移动操作。移动后对象仍需满足其类型的有效性要求，但值通常不应在没有契约的情况下被假定为空。

### 2. auto 会让变量变成动态类型吗？

不会。auto 在编译期推导静态类型，变量的类型在编译完成后就已经确定。

### 3. constexpr 函数一定在编译期执行吗？

不一定。constexpr 函数可以用于编译期常量求值，也可能在运行时被调用；consteval 则要求调用满足立即求值约束。

### 4. string_view 比 string 更安全、更快吗？

不能一概而论。string_view 通常避免拥有和复制字符，但不管理生命周期；底层字符串销毁或重分配后，view 可能悬空。只有当不拥有数据的语义合适时，它才是正确选择。

### 5. lambda 捕获引用一定更高效吗？

引用捕获避免复制捕获对象，但增加了对原对象生命周期的依赖。若回调会延迟执行或跨线程保存，引用捕获可能带来悬空引用问题。按值捕获有时反而更安全。

### 6. =default 一定能生成可用函数吗？

不一定。若成员或基类使默认操作无法满足要求，该函数可能被定义为 deleted。=default 的含义是请求编译器生成默认实现，而不是保证该实现必然可用。

### 7. optional 和 variant 是动态分配的容器吗？

不能这样概括。optional 内部管理一个可选对象；variant 管理其备选类型中的一个活动对象。它们不等同于 vector 这样的动态序列容器，是否发生动态分配还取决于所保存类型及具体实现细节。

### 8. noexcept 只是优化提示吗？

不是。它是语言级异常规格。若异常逃出 noexcept 函数，会调用 std::terminate。因此只有在确实保证不抛异常时才应声明 noexcept。

### 9. C++20 的新特性一定能在项目里使用吗？

不一定。除了编译器和标准库实现支持外，还要看项目配置的语言标准、平台工具链和团队兼容性要求。阅读引擎代码时，应先确认工程实际采用的 C++ 标准版本。

## 十二、现代 C++ 高频面试题

### Q1：C++11 引入移动语义是为了解决什么问题？

它允许在适合的场景下转移资源所有权，减少深拷贝带来的分配和复制成本。移动操作需要通过右值引用等机制参与重载决议。

### Q2：std::move 和 std::forward 的区别是什么？

std::move 把表达式转换为右值类别，表达可移动意图；std::forward<T> 根据模板推导结果有条件地保留实参的值类别，主要用于完美转发。

### Q3：为什么移动构造函数经常声明 noexcept？

容器扩容等操作可能根据移动操作是否可能抛异常选择拷贝或移动策略。对确实不抛异常的移动操作声明 noexcept，可以帮助标准库选择更合适的实现路径。

### Q4：auto 和 decltype 的区别是什么？

auto 主要根据初始化表达式按值推导，通常忽略顶层 const 和引用；decltype 根据指定表达式的类型与值类别规则推导，能够保留引用等细节。decltype(x) 与 decltype((x)) 可能不同。

### Q5：为什么优先使用 nullptr？

nullptr 是专门的空指针字面量，类型为 std::nullptr_t；NULL 可能是整数常量 0，在重载决议中可能引发意外行为。

### Q6：enum class 相比 enum 有什么优势？

枚举项有作用域限定，不会隐式转换为整数，能减少名称冲突和意外的整数运算，类型安全性更好。

### Q7：lambda 和函数指针的区别是什么？

lambda 通常生成闭包对象，可以保存捕获状态；无捕获 lambda 可按规则转换为函数指针，而有捕获 lambda 通常不能直接转换为普通函数指针。

### Q8：constexpr 与 const 有什么区别？

const 表示不能通过该名称修改对象；constexpr 对变量要求常量初始化，并用于表达编译期常量求值能力。const 对象不一定是常量表达式。

### Q9：optional、variant、any 的区别是什么？

optional 表示一个类型的值可能存在；variant 表示若干已知类型之一；any 可以在运行时保存不预先列出的可复制构造类型，但类型约束更弱。

### Q10：string_view 有什么风险？

它不拥有字符存储，不延长底层字符串生命周期。若底层对象销毁或存储失效，view 可能悬空；其 data() 也不保证一定以 NUL 结尾。

### Q11：if constexpr 与普通 if 有什么区别？

if constexpr 根据编译期条件丢弃不需要的分支，使模板可以按类型选择不同实现；普通 if 不能避免模板中不适用分支的常规实例化检查。

### Q12：C++20 Concepts 的作用是什么？

Concepts 为模板参数表达约束，提升接口可读性和诊断质量，并参与约束排序与重载决议。它们不能简单视作 SFINAE 的语法别名。

### Q13：span 和 string_view 的区别是什么？

二者都是非拥有视图。string_view 专用于字符序列；span 可以表示各种连续元素的范围。两者都不延长底层存储生命周期。

### Q14：jthread 为什么比 thread 更易管理？

jthread 的析构会按其语义请求停止并管理线程结束过程，减少遗忘 join 的风险。但停止是协作式的，线程函数必须响应停止请求，不能依赖它强制终止线程。
