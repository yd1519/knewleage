# C++ 秋招八股复习文档（一）：C++ 语言基础

**复习范围：** 基本类型、变量、作用域、存储期、指针、引用、const、数组、函数、函数重载、隐式转换、初始化、表达式与运算符优先级。

**标准版本：** 以 C++11/14 为主，必要时补充后续标准的差异。

---

## 一、基本数据类型

### 1. C++ 基本类型有哪些？

常见类型包括：

| 类型类别 | 类型示例 | 说明 |
|---|---|---|
| 布尔类型 | <code>bool</code> | <code>true</code>、<code>false</code> |
| 字符类型 | <code>char</code>、<code>wchar_t</code>、<code>char16_t</code>、<code>char32_t</code> | 字符及字符编码相关 |
| 整数类型 | <code>short</code>、<code>int</code>、<code>long</code>、<code>long long</code> | 表示整数 |
| 浮点类型 | <code>float</code>、<code>double</code>、<code>long double</code> | 表示浮点数 |
| 空类型 | <code>void</code> | 表示没有值或不指定具体类型 |
| 空指针类型 | <code>std::nullptr_t</code> | <code>nullptr</code> 的类型 |

此外，还有派生类型，例如指针、引用、数组、函数类型，以及用户自定义类型，例如 <code>class</code>、<code>struct</code>、<code>enum</code>。

### 2. 各基本类型占多少字节？

不能脱离平台直接给出所有类型的固定大小。

~~~cpp
sizeof(char)
sizeof(short)
sizeof(int)
sizeof(long)
sizeof(long long)
sizeof(float)
sizeof(double)
sizeof(void*)
~~~

常见 64 位平台上，<code>int</code> 通常为 4 字节，指针通常为 8 字节，但具体大小取决于实现。

必须记住的标准保证：

- <code>sizeof(char) == 1</code>。
- <code>sizeof(char) &lt;= sizeof(short) &lt;= sizeof(int) &lt;= sizeof(long) &lt;= sizeof(long long)</code>。
- <code>sizeof</code> 的单位是 C++ 的 byte；一个 byte 至少包含 8 bit。
- <code>sizeof</code> 的返回类型是 <code>std::size_t</code>。

如果需要明确位宽，可以使用 <code>&lt;cstdint&gt;</code> 中的 <code>std::int32_t</code>、<code>std::uint64_t</code> 等类型；其中精确宽度的类型在实现不支持时可以不存在。

### 3. 有符号整数溢出会怎样？

~~~cpp
int x = INT_MAX;
x = x + 1;
~~~

如果运算结果超出 <code>int</code> 的可表示范围，**有符号整数溢出属于未定义行为（Undefined Behavior，UB）**。

不能认为结果必然回绕到 <code>INT_MIN</code>。

对于无符号整数，运算结果按照模 <code>2^N</code> 回绕，其中 <code>N</code> 是该无符号类型的位宽。

### 4. float 和 double 的区别

- <code>float</code> 通常使用 32 位存储。
- <code>double</code> 通常使用 64 位存储。
- <code>double</code> 通常具有更高的精度和范围，但具体由实现决定。

浮点数不能精确表示所有十进制小数。

~~~cpp
double a = 0.1;
double b = 0.2;

std::cout << (a + b == 0.3);
~~~

不能假设结果一定为 <code>true</code>。浮点运算通常需要考虑舍入误差。

### 5. char 是有符号还是无符号？

普通 <code>char</code> 的有符号性由实现决定。

~~~cpp
char c = -1;
~~~

不能假设 <code>char</code> 在所有平台上都是 <code>signed char</code>。

涉及二进制数据、字节操作时，应根据需求明确选择 <code>unsigned char</code>、<code>std::byte</code>（C++17）等类型。

## 二、变量、作用域、生命周期与存储期

### 1. 什么是作用域？

作用域（Scope）决定一个名称在程序的哪些区域内可以被查找和使用。

常见类型包括：

- 块作用域：局部变量。
- 命名空间作用域：命名空间内声明的名称。
- 类作用域：类成员。
- 函数作用域：主要涉及标签等特殊情况。

例如：

~~~cpp
int global = 10;

void foo()
{
    int local = 20;
}
~~~

<code>global</code> 可以在适当的声明可见范围内使用，而 <code>local</code> 只能在其作用域内使用。

### 2. 什么是生命周期？

生命周期（Lifetime）描述对象何时开始存在，以及何时结束。

~~~cpp
void foo()
{
    int x = 10;
} // x 的生命周期结束
~~~

离开作用域后，<code>x</code> 的生命周期结束，不能继续通过原来的地址合法访问这个对象。

### 3. 什么是存储期？

存储期（Storage Duration）描述对象的存储持续时间。C++ 中主要有四类：

| 存储期 | 典型例子 | 通常的生命周期 |
|---|---|---|
| 自动存储期 | 普通局部变量 | 进入相应生命周期后，离开作用域时结束 |
| 静态存储期 | 全局变量、局部 <code>static</code> 变量 | 整个程序运行期间 |
| 线程存储期 | <code>thread_local</code> 变量 | 所属线程的生命周期内 |
| 动态存储期 | <code>new</code> 创建的对象 | 由相应的创建与销毁操作控制 |

注意：存储期、作用域和生命周期是不同概念，不能混为一谈。

### 4. 栈和堆是什么？

常见实现会把普通局部对象放在栈上，把动态分配对象放在堆上。

~~~cpp
void foo()
{
    int a = 10;
    int* p = new int(20);

    delete p;
}
~~~

这里：

- <code>a</code> 是局部对象，通常使用栈帧存储。
- <code>p</code> 是局部指针对象，通常使用栈帧存储。
- <code>new int(20)</code> 创建的对象具有动态存储期。

但栈和堆是常见实现模型，并非 C++ 标准强制规定的完整内存布局。

### 5. 全局变量和局部 static 变量有什么区别？

~~~cpp
int global = 0;

void foo()
{
    static int count = 0;
    ++count;
}
~~~

二者都具有静态存储期。

局部 <code>static</code> 变量的名称作用域仍然限制在函数内部，但其对象不会在每次函数调用时重新创建。

C++11 起，函数内局部静态变量的初始化具有线程安全保证。注意，这并不代表之后对该变量的所有访问自动线程安全。

### 6. 什么是未初始化变量？

~~~cpp
void foo()
{
    int a;
    int b{};
}
~~~

对于这里的自动存储期 <code>int</code>：

- <code>a</code> 默认初始化，没有获得确定的初始值；在 C++11/14 中读取它属于未定义行为。
- <code>b{}</code> 使用值初始化，结果为 <code>0</code>。

不要把未初始化变量的值理解为“内存里原本留下的随机数，所以可以直接读取”。

### 7. 什么是野指针和悬空指针？

~~~cpp
int* p = new int(10);
delete p;
~~~

<code>delete p</code> 后，<code>p</code> 仍然保存原来的地址，但该地址处的原对象已经被销毁。

此时 <code>p</code> 是悬空指针。

~~~cpp
std::cout << *p; // 未定义行为
~~~

将 <code>p</code> 设为 <code>nullptr</code> 可以避免继续通过 <code>p</code> 访问，但不能自动修复其他指向同一对象的悬空指针。

### 8. 内存泄漏是什么？

~~~cpp
void foo()
{
    int* p = new int(10);
}
~~~

函数返回后，局部指针 <code>p</code> 消失，但动态分配的对象没有释放，也没有留下可用于释放它的指针，造成内存泄漏。

现代 C++ 通常优先使用 RAII 和智能指针来管理动态资源。

## 三、指针

### 1. 什么是指针？

指针是一个保存地址值的对象，其类型决定了如何解释所指向的对象，以及如何进行指针运算。

~~~cpp
int a = 10;
int* p = &a;

*p = 20;
~~~

此时 <code>a</code> 的值变为 <code>20</code>。

- <code>&a</code>：取 <code>a</code> 的地址。
- <code>p</code>：指针对象本身。
- <code>*p</code>：通过指针访问所指对象。

### 2. 什么是空指针？

C++11 引入 <code>nullptr</code>，推荐用它表示空指针。

~~~cpp
int* p = nullptr;
~~~

<code>nullptr</code> 的类型为 <code>std::nullptr_t</code>，可以转换为指针类型。

相比之下，<code>NULL</code> 可能被实现为整数常量 <code>0</code>，容易在重载中引发歧义。

~~~cpp
void foo(int);
void foo(int*);

foo(0);       // 调用 foo(int)
foo(nullptr); // 调用 foo(int*)
~~~

### 3. 指针和引用有什么区别？

| 对比项 | 指针 | 引用 |
|---|---|---|
| 语言语义 | 独立的指针对象 | 另一个对象的别名 |
| 初始化 | 可以先不指向对象，但不能在未初始化状态下使用 | 必须初始化 |
| 为空 | 可以是 <code>nullptr</code> | 不能把空引用作为合法的正常状态使用 |
| 重新指向 | 可以 | 不能重新绑定到另一个对象 |
| 访问对象 | 通过 <code>*p</code> | 直接使用引用名称 |
| <code>sizeof</code> | 求指针对象大小 | 求被引用类型的大小 |

引用的实现方式由编译器决定，标准没有规定引用必须实现为指针。

### 4. 什么是指针算术？

~~~cpp
int arr[5] = {1, 2, 3, 4, 5};
int* p = arr;
~~~

<code>p + 1</code> 指向下一个 <code>int</code> 元素，而不是简单地向后移动一个 byte。

若 <code>sizeof(int) == 4</code>，地址通常增加 4 字节。

合法的指针算术主要限于同一数组对象及其末尾之后的位置；不能任意跨越无关对象进行指针算术。

数组末尾之后的指针可以用于比较等有限用途，但不能解引用。

### 5. 什么是多级指针？

~~~cpp
int a = 10;
int* p = &a;
int** pp = &p;
~~~

- <code>p</code> 指向 <code>a</code>。
- <code>pp</code> 指向指针对象 <code>p</code>。
- <code>**pp</code> 访问 <code>a</code>。

多级指针常用于需要通过参数修改指针、动态二维数据结构等场景。

### 6. 什么是 void*？

<code>void*</code> 是通用对象指针类型，可以保存对象的地址。

~~~cpp
int a = 10;
void* p = &a;

int* q = static_cast<int*>(p);
~~~

不能直接通过 <code>void*</code> 解引用，因为 <code>void</code> 不是完整的对象类型，无法确定访问对象的类型和大小。

函数指针和对象指针是不同类别，不能简单地认为它们都能无条件转换成 <code>void*</code>。

### 7. 什么是指针常量与常量指针？

~~~cpp
const int* p1 = &a;
int* const p2 = &a;
const int* const p3 = &a;
~~~

- <code>const int*</code>：不能通过 <code>p1</code> 修改所指对象，但可以改变 <code>p1</code> 的指向。
- <code>int* const</code>：<code>p2</code> 不能改变指向，但可以通过它修改所指对象。
- <code>const int* const</code>：指向不能改变，也不能通过该指针修改对象。

<code>const int*</code> 也可以写作 <code>int const*</code>。

### 8. sizeof(pointer) 为什么和 sizeof(*pointer) 不同？

~~~cpp
int a = 10;
int* p = &a;

sizeof(p);  // 指针对象大小
sizeof(*p); // int 的大小
~~~

在常见 64 位环境中，指针大小通常是 8 字节，而 <code>int</code> 通常是 4 字节。

<code>sizeof(*p)</code> 不会实际读取 <code>*p</code> 的值，因此即使 <code>p</code> 未初始化，也不能据此认为解引用表达式本身被执行了。

## 四、引用

### 1. 什么是引用？

引用是一个已有对象的别名。

~~~cpp
int a = 10;
int& r = a;

r = 20;
~~~

执行后 <code>a == 20</code>。

引用必须在声明时初始化，初始化后不能重新绑定。

### 2. 左值引用和右值引用有什么区别？

~~~cpp
int a = 10;

int& lref = a;
int&& rref = 10;
~~~

- <code>int&</code> 是左值引用，通常绑定到可修改的左值。
- <code>int&&</code> 是右值引用，可以绑定到右值。
- <code>const int&</code> 可以绑定到左值或右值。

右值引用是移动语义和完美转发的重要基础。

### 3. 为什么 const int& r = 10 合法？

~~~cpp
const int& r = 10;
~~~

<code>10</code> 是右值。常量左值引用可以绑定到临时对象，且这里临时对象的生命周期延长至引用的生命周期结束。

但这种生命周期延长有例外：例如函数返回引用时，不会因为调用方用引用接收返回值，就自动延长原本已经结束的临时对象的生命周期。

### 4. 为什么函数参数常用 const T&？

~~~cpp
void foo(const std::string& s);
~~~

对于较大的只读对象，使用 <code>const T&amp;</code> 通常可以避免复制整个对象，同时限制函数通过该引用修改对象。

但不意味着所有类型、所有参数都必须用引用。小型基础类型按值传递通常更简单，所有权和移动语义也会影响参数设计。

### 5. 返回引用有什么风险？

~~~cpp
int& foo()
{
    int x = 10;
    return x;
}
~~~

错误：返回局部变量的引用。

当函数返回时，<code>x</code> 的生命周期结束，调用方获得的引用悬空。

不能返回已经结束生命周期的局部对象的引用或地址。

## 五、数组

### 1. 数组和指针有什么区别？

~~~cpp
int arr[10];
int* p = arr;
~~~

<code>arr</code> 的类型是 <code>int[10]</code>，而 <code>p</code> 的类型是 <code>int*</code>。

在很多表达式中，数组会退化为指向首元素的指针，但数组本身并不是指针。

### 2. sizeof(arr) 和 sizeof(p) 有什么区别？

~~~cpp
int arr[10];
int* p = arr;

sizeof(arr); // 10 * sizeof(int)
sizeof(p);   // 指针对象的大小
~~~

假设 <code>sizeof(int) == 4</code>，且指针大小为 8 字节：

- <code>sizeof(arr) == 40</code>
- <code>sizeof(p) == 8</code>

数组退化为指针并非无条件发生，<code>sizeof</code> 和对数组取地址等情形会保留数组类型。

### 3. 为什么函数参数中的数组会退化？

~~~cpp
void foo(int arr[])
{
    std::cout << sizeof(arr);
}
~~~

函数参数声明中的 <code>int arr[]</code> 会调整为 <code>int* arr</code>。

因此在函数内部，<code>sizeof(arr)</code> 得到的是指针大小，而不是原数组大小。

如果需要数组长度，可以显式传递长度，或使用适合的数组引用参数、容器或 <code>std::array</code>。

### 4. arr 和 &arr 有什么区别？

~~~cpp
int arr[10];
~~~

在大多数表达式中，<code>arr</code> 退化为 <code>int*</code>，指向首元素。

<code>&amp;arr</code> 的类型是 <code>int (*)[10]</code>，即指向整个数组的指针。

两者的起始地址通常相同，但指针算术不同：

- <code>arr + 1</code>：跨过一个 <code>int</code>。
- <code>&amp;arr + 1</code>：跨过整个 <code>int[10]</code> 数组。

### 5. 二维数组如何理解？

~~~cpp
int arr[3][4];
~~~

它是由 3 个元素组成的数组，每个元素本身是 <code>int[4]</code>。

~~~cpp
int (*p)[4] = arr;
~~~

<code>p</code> 是指向包含 4 个 <code>int</code> 的数组的指针。

它不是 <code>int**</code>。二维数组的连续内存布局与指针数组、动态分配的指针表结构并不相同。

## 六、const 与 volatile

### 1. const 有哪些常见用法？

~~~cpp
const int x = 10;
const int* p = &x;
int* const q = &someInt;
~~~

<code>const</code> 限制通过特定声明进行修改的权限。

对于真正声明为 <code>const</code> 的对象，不能通过去除限定符后写入的方式修改它。

### 2. const_cast 是什么？

~~~cpp
const int x = 10;
int* p = const_cast<int*>(&x);
~~~

这段转换本身可以编译，但通过 <code>p</code> 修改 <code>x</code> 会产生未定义行为，因为 <code>x</code> 本身是 const 对象。

如果底层对象原本不是 const，仅仅通过 const 引用或指针访问，那么去除 const 后修改对象在相应条件下可以合法。

<code>const_cast</code> 只用于添加或移除 cv 限定，不负责任意类型转换。

### 3. 什么是 volatile？

~~~cpp
volatile int x;
~~~

<code>volatile</code> 用来表达对对象访问具有特殊可观察语义的需求，常见于某些底层硬件接口等场景。

它不等于原子操作，不保证线程安全，也不能替代 <code>std::atomic</code> 或互斥锁。

## 七、函数

### 1. 值传递、指针传递和引用传递有什么区别？

~~~cpp
void f1(int x);
void f2(int* x);
void f3(int& x);
~~~

- 值传递：函数获得一个独立的参数对象。
- 指针传递：函数获得指针值，可以通过它访问所指对象。
- 引用传递：参数是原对象的别名。

注意，C++ 的参数始终是按值初始化的。所谓“指针传递”和“引用传递”，是指参数类型分别为指针和引用，而不是语言另外存在两种独立的参数传递机制。

### 2. 什么是函数重载？

函数重载允许同一作用域内存在同名但参数列表不同的函数。

~~~cpp
void foo(int);
void foo(double);
void foo(const std::string&);
~~~

编译器根据实参类型、转换规则等进行重载决议。

**不能仅通过返回类型区分普通函数重载。**

~~~cpp
int foo();
double foo(); // 不能仅靠返回类型重载
~~~

### 3. 什么是默认参数？

~~~cpp
void foo(int a, int b = 10);
~~~

调用：

~~~cpp
foo(1);
foo(1, 20);
~~~

分别等效于提供 <code>b = 10</code> 和显式提供 <code>b = 20</code>。

默认参数通常从可见声明处获取，同一作用域中不能在后续声明里重复提供已经指定的默认实参。

### 4. 什么是 inline 函数？

~~~cpp
inline int add(int a, int b)
{
    return a + b;
}
~~~

<code>inline</code> 不保证编译器一定将函数内联展开。

它还涉及跨翻译单元的定义规则：满足相应 ODR 条件的 inline 函数可以在多个翻译单元中定义。

因此不要把 <code>inline</code> 简单理解为“强制展开函数”。

### 5. 返回值优化是什么？

~~~cpp
struct A {};

A foo()
{
    return A{};
}

A a = foo();
~~~

编译器可能通过复制消除避免额外的拷贝或移动。

C++17 起，某些同类型纯右值初始化场景中，复制消除是标准保证的语义；在 C++11/14 中，相关优化通常属于允许但不一定强制的复制消除。

## 八、隐式转换与 explicit

### 1. 什么是隐式类型转换？

当表达式类型与目标类型不同，且语言允许相应转换时，编译器可以自动执行转换。

~~~cpp
double x = 10;
~~~

这里 <code>int</code> 值转换为 <code>double</code>。

常见转换包括：

- 整数提升。
- 算术类型转换。
- 数组到指针转换。
- 派生类到基类的转换。
- 用户定义转换。

### 2. 什么是窄化转换？

窄化转换可能导致信息损失。

~~~cpp
int x = 3.14;
~~~

通常得到 <code>3</code>。

列表初始化会禁止许多窄化转换：

~~~cpp
int x{3.14}; // 编译错误
~~~

列表初始化有助于在编译阶段发现潜在的精度损失。

### 3. 什么是 explicit？

~~~cpp
struct A {
    explicit A(int x) {}
};

A a(10);
A b{10};

// A c = 10; // 编译错误
~~~

<code>explicit</code> 用来限制构造函数或转换函数参与隐式转换。

它在接口设计中非常重要，可以避免意外的类型转换。

### 4. 什么是隐式转换导致的重载歧义？

~~~cpp
void foo(long);
void foo(double);

foo(10);
~~~

对于整数实参 <code>10</code>，从 <code>int</code> 到 <code>long</code> 与从 <code>int</code> 到 <code>double</code> 都需要标准转换，可能导致无法确定唯一的最佳匹配，因而出现重载歧义。

重载决议需要比较候选函数的转换序列，不能只记“编译器选最像的那个”。

## 九、初始化方式

### 1. 默认初始化、值初始化与列表初始化

~~~cpp
int a;     // 默认初始化：值不确定
int b{};   // 值初始化：0
int c();   // 函数声明，不是创建 int 变量
int d = 0; // 拷贝初始化
int e(10); // 直接初始化
int f{10}; // 列表初始化
~~~

特别注意：

~~~cpp
int c();
~~~

在块作用域中声明的是一个返回 <code>int</code> 的函数，而不是值初始化为 0 的变量。

### 2. 类对象的初始化

~~~cpp
struct A {
    int x;
    A() : x(10) {}
};

A a;
~~~

构造函数通过成员初始化列表初始化 <code>x</code>。

类对象的初始化行为还受构造函数、基类和成员类型影响，不能完全套用基础类型的初始化规则。

### 3. 成员初始化顺序

~~~cpp
struct A {
    int x;
    int y;

    A() : y(2), x(y + 1) {}
};
~~~

成员的实际初始化顺序由它们在类定义中的声明顺序决定，而不是初始化列表中的书写顺序。

上面的代码中 <code>x</code> 先初始化，<code>y</code> 后初始化；因此 <code>x(y + 1)</code> 读取尚未初始化的 <code>y</code>，这是错误写法。

应该按声明顺序理解初始化，并避免在成员初始化表达式中读取尚未初始化的成员。

### 4. 为什么推荐列表初始化？

~~~cpp
int x{10};
std::vector<int> v{1, 2, 3};
~~~

列表初始化可以防止许多窄化转换。

但它对 <code>std::initializer_list</code> 有特殊的重载优先规则，因此对于容器，花括号不总是等价于圆括号。

## 十、表达式与运算符优先级

### 1. 优先级与结合性有什么区别？

优先级决定不同运算符如何分组，结合性决定同一优先级的运算符如何分组。

~~~cpp
int x = 2 + 3 * 4;
~~~

先乘后加，结果为 <code>14</code>。

~~~cpp
int a = 10 - 3 - 2;
~~~

减法是左结合，等价于 <code>(10 - 3) - 2</code>，结果为 <code>5</code>。

赋值运算符是右结合：

~~~cpp
a = b = 10;
~~~

等价于 <code>a = (b = 10)</code>。

### 2. 常见优先级陷阱

~~~cpp
*p++;
~~~

等价于：

~~~cpp
*(p++);
~~~

先使用当前指针解引用，再将指针递增。

而：

~~~cpp
(*p)++;
~~~

递增的是所指对象的值。

再看：

~~~cpp
if (x & mask == 0) {}
~~~

由于相等运算符的优先级高于按位与，它会被解析为：

~~~cpp
if (x & (mask == 0)) {}
~~~

通常不是期望的含义。应写成：

~~~cpp
if ((x & mask) == 0) {}
~~~

### 3. && 和 & 的区别

- <code>&amp;&amp;</code>：逻辑与，具有短路求值。
- <code>&amp;</code>：整数的按位与，也可以是取地址运算符。

~~~cpp
if (p != nullptr && *p > 0) {}
~~~

当 <code>p == nullptr</code> 时，右侧不会被求值。

这正是短路求值在防止非法解引用方面的典型用途。

### 4. i++ 与 ++i

~~~cpp
int i = 10;
int a = i++;
~~~

<code>a</code> 得到原来的值 <code>10</code>，之后 <code>i</code> 变为 <code>11</code>。

~~~cpp
int j = 10;
int b = ++j;
~~~

<code>j</code> 先递增，<code>b</code> 得到 <code>11</code>。

对于基础类型，优先选择符合语义且更清晰的表达式；不要在复杂表达式中叠加多个副作用。

### 5. 求值顺序不等于优先级

C++11/14 中：

~~~cpp
int i = 0;
int x = i++ + i++;
~~~

对同一标量对象进行未被正确排序的多次修改，属于未定义行为。

不要依靠运算符优先级推断所有操作的实际执行顺序。

编写表达式时，应该将有副作用的操作拆开，让求值顺序清晰明确。

## 十一、未定义行为、未指定行为与实现定义行为

这是面试中非常常见的概念题。

| 概念 | 含义 |
|---|---|
| 未定义行为（UB） | 标准不要求实现提供特定行为 |
| 未指定行为 | 标准允许若干种行为，但不要求记录具体选择 |
| 实现定义行为 | 标准允许不同实现选择，但实现需要记录其选择 |

典型例子：

- 有符号整数溢出：未定义行为。
- 解引用悬空指针：未定义行为。
- 普通 <code>char</code> 的有符号性：实现定义。
- 未指定的求值顺序：需要结合具体表达式与语言版本判断，不能一概当成 UB。

面试时，不要把所有“不确定结果”都叫作未定义行为。

## 十二、第一阶段高频八股速记

**Q：指针和引用有什么区别？**

A：指针是独立对象，保存地址值；引用是已有对象的别名，必须初始化且不能重新绑定。

**Q：引用底层就是指针吗？**

A：不能这样严格表述。引用的实现方式由编译器决定，标准没有要求引用必须通过指针实现。

**Q：数组和指针有什么区别？**

A：数组是包含多个元素的对象，指针是保存地址的对象。数组在许多表达式中会退化为指向首元素的指针，但两者类型不同。

**Q：sizeof(arr) 为什么和 sizeof(p) 不同？**

A：数组在 <code>sizeof</code> 中不退化，得到整个数组的大小；指针则得到指针对象的大小。

**Q：const int* 和 int* const 有什么区别？**

A：前者限制通过指针修改所指对象，后者限制指针自身重新指向。

**Q：什么是悬空指针？**

A：指针保存的地址不再对应一个可合法访问的原对象，例如对象生命周期结束或动态存储被释放之后。

**Q：什么是隐式转换？**

A：表达式在符合语言转换规则时，可以由编译器自动转换到目标类型。

**Q：explicit 有什么作用？**

A：限制构造函数或转换函数参与隐式转换，减少意外类型转换。

**Q：默认初始化和值初始化有什么区别？**

A：对于未带初始化器的自动存储期基础类型，默认初始化不会提供确定初值；值初始化则可能将其初始化为零。具体行为需要结合类型判断。

**Q：运算符优先级与求值顺序有什么区别？**

A：优先级和结合性决定表达式分组，不等于所有操作的实际执行顺序。
