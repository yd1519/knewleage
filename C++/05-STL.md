## 一、STL 是什么？

### 1. STL 的基本组成

STL（Standard Template Library，标准模板库）是 C++ 标准库中一套基于模板的通用组件体系。学习时通常将其归纳为：

- **容器（Containers）：** 管理和组织对象，例如 `vector`、`map`、`unordered_map`。
- **迭代器（Iterators）：** 提供遍历或访问容器元素的统一抽象。
- **算法（Algorithms）：** 通过迭代器操作一段元素范围，例如 `sort`、`find`、`reverse`。
- **函数对象（Function Objects）：** 可像函数一样调用的对象，用于定制比较、转换或其他行为。
- **适配器（Adapters）：** 基于已有组件提供另一种接口，例如 `stack`、`queue`、`priority_queue`。
- **分配器（Allocators）：** 抽象容器的内存分配策略。

“容器、迭代器、算法、仿函数”是常见的面试概括，但并不是 STL 的全部内容。

### 2. STL 为什么大量使用模板？

模板让容器和算法可以服务于不同类型，同时尽可能在编译期完成类型检查和泛化。

~~~cpp
std::vector<int> numbers{3, 1, 2};
std::sort(numbers.begin(), numbers.end());
~~~

`vector` 管理元素，迭代器表示元素范围，`sort` 只依赖迭代器所提供的能力，而不需要知道容器内部如何组织内存。

这种设计让算法和容器能够在一定程度上独立组合。需要注意，不是每种算法都能用于每种容器：算法对迭代器类别有要求。

### 3. 容器成员函数与通用算法有什么区别？

容器成员函数通常了解自身数据结构，可以利用内部结构完成更合适的操作；通用算法则通常只通过迭代器访问元素。

例如：

- `std::sort(v.begin(), v.end())` 可用于 `vector` 等支持随机访问迭代器的范围。
- `std::list` 不提供随机访问迭代器，不能直接使用通用的 `std::sort`；它提供自己的成员函数 `list::sort()`。
- `map` 的元素按键组织，插入和查找应该使用容器成员函数，而不是期待通用算法理解其树结构。

### 4. 头文件和命名空间

常见 STL 组件需要包含对应头文件：

~~~cpp
#include <vector>
#include <string>
#include <map>
#include <unordered_map>
#include <set>
#include <algorithm>
#include <iterator>
#include <queue>
#include <stack>
#include <memory>
#include <functional>
~~~

标准库组件通常位于 `std` 命名空间。工程代码一般避免在公共头文件或大型代码文件中无条件使用 `using namespace std;`，以免名称冲突。

## 二、容器总览与选择思路

### 1. 常见容器分类

| 类别 | 容器 | 典型特点 |
|---|---|---|
| 序列容器 | `vector` | 连续存储，随机访问快，尾部追加高效 |
| 序列容器 | `deque` | 支持两端高效插入删除，支持随机访问 |
| 序列容器 | `list` | 双向链表，已知位置插入删除方便，不支持随机访问 |
| 序列容器 | `forward_list` | 单向链表，结构较轻，仅支持单向遍历 |
| 序列容器 | `array` | 固定大小的连续序列，大小是类型的一部分 |
| 序列容器 | `string` | 连续存储的字符序列，提供字符串操作 |
| 有序关联容器 | `set / multiset` | 按比较规则有序组织键 |
| 有序关联容器 | `map / multimap` | 有序键值结构 |
| 无序关联容器 | `unordered_set` | 基于哈希的唯一键集合 |
| 无序关联容器 | `unordered_map` | 基于哈希的键值结构 |
| 容器适配器 | `stack` | 后进先出接口 |
| 容器适配器 | `queue` | 先进先出接口 |
| 容器适配器 | `priority_queue` | 优先级队列，默认堆顶为最大元素 |

### 2. 选容器时应该考虑什么？

不要只背“哪个容器快”，应先明确访问模式：

1. 是否需要按下标随机访问？
2. 是否频繁在序列中间插入或删除？
3. 是否需要保持元素顺序？
4. 是否需要根据键查找、范围查询或有序遍历？
5. 是否只需要近似常数时间的哈希查找？
6. 是否需要稳定的迭代器或元素引用？
7. 内存局部性、分配次数和额外内存是否重要？
8. 元素类型的移动、复制和析构成本如何？

对性能敏感的代码，复杂度只是起点；缓存局部性、分配器行为、数据规模和实际访问模式也会影响结果。

## 三、vector

### 1. vector 的底层结构

`std::vector` 是动态数组，元素在逻辑上连续存储。它可以通过下标或随机访问迭代器快速访问元素。

~~~cpp
std::vector<int> v{10, 20, 30};
int x = v[1]; // 20
~~~

连续存储带来良好的缓存局部性，也让 `vector` 能与需要连续元素范围的接口配合。动态数组扩容时，可能需要分配新存储空间并移动或复制已有元素。

### 2. size 和 capacity 的区别

- `size()`：当前实际包含的元素数量。
- `capacity()`：在不重新分配存储空间的情况下，最多可以容纳的元素数量。

~~~cpp
std::vector<int> v;
v.reserve(100);
~~~

这通常会让 `capacity()` 至少达到 100，但 `size()` 仍然是 0。仅仅调用 `reserve` 不会构造 100 个元素。

~~~cpp
v.resize(10);
~~~

`resize(10)` 会让元素数量变成 10；如果原来不足 10，就会新增元素并按相应规则初始化，如果原来超过 10，就会销毁多出的元素。

### 3. reserve 和 resize 的区别

| 操作 | 主要影响 | 是否改变 size |
|---|---|---|
| `reserve(n)` | 请求至少容纳 n 个元素的容量 | 不改变 |
| `resize(n)` | 改变实际元素数量 | 改变 |
| `shrink_to_fit()` | 请求减少未使用容量 | 不保证一定收缩 |

`reserve` 通常用于提前减少追加元素时的重复分配；`resize` 用于真正调整序列长度。

不要把 `capacity()` 以外的未构造存储当作已经存在的元素使用。

### 4. vector 尾部追加的复杂度

`push_back` 和 `emplace_back` 的尾部追加在通常分析中具有摊还常数时间复杂度。

当容量不足时，容器可能需要重新分配存储空间，并移动或复制已有元素，因此某一次追加可能是线性时间。

“摊还常数”不是说每次追加都严格为 O(1)，而是对一系列操作的平均成本进行分析。

### 5. push_back 与 emplace_back 的区别

~~~cpp
struct Item {
    Item(int, double) {}
};

std::vector<Item> v;
v.push_back(Item(1, 2.0));
v.emplace_back(1, 2.0);
~~~

- `push_back` 接收一个已有元素的左值或右值（受对应重载约束）。
- `emplace_back` 将参数转发给元素构造函数，尝试在容器尾部直接构造元素。

`emplace_back` 在某些场景可避免先创建临时对象，但不保证所有情况下都比 `push_back` 更快。容器扩容时仍可能移动或复制已有元素。

### 6. vector 中间插入和删除

在中间插入或删除元素时，通常需要移动或赋值一部分后续元素，因此复杂度通常为线性。

~~~cpp
std::vector<int> v{1, 2, 3, 4};
v.insert(v.begin() + 1, 99);
v.erase(v.begin() + 2);
~~~

对于频繁中间插入删除的场景，应该比较其他容器或改用批量整理、索引标记等设计，而不是默认 vector 一定合适。

### 7. vector 的迭代器失效

这是 STL 面试高频内容。需要按操作分别判断：

- **发生重新分配：** 原有元素的指针、引用、迭代器都会失效。
- **尾部插入且未重新分配：** 通常已有元素的引用和迭代器仍有效，但旧的 end 迭代器失效。
- **中间插入且未重新分配：** 插入点及其后的迭代器、引用通常失效；之前的仍有效。
- **erase：** 被删除元素及其后的迭代器、引用失效；之前的仍有效。
- **clear：** 所有元素的引用、指针和迭代器失效，容器变空。

这里的规则以标准容器行为为准；具体操作的前置条件和边界情况仍应查阅对应标准说明。

### 8. 如何安全地遍历并删除 vector 元素？

错误做法是删除元素后仍使用已经失效的迭代器。

推荐的循环形式：

~~~cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (*it < 0) {
        it = v.erase(it);
    } else {
        ++it;
    }
}
~~~

`erase` 会返回删除位置之后的有效迭代器，循环据此继续。

若是批量删除满足条件的元素，也可以考虑后文的 erase-remove 惯用法。

### 9. vector<bool> 有什么特殊之处？

`std::vector<bool>` 是标准库为布尔值提供的特殊化形式，常用位压缩方式节省空间。

它的元素访问可能返回代理对象，而不是真正的 `bool&`。因此：

- 不应假设它与普通 `vector<T>` 的引用行为完全相同。
- 不能把它简单当成连续的 `bool` 数组。
- 若需要普通布尔对象的引用语义，应考虑其他表示方式。

### 10. vector 的常见面试结论

- 随机访问：O(1)。
- 尾部追加：摊还 O(1)，单次扩容可能 O(n)。
- 中间插入和删除：通常 O(n)。
- 连续存储，缓存局部性较好。
- 扩容可能使所有元素地址失效。
- `reserve` 改容量，不改变元素数量；`resize` 改元素数量。

## 四、string 与 array

### 1. std::string 的本质

`std::string` 通常是 `std::basic_string<char>` 的别名，提供字符序列的存储与操作。

~~~cpp
std::string s = "hello";
s += " world";
auto part = s.substr(0, 5);
~~~

它支持长度查询、拼接、查找、截取、比较等操作，并像其他标准容器一样管理自身资源。

### 2. string 的常见接口

- `size()` / `length()`：返回字符数量，二者等价。
- `empty()`：判断是否为空。
- `substr(pos, count)`：返回子串。
- `find(value)`：查找子串或字符，找不到返回 `std::string::npos`。
- `compare()`：按字符串比较规则比较。
- `c_str()`：返回以空字符结尾的字符指针。
- `data()`：访问底层字符数据；具体保证与标准版本有关。

注意，`substr` 通常会生成一个新的字符串对象，而不是返回原字符串的视图。若只需要非拥有的字符串视图，可了解 C++17 的 `std::string_view`。

### 3. c_str() 返回的指针需要注意什么？

`c_str()` 返回指向字符串内部字符存储的指针。对字符串执行可能使存储重新分配或字符序列变化的操作后，之前保存的指针可能失效或不再代表期望内容。

不要长期缓存这个指针并假设字符串之后如何修改都不会影响它。调用外部 C API 时，也要确认该 API 是否会在调用返回后继续保存指针。

### 4. 字符串的 size 是字节数吗？

对于 `std::string`，元素类型是 `char`，`size()` 返回 char 元素的数量，通常对应存储字节数，但它不等于 Unicode 字符数量或用户感知的字素数量。

UTF-8 中一个 Unicode 码点可能由多个字节表示。因此，对 UTF-8 字符串使用 `size()` 不能直接得到“字符个数”。

### 5. 什么是 std::array？

`std::array<T, N>` 是固定大小的序列容器，大小是类型的一部分，元素连续存储。

~~~cpp
std::array<int, 3> values{1, 2, 3};
~~~

它比原生数组更符合标准容器接口，可以使用 `size()`、迭代器、范围 for 和标准算法；但它不能像 vector 一样动态改变元素数量。

## 五、deque、list 与 forward_list

### 1. deque 的特点

`std::deque`（双端队列）支持随机访问，并提供两端插入和删除操作。

- 在两端插入或删除通常具有常数时间复杂度。
- 支持下标随机访问。
- 不保证所有元素都位于一块连续内存中。
- 其迭代器失效规则与 vector 不同。

不要因为 deque 支持下标访问，就认为它一定是连续数组。

### 2. vector 与 deque 如何选择？

| 需求 | 常见选择 | 原因 |
|---|---|---|
| 需要连续存储与良好缓存局部性 | vector | 元素连续 |
| 频繁在尾部追加，通常不要求头部高效操作 | vector | 常见默认选择 |
| 频繁在两端插入删除 | deque | 两端操作适合 |
| 需要随机访问但不要求连续内存 | deque 或 vector | 结合实际访问模式 |
| 需要元素稳定性或频繁按位置插入删除 | 进一步评估 list 等结构 | 但要考虑缓存和额外分配成本 |

即使需要头部插入，也不应仅凭复杂度断定 deque 在所有实际负载下都更快；应结合访问模式和性能测试。

### 3. list 的底层结构与特点

`std::list` 通常采用双向链表结构。每个节点保存元素以及前后链接。

优势：

- 已经获得有效迭代器后，在相应位置插入或删除节点通常为 O(1)。
- 插入、删除其他节点一般不会使已有元素迭代器和引用失效（被删除元素本身除外）。
- 支持节点拼接等专门操作。

不足：

- 不支持随机访问，按位置前进需要逐个遍历。
- 节点通常有额外指针开销。
- 节点分散，缓存局部性通常不如连续容器。
- 每个节点的内存管理可能带来额外成本。

### 4. list::sort 与 std::sort 的区别

`std::sort` 要求随机访问迭代器，不能直接用于 `std::list`。

~~~cpp
std::list<int> values{3, 1, 2};
values.sort();
~~~

`list::sort()` 是链表自己的成员算法，会按顺序整理节点，不要求随机访问迭代器。标准保证其稳定排序语义。

### 5. forward_list 是什么？

`std::forward_list` 是单向链表，只能沿一个方向遍历。它不提供普通的 `size()` 成员函数，这是为了让实现保持轻量的一种设计选择。

它提供以“给定位置之后”为中心的操作，例如 `insert_after` 和 `erase_after`。

适用于只需要单向遍历、希望使用链表结构且在意结构开销的特定场景，但并非所有链表场景都应默认使用它。

## 六、map、set 与有序关联容器

### 1. map 和 set 的基本特点

`std::map` 与 `std::set` 是有序关联容器，按比较器定义的顺序组织元素。常见实现采用平衡搜索树，例如红黑树，但标准主要规定语义与复杂度，不要求特定树实现。

- `map` 保存键值对，键唯一。
- `set` 保存键，元素唯一。
- `multimap` 允许多个等价键对应不同元素。
- `multiset` 允许多个等价元素。

### 2. map 的基本用法

~~~cpp
std::map<std::string, int> score;
score["Alice"] = 100;
score.insert({"Bob", 90});

auto it = score.find("Alice");
if (it != score.end()) {
    std::cout << it->second;
}
~~~

`map` 的元素类型是类似 `std::pair<const Key, T>` 的键值结构。键部分是 const，不能通过迭代器直接修改键值，否则会破坏有序容器的排序不变量。

### 3. map 的 operator[] 有什么特点？

~~~cpp
std::map<std::string, int> score;
int x = score["Unknown"];
~~~

对于不存在的键，`operator[]` 会插入一个对应键，并对 mapped value 进行值初始化，因此这里会创建一个值为 0 的 `int` 元素。

所以，若只是想查询是否存在，不应随意使用 `operator[]`，以免无意中插入元素。

可使用：

~~~cpp
auto it = score.find("Unknown");
if (it != score.end()) {
    // 找到了
}
~~~

也可以使用 `count`、`contains`（C++20）等接口，视标准版本和需求而定。

### 4. insert、emplace 与 try_emplace

- `insert` 插入给定值。
- `emplace` 尝试在容器中就地构造元素。
- `try_emplace`（C++17）在键不存在时才构造 mapped value，适合键值映射场景。

~~~cpp
std::map<int, std::string> table;
table.try_emplace(1, "hello");
~~~

`emplace` 并不保证所有参数在键冲突时都完全不进行构造相关的求值；若需要避免不必要的 mapped value 构造，可评估 `try_emplace`。

### 5. map 的复杂度

有序关联容器的查找、插入和删除通常为 O(log n) 复杂度。按键查找可以利用有序结构，范围查询与按顺序遍历也比较自然。

插入或删除可能使相应元素迭代器失效，但不会像 vector 扩容那样让所有其他元素迭代器统一失效。对标准 map/set 来说，插入通常不使已有迭代器失效；删除只使指向被删除元素的迭代器失效。

### 6. set 中的元素可以修改吗？

通常不能通过 set 迭代器修改元素，因为元素值本身参与排序。修改它可能破坏容器的有序结构。

若确实需要修改某个键，可以先取出或复制所需信息，移除旧元素，再插入新键。C++17 还提供节点句柄接口，允许在符合规则的情况下提取节点并修改键，再重新插入。

### 7. 自定义 map/set 比较器

关联容器通过比较器决定元素顺序和键的等价关系。

~~~cpp
struct ByLength {
    bool operator()(const std::string& a,
                    const std::string& b) const
    {
        return a.size() < b.size();
    }
};

std::set<std::string, ByLength> words;
~~~

这里比较器只比较长度，因此长度相同的字符串会被该排序关系视为等价键；set 可能只保留其中一个。

比较器必须满足严格弱序（strict weak ordering）要求。不要使用前后矛盾或不稳定的比较规则。

## 七、unordered_map 与无序关联容器

### 1. unordered_map 的基本特点

`std::unordered_map` 是基于哈希的键值容器，通常采用哈希表实现。

- 平均情况下，查找、插入和删除为 O(1)。
- 最坏情况下可能退化到 O(n)。
- 不按键排序。
- 需要键类型具有合适的哈希函数和相等比较。
- rehash 可能使迭代器失效。

~~~cpp
std::unordered_map<std::string, int> counts;
++counts["apple"];
++counts["apple"];
~~~

### 2. 哈希表基本原理

哈希函数将键映射到一个哈希值，容器再根据哈希值确定桶或其他内部位置。不同键可能产生相同哈希值，因此需要冲突处理机制。

常见冲突处理思路包括链式结构和开放寻址等。标准不强制 unordered 容器必须采用其中某一种具体实现。

### 3. 哈希冲突是什么？

不同键得到相同哈希值或映射到同一桶时，就会发生冲突。容器必须继续比较键，才能判断它们是否相等。

哈希函数的目标是分布合理、计算开销可接受；它不要求不同键永远得到不同哈希值。

### 4. unordered_map 的负载因子

负载因子通常定义为元素数量与桶数量的比值，可通过 `load_factor()` 查看。

`max_load_factor()` 用于读取或设置最大负载因子。插入元素后，如果负载因子超过实现所采用的增长阈值，容器可能进行 rehash。

~~~cpp
std::unordered_map<int, int> table;
table.reserve(1000);
~~~

`reserve` 可用于为预计元素数量预留足够的桶空间，减少后续 rehash 的可能性，但不代表之后任何插入都绝对不会发生重哈希。

### 5. rehash 会导致什么？

rehash 会重新组织桶结构，可能使所有迭代器失效。对于标准 unordered 关联容器，指向元素的引用和指针通常仍保持有效；但删除相应元素当然会使其自身的引用、指针和迭代器失效。

在依赖迭代器有效性的循环中，不能忽略插入是否触发 rehash。

### 6. unordered_map 与 map 如何选择？

| 需求 | 常见选择 |
|---|---|
| 平均快速按键查找，不要求顺序 | unordered_map |
| 需要按键排序、范围查询或有序遍历 | map |
| 需要较稳定的对数复杂度上界 | map |
| 键的哈希函数不易设计或不可接受 | map 或其他结构 |
| 内存占用、缓存行为敏感 | 需要基于实际负载测试 |

不要简单地说 unordered_map 永远比 map 快。数据量、哈希质量、键类型、负载因子、内存分配和访问模式都会影响性能。

### 7. 自定义 unordered_map 的键类型

自定义键类型通常需要提供：

- 合适的哈希函数。
- 相等比较函数。

~~~cpp
struct Point {
    int x;
    int y;

    bool operator==(const Point& other) const
    {
        return x == other.x && y == other.y;
    }
};
~~~

之后可为 Point 提供自定义 hash 函数对象，并将其作为 unordered_map 的模板参数。

核心要求是：相等的键必须得到相同哈希值；如果相等比较认为两个键相等，哈希函数就不能把它们映射成不同的哈希值。

## 八、stack、queue 与 priority_queue

### 1. 什么是容器适配器？

容器适配器不是独立的底层容器实现，而是在底层容器之上提供受限的接口。

### 2. stack：后进先出

`std::stack`（LIFO）提供 `push`、`pop`、`top`、`empty`、`size` 等接口。

~~~cpp
std::stack<int> s;
s.push(1);
s.push(2);
int top = s.top(); // 2
s.pop();           // 删除栈顶，不返回元素
~~~

注意，`pop()` 通常只负责删除栈顶，不返回被删除的值。需要取值时应先读取 `top()`，再调用 `pop()`。

### 3. queue：先进先出

`std::queue`（FIFO）提供 `push`、`pop`、`front`、`back` 等接口。

~~~cpp
std::queue<int> q;
q.push(1);
q.push(2);
int first = q.front(); // 1
q.pop();
~~~

同样，`pop()` 不返回被删除的元素。

### 4. priority_queue：优先级队列

默认情况下，`std::priority_queue` 让最大元素位于堆顶。

~~~cpp
std::priority_queue<int> pq;
pq.push(3);
pq.push(10);
pq.push(5);
int top = pq.top(); // 10
~~~

常见操作复杂度：

- 读取堆顶：O(1)。
- 插入：O(log n)。
- 删除堆顶：O(log n)。

默认是最大堆。如果要构造最小堆，可以使用合适的比较器，例如：

~~~cpp
std::priority_queue<int,
                    std::vector<int>,
                    std::greater<int>> minHeap;
~~~

比较器语义容易让人困惑，面试中应通过一个小例子确认堆顶到底是最大值还是最小值。

## 九、迭代器

### 1. 迭代器是什么？

迭代器是访问元素范围的抽象接口，外观上类似指针，但其具体实现可以是普通指针、类对象或代理对象。

~~~cpp
std::vector<int> v{1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it) {
    std::cout << *it;
}
~~~

迭代器让算法可以在不直接依赖容器内部布局的情况下遍历元素。

### 2. 常见迭代器类别

| 类别 | 能力 | 典型例子 |
|---|---|---|
| 输入迭代器 | 单向读取，满足输入迭代要求 | 某些输入流迭代器 |
| 输出迭代器 | 单向写入，满足输出迭代要求 | 某些输出迭代器 |
| 前向迭代器 | 多次向前遍历 | forward_list 迭代器 |
| 双向迭代器 | 向前、向后遍历 | list、map 的迭代器 |
| 随机访问迭代器 | 支持常数时间跳跃和距离计算 | vector、deque 迭代器 |
| 连续迭代器 | 随机访问，并保证所指元素连续存储 | vector 等满足要求的迭代器 |

C++20 进一步规范了连续迭代器概念。旧标准面试通常重点掌握输入、输出、前向、双向和随机访问五类。

### 3. 为什么 std::sort 不能直接排序 list？

通用 `std::sort` 需要随机访问迭代器，才能高效执行分区等操作。

`list` 只提供双向迭代器，因此不能满足 `std::sort` 的要求。应使用 `list::sort()`，或者把元素复制到支持随机访问的容器中再排序。

### 4. begin 与 end 的区别

`begin()` 指向第一个元素；`end()` 指向最后一个元素之后的位置，是一个尾后迭代器。

尾后迭代器不能解引用。空容器中 `begin() == end()`。

标准算法通常处理半开区间 `[first, last)`，即包含 first 指向的元素，不包含 last。

### 5. const_iterator 与 iterator

- `iterator` 通常允许通过迭代器修改元素（受容器元素类型和接口约束）。
- `const_iterator` 不允许通过该迭代器修改元素。

~~~cpp
std::vector<int> v{1, 2, 3};

auto it = v.begin();
*it = 10;

auto cit = v.cbegin();
// *cit = 20; // 错误：不能通过 const_iterator 修改元素
~~~

`const_iterator` 不等于“迭代器变量自身是 const”。前者限制通过迭代器访问元素的修改能力；后者只是迭代器对象本身不能重新赋值。

### 6. 反向迭代器

许多容器提供 `rbegin()` 和 `rend()` 用于反向遍历。

~~~cpp
std::vector<int> v{1, 2, 3};
for (auto it = v.rbegin(); it != v.rend(); ++it) {
    std::cout << *it;
}
~~~

反向迭代器的递增操作会向底层序列的反方向移动。其内部基迭代器通常指向所表示元素的后一位置，因此 `base()` 的结果并不直接等于反向迭代器当前解引用的元素位置。

### 7. 迭代器失效的通用原则

不要只背一张“所有容器统一规则”的表，因为容器和操作差别很大。核心思路是：

- vector 扩容可能让所有元素地址变化。
- deque 的两端操作可能对迭代器有特殊失效规则。
- list 插入通常不影响其他节点迭代器，删除会使被删节点的迭代器失效。
- map/set 插入通常不使已有迭代器失效，删除只使被删元素的迭代器失效。
- unordered 容器 rehash 会使迭代器失效，但元素引用和指针通常仍有效。
- erase 返回值应按对应容器的接口规则使用。

遇到面试题时，先明确容器、操作、是否发生重新分配或 rehash，再判断失效范围。

## 十、标准算法

### 1. 算法为什么接受迭代器？

通用算法通常通过一对迭代器指定操作范围，使它能够用于不同容器。

~~~cpp
std::vector<int> v{4, 2, 3, 1};
std::sort(v.begin(), v.end());
~~~

这里的 `sort` 不需要知道 vector 的容量或内部管理方式，只需要范围提供它要求的迭代器能力。

### 2. 常见算法

| 算法 | 用途 | 常见复杂度/要求 |
|---|---|---|
| `sort` | 排序 | O(n log n) 比较复杂度量级，需随机访问迭代器 |
| `stable_sort` | 稳定排序 | 通常 O(n log n)，额外内存不足时可能更高 |
| `find` | 查找指定值 | O(n) |
| `count` | 统计相等元素数量 | O(n) |
| `reverse` | 反转范围 | O(n)，要求双向迭代器 |
| `unique` | 移除相邻重复元素的逻辑重复项 | 线性量级，需要前向迭代器 |
| `remove` | 将不符合条件的元素移到逻辑新尾之后 | 线性量级，需要前向迭代器 |
| `lower_bound` | 查找不小于目标值的第一个位置 | 有序范围上对数次比较 |
| `upper_bound` | 查找大于目标值的第一个位置 | 有序范围上对数次比较 |
| `binary_search` | 判断有序范围是否包含目标值 | 对数次比较量级 |
| `accumulate` | 累加范围元素 | O(n)，在 `<numeric>` 中 |

复杂度还可能依赖迭代器类别：例如在非随机访问迭代器上，`lower_bound` 的比较次数可以是对数级，但迭代器移动次数可能是线性级。

### 3. sort 的使用条件与稳定性

~~~cpp
std::sort(v.begin(), v.end());
~~~

`std::sort` 要求随机访问迭代器，并且排序所用比较关系应满足严格弱序。它不是稳定排序：相等元素的相对顺序不保证保持。

如果必须保留相等元素的原有相对顺序，应考虑 `std::stable_sort`。

### 4. 自定义比较器

~~~cpp
std::sort(v.begin(), v.end(),
          [](int a, int b) {
              return a > b;
          });
~~~

这个比较器让元素按降序排列。比较器返回 true 的含义是：按排序关系，a 应该排在 b 前面。

不要把比较器写成 `a >= b`。严格弱序要求元素不能被视为严格地小于自身；用大于等于会破坏该要求，并导致未定义行为。

### 5. sort 与 map/set 的比较规则

`sort` 需要比较器为元素定义满足严格弱序的排序关系。map/set 的比较器也用于确定键的有序关系与等价关系。

但二者的目标并不完全一样：

- `sort` 对一个范围进行排序。
- `map/set` 使用比较关系维护容器结构，并据此定义键的等价关系。

对于关联容器，如果两个键在比较关系下互不小于对方，它们会被视为等价，即使它们的 `operator==` 不一定返回 true。

### 6. lower_bound 和 upper_bound

对于按相应比较规则排序的范围：

- `lower_bound` 返回第一个“不在目标之前”的位置，常见升序整数场景下就是第一个大于等于目标值的位置。
- `upper_bound` 返回第一个严格在目标之后的位置，常见升序整数场景下就是第一个大于目标值的位置。

~~~cpp
std::vector<int> v{1, 2, 2, 2, 4, 5};
auto first = std::lower_bound(v.begin(), v.end(), 2);
auto last  = std::upper_bound(v.begin(), v.end(), 2);
auto count = last - first; // 3，vector 的迭代器支持随机访问
~~~

范围必须按对应比较规则满足算法的前置条件。对未排序范围使用二分查找算法，不能保证得到正确结果。

### 7. remove 为什么不真正删除容器元素？

`std::remove` 是通用算法，它只有迭代器，没有容器对象，因而通常不能直接改变容器的 size。

~~~cpp
auto newEnd = std::remove(v.begin(), v.end(), 2);
v.erase(newEnd, v.end());
~~~

`remove` 会把不等于目标值的元素移到前部，并返回新的逻辑尾位置。原范围末尾的部分元素仍然存在，容器大小尚未改变；需要再调用容器的 `erase` 才能真正删除。

### 8. erase-remove 惯用法

~~~cpp
v.erase(std::remove(v.begin(), v.end(), value), v.end());
~~~

这通常被称为 erase-remove 惯用法，常用于 vector、string 等序列容器中按值删除元素。

C++20 为部分标准序列容器提供了 `std::erase` / `std::erase_if` 等非成员函数，能让表达更简洁；项目如果采用 C++11/14，仍应掌握传统写法。

对于 map/set 等关联容器，不应直接对元素范围套用这一模式，因为其元素键值约束和迭代器性质不同，应使用容器的成员删除接口。

### 9. unique 的常见误区

`std::unique` 只会将相邻的重复元素压缩到逻辑范围前部，不会自动删除容器末尾元素。

~~~cpp
std::vector<int> v{1, 1, 2, 1, 1};
auto it = std::unique(v.begin(), v.end());
v.erase(it, v.end());
~~~

这里并非所有相同值都会被当成一个全局集合中的重复项。若要去除所有重复值并保留唯一元素，通常先排序，再执行 `unique` 和 `erase`；但排序会改变元素顺序。

### 10. 算法修改元素时的注意事项

某些算法会修改元素值，例如 `replace`、`transform`、`sort` 等；某些算法只读取，例如 `find`。

使用前应确认：

- 迭代器类别满足要求。
- 范围有效且满足算法的有序等前置条件。
- 输出迭代器指向可写且容量足够的目标区域。
- 比较器或谓词满足要求。
- 算法执行后是否有元素顺序变化或迭代器失效。

## 十一、函数对象、仿函数与 lambda

### 1. 什么是函数对象？

函数对象（function object，常称仿函数）是定义了函数调用运算符 `operator()` 的对象，可以像函数一样调用。

~~~cpp
struct Greater {
    bool operator()(int a, int b) const
    {
        return a > b;
    }
};

Greater greater;
bool result = greater(3, 2);
~~~

函数对象可以携带状态，也可以通过模板进行特化优化。标准算法经常接收函数对象作为比较器、谓词或转换操作。

### 2. 什么是谓词？

谓词是用于判断条件的可调用对象，通常返回可转换为 bool 的结果。

~~~cpp
auto isEven = [](int x) {
    return x % 2 == 0;
};
~~~

谓词可用于 `find_if`、`count_if`、`remove_if` 等算法。谓词应满足算法所要求的语义；排序比较器尤其需要满足严格弱序。

### 3. lambda 表达式是什么？

lambda 是创建闭包对象的一种语法，可以定义匿名可调用对象。

~~~cpp
auto add = [](int a, int b) {
    return a + b;
};
int result = add(1, 2);
~~~

lambda 不只是一个函数指针。它通常对应一个编译器生成的闭包类型，捕获列表中的状态会成为闭包对象的一部分。

### 4. lambda 捕获方式

~~~cpp
int x = 10;
int y = 20;

auto a = [x] { return x; };       // 按值捕获 x
auto b = [&y] { return y; };      // 按引用捕获 y
auto c = [=] { return x + y; };   // 默认按值捕获所使用的局部变量
auto d = [&] { return x + y; };   // 默认按引用捕获所使用的局部变量
~~~

按值捕获通常在闭包创建时保存被捕获变量的副本；按引用捕获则依赖原对象的生命周期。若闭包比被引用对象活得更久，就可能产生悬空引用。

### 5. mutable lambda 是什么？

按值捕获的变量默认不能在 lambda 的 const 调用运算符中被修改。使用 `mutable` 可以让闭包在调用时修改其按值捕获的副本。

~~~cpp
int x = 1;
auto f = [x]() mutable {
    return ++x;
};
~~~

这里修改的是闭包内部捕获的副本，不会改变外部原始变量 `x`。

### 6. lambda 与函数指针的区别

- 无捕获 lambda 可以在满足规则时转换为对应的函数指针。
- 有捕获 lambda 通常不能直接转换为普通函数指针，因为调用需要闭包对象中的捕获状态。
- lambda 的闭包类型由编译器生成，类型通常是唯一且无法直接命名的。
- 使用 `auto` 可以保存 lambda 对象；需要类型擦除时可以考虑 `std::function`，但它可能有额外开销。

### 7. std::function 是什么？

`std::function` 是一个可调用对象包装器，可以存储符合其函数签名的不同可调用实体。

~~~cpp
std::function<int(int, int)> operation =
    [](int a, int b) { return a + b; };

int result = operation(2, 3);
~~~

它可以存储普通函数、函数对象、lambda 和绑定表达式等，但类型擦除可能引入额外开销，也可能涉及动态分配。性能敏感代码应根据需要选择模板参数、具体闭包类型或 `std::function`。

### 8. bind 与现代 lambda

`std::bind` 可以绑定可调用对象的部分参数，并用占位符表示调用时提供的参数。

现代 C++ 中，很多场景用 lambda 更清晰，也更容易明确捕获语义。掌握 `std::bind` 有助于阅读旧代码，但不必为了使用它而放弃更直接的 lambda 写法。

## 十二、pair、tuple、bitset 与其他常见工具

### 1. std::pair

`std::pair` 保存两个可能不同类型的值。

~~~cpp
std::pair<int, std::string> item{1, "apple"};
std::cout << item.first << item.second;
~~~

map 的元素也采用 pair 形式保存键和值。C++11 起可以通过花括号初始化，C++17 还提供结构化绑定。

### 2. std::tuple

`std::tuple` 可以保存固定数量、类型可能不同的值。

~~~cpp
auto item = std::make_tuple(1, std::string("hello"), 3.14);
auto name = std::get<1>(item);
~~~

C++17 可以使用结构化绑定拆分 tuple 或 pair：

~~~cpp
auto [id, text, value] = item;
~~~

结构化绑定默认会按声明形式创建绑定；需要避免复制时，应理解 `auto`、`auto&` 和 `const auto&` 的区别。

### 3. std::bitset

`std::bitset<N>` 用固定数量的位表示布尔状态，适合位集合、标记和某些集合运算场景。

它的位数在编译期固定，提供测试、设置、翻转和计数等操作。不要将其与动态位集合或 `vector<bool>` 的语义完全等同。

### 4. std::string_view（C++17）

`std::string_view` 是非拥有的字符序列视图，通常只保存指针和长度，不负责管理字符存储。

~~~cpp
std::string text = "hello";
std::string_view view = text;
~~~

它可以避免某些只读接口中的字符串复制，但必须保证底层字符存储在 view 使用期间仍然有效。若底层 string 被销毁、重新分配或字符数据发生不符合预期的变化，view 可能变成悬空或观察到变化后的内容。

### 5. std::optional（C++17）与 std::variant（C++17）

- `std::optional<T>` 表示可能存在一个 T 值，也可能没有值。
- `std::variant<Ts...>` 表示当前持有候选类型列表中的某一种类型。

它们常用于表达比魔法数、空指针或多个独立状态变量更明确的业务状态。两者是现代 C++ 标准库的重要工具，具体用法可在后续现代 C++ 章节深入学习。

## 十三、容器复杂度与迭代器失效速查

### 1. 常见操作复杂度速查

下表是常见情况的面试级概括；具体操作、前置条件和元素类型会影响细节。

| 容器 | 随机访问 | 查找 | 尾部/两端插入 | 中间插入/删除 |
|---|---|---|---|---|
| vector | O(1) | 一般线性查找 O(n) | 尾部摊还 O(1) | 通常 O(n) |
| deque | O(1) | 一般线性查找 O(n) | 两端通常 O(1) | 通常 O(n) |
| list | 不支持 O(1) 随机访问 | 一般 O(n) | 头尾操作 O(1) | 已知位置插删 O(1) |
| map/set | 不适用序列下标 | O(log n) | 插入 O(log n) | 按键删除 O(log n) 量级 |
| unordered_map/set | 不适用序列下标 | 平均 O(1)，最坏 O(n) | 平均 O(1)，最坏 O(n) | 按键删除平均 O(1)，最坏 O(n) |

对 list 来说，“已知位置”很重要：如果先要从头遍历 n 个节点才能找到目标位置，总操作仍可能是 O(n)。

### 2. 常见迭代器失效对照

| 容器与操作 | 常见规则 |
|---|---|
| vector 扩容 | 所有指向元素的指针、引用和迭代器失效 |
| vector 尾部插入且不扩容 | 原元素迭代器通常有效，旧 end 失效 |
| vector 中间插入/删除 | 插入点或删除点及之后的迭代器通常失效 |
| deque 两端插入 | 迭代器可能失效；已有元素引用通常仍有效，需按具体操作核对 |
| list 插入 | 已有迭代器和引用通常保持有效 |
| list 删除 | 被删除元素的迭代器和引用失效 |
| map/set 插入 | 已有迭代器和引用通常保持有效 |
| map/set 删除 | 仅被删除元素的迭代器和引用失效 |
| unordered_map/set rehash | 迭代器失效；元素引用和指针通常保持有效 |
| unordered_map/set 删除 | 被删除元素的迭代器、引用和指针失效 |

该表用于快速记忆，不能代替具体操作的标准规定。遇到 deque、批量操作、swap、赋值、clear 等边界情况，应单独核对。

## 十四、STL 高频面试题

### Q1：vector 和 list 的区别是什么？

vector 是连续存储的动态数组，随机访问 O(1)，尾部追加摊还 O(1)，但中间插删通常需要移动后续元素；list 是链表，随机访问效率低，但在已知位置插删节点通常 O(1)，并且插入不会使其他节点迭代器失效。实际选择还要考虑缓存局部性和内存开销。

### Q2：vector 的 size 和 capacity 有什么区别？

size 是当前元素数量；capacity 是不重新分配存储时可容纳的元素数量。reserve 主要调整容量，不改变 size；resize 改变元素数量。

### Q3：vector 扩容为什么会导致迭代器失效？

扩容可能分配新的连续存储并把原元素移动或复制过去，旧存储随后释放，因此原先指向旧存储的指针、引用和迭代器失效。

### Q4：map 和 unordered_map 的区别是什么？

map 按比较器维护有序结构，查找、插入、删除通常 O(log n)；unordered_map 基于哈希，平均 O(1)，最坏 O(n)，但不提供按键排序，rehash 会使迭代器失效。

### Q5：map 的 operator[] 有什么风险？

访问不存在的键时会插入一个新元素，并对 mapped value 进行值初始化。因此只查询时通常应优先使用 find、count 或合适版本中的 contains。

### Q6：为什么 std::sort 不能用于 list？

std::sort 要求随机访问迭代器，而 list 只提供双向迭代器。应使用 list 自身的 sort 成员函数。

### Q7：remove 为什么不真正删除元素？

remove 只通过迭代器重排或移动元素，返回逻辑新尾位置，不知道具体容器对象，无法自行改变容器大小。需要用 erase 删除尾部冗余元素。

### Q8：erase-remove 是什么？

传统序列容器的惯用写法：先用 remove 或 remove_if 把保留元素移到前面，再通过 erase 删除逻辑新尾到实际尾部的元素。

### Q9：迭代器和指针有什么区别？

迭代器是对元素访问方式的抽象，可以由普通指针实现，也可以是类对象或代理类型。它的能力由迭代器类别决定，不能假设每个迭代器都支持指针的全部操作。

### Q10：函数对象与 lambda 有什么关系？

函数对象是支持函数调用运算符的对象；lambda 表达式会生成闭包对象，因此 lambda 本身就是一种函数对象形式。它可以携带捕获状态。

### Q11：unordered_map 的查找一定是 O(1) 吗？

不是。平均情况下常见复杂度为 O(1)，但哈希冲突严重时最坏可能达到 O(n)。

### Q12：set/map 的键为什么不能随意修改？

键参与容器内部排序。直接修改键可能破坏容器维护的结构与不变量。通常应移除旧键后插入新键，或使用符合规则的节点句柄操作。

### Q13：什么是严格弱序？

它是排序比较器必须满足的一组关系性质，保证元素之间的排序关系一致且可用于标准算法。像 `a >= b` 这样的比较器不满足严格弱序要求，不能用作标准排序比较器。

### Q14：emplace 一定比 push 更快吗？

不一定。emplace 可能避免某些临时对象，但实际效果取决于参数、元素构造和容器操作；扩容时仍可能需要移动或复制已有元素。

### Q15：string_view 为什么可能悬空？

string_view 不拥有字符存储，只观察另一处存储。底层对象销毁或其字符存储失效后，view 仍保留旧地址和长度，继续访问就可能产生未定义行为。
