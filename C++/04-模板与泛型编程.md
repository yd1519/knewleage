## 一、模板与泛型编程基础

### 1. 什么是模板？

模板（template）允许程序员把类型或某些编译期值作为参数，描述一组可复用的函数或类。

~~~cpp
template<class T>
T Max(T a, T b)
{
    return a < b ? b : a;
}

int i = Max(1, 2);
double d = Max(1.5, 2.0);
~~~

调用时，编译器根据模板参数生成适用于相应类型的函数实例。模板不是简单的文本替换；它具有类型推导、重载决议、实例化和约束检查等语言规则。

### 2. 什么是泛型编程？

泛型编程是编写不依赖某个具体类型、而依赖类型所提供操作和语义的代码。

例如，一个排序算法不必只接受 `int` 数组，只要元素和比较器满足算法所需的要求，就可以处理其他类型。

~~~cpp
template<class T>
void Swap(T& a, T& b)
{
    T temp = a;
    a = b;
    b = temp;
}
~~~

这个实现要求 `T` 可以被复制构造并赋值。泛型代码的关键不只是“能接受很多类型”，还要明确它对这些类型提出了哪些操作要求。

### 3. 模板与宏有什么区别？

| 对比项 | 模板 | 宏 |
|---|---|---|
| 处理阶段 | 编译器按 C++ 语法处理 | 预处理阶段进行文本替换 |
| 类型检查 | 有类型系统参与 | 宏自身不进行 C++ 类型检查 |
| 作用域 | 遵循 C++ 名称与作用域规则 | 宏替换不遵循普通变量作用域 |
| 错误诊断 | 通常有模板相关诊断，复杂时可能较长 | 常出现替换后的语法错误 |
| 适用场景 | 类型泛化、编译期计算、通用算法 | 条件编译、少数文本级元编程场景 |

模板通常更安全、更符合类型系统，但也不是所有宏都能被模板直接替代，例如条件编译和部分代码生成场景。

### 4. `template<class T>` 和 `template<typename T>` 有区别吗？

在声明模板类型参数时，二者等价：

~~~cpp
template<class T>
void Foo(T);

template<typename T>
void Bar(T);
~~~

这里的 `class` 不表示 `T` 必须是 class 类型；它也可以推导为 `int`、指针等类型。

不过，在模板参数列表中声明模板模板参数时，语法中的 `class` 有专门用途；日常类型模板参数场景下，两种写法可按风格选择。

### 5. 模板是运行时机制吗？

模板的类型推导、实例化与大量检查发生在编译期。生成的模板实例像普通函数或类一样参与后续编译和链接。

因此常见特点是：

- 很多错误在编译期暴露。
- 不同模板参数可能生成不同实例。
- 模板常用于零运行时抽象成本的通用代码。
- 模板实例过多时可能增加编译时间和二进制体积。

但不要简单地说“模板没有任何运行时成本”。实例生成的函数仍然执行普通程序逻辑；代码体积、缓存行为等也可能影响运行性能。

## 二、函数模板

### 1. 函数模板的基本语法

~~~cpp
template<typename T>
T Add(T a, T b)
{
    return a + b;
}
~~~

使用时可以让编译器推导模板实参：

~~~cpp
int a = Add(1, 2);
double b = Add(1.0, 2.0);
~~~

编译器需要在实例化时检查表达式是否对相应类型有效。例如 `T` 必须支持这里使用的加法运算，并且表达式结果能够用于返回类型。

### 2. 函数模板参数如何推导？

~~~cpp
template<typename T>
void Foo(T value);

int x = 10;
Foo(x);   // T 推导为 int
Foo(3.5); // T 推导为 double
~~~

模板实参推导会综合参数类型、实参表达式类型以及参数声明形式。它并不是简单地把实参类型原封不动地复制给 `T`。

尤其要注意参数是否是：

- 按值参数 `T`。
- 左值引用参数 `T&`。
- const 左值引用参数 `const T&`。
- 转发引用参数 `T&&`（需要满足特定的模板推导条件）。

这些形式会影响顶层 cv 限定和引用在推导中的处理方式。

### 3. 按值参数 T 的推导规则

~~~cpp
template<class T>
void ByValue(T value);

const int x = 10;
ByValue(x); // T 推导为 int，顶层 const 不保留在按值参数类型中
~~~

当参数按值传递时，实参顶层的 `const` 和引用通常不会成为推导出的 `T` 的一部分。

例如，若实参是 `int&`，按值参数的 `T` 通常推导为 `int`，而不是 `int&`。

这不意味着指针指向对象的 const 可以随意去掉；指针类型内部的 cv 限定需要根据完整类型规则判断。

### 4. T& 与 const T& 的推导

~~~cpp
template<class T>
void LRef(T& value);

template<class T>
void ConstLRef(const T& value);

int x = 1;
const int cx = 2;

LRef(x);       // T 为 int
LRef(cx);      // T 为 const int
ConstLRef(x);  // T 为 int
ConstLRef(cx); // T 为 int
~~~

对于 `T&`，实参的 const 限定会反映在推导出的 `T` 中。

对于 `const T&`，参数本身已经为所引用对象添加了 const，因此实参为 `int` 或 `const int` 时，`T` 都可以推导为 `int`。

### 5. 数组与函数在按值参数中的退化

~~~cpp
template<class T>
void ByValue(T value);

template<class T>
void ByRef(T& value);

int arr[5]{};
ByValue(arr); // T 通常推导为 int*
ByRef(arr);   // T 推导为 int[5]
~~~

按值参数推导时，数组和函数实参通常发生数组到指针、函数到指针的调整。

引用参数可以保留数组类型，因此在需要保留数组长度时，可以使用引用形式并结合 `std::extent` 等类型工具。

### 6. 显式指定模板实参

~~~cpp
template<class T>
T Convert(double value)
{
    return static_cast<T>(value);
}

int x = Convert<int>(3.14);
~~~

调用者可以显式指定模板参数。未被显式指定、但能够从函数实参推导的参数，仍然可以由编译器推导。

如果显式指定的模板实参与函数参数类型不兼容，或者实例化后的函数体无效，编译仍会失败。

### 7. 函数模板的默认模板参数

~~~cpp
template<class T = int>
T MakeValue()
{
    return T{};
}

int a = MakeValue<>();
double b = MakeValue<double>();
~~~

函数模板可以提供默认模板参数。若没有函数实参可供推导，默认模板参数尤其有用。

注意，`MakeValue<>()` 明确使用模板调用语法；而 `MakeValue()` 是否能直接使用，取决于名称查找和模板实参是否能由上下文确定，不能把所有模板函数都当作能自动推导出返回类型。

### 8. 函数模板可以重载吗？

可以。函数模板可以与普通函数重载，也可以有多个不同参数形式的模板重载。

~~~cpp
void Print(int value)
{
    std::cout << "ordinary";
}

template<class T>
void Print(T value)
{
    std::cout << "template";
}

Print(10);   // 普通函数通常优先于同样匹配的模板特化候选
Print(3.14); // 模板版本可能成为更合适的候选
~~~

实际结果由完整重载决议规则决定，包括候选函数集合、可行性、转换序列、模板偏序和非模板优先规则等。

### 9. 普通函数与函数模板同样匹配时，谁优先？

~~~cpp
void Foo(int) {}

template<class T>
void Foo(T) {}

Foo(10);
~~~

在这个例子中，普通函数与模板实例化后的函数都可以进行同等级的精确匹配；在这种情况下，非模板函数通常优先。

但不能把这条规则扩大成“普通函数永远比模板优先”。如果模板候选具有更好的转换序列，模板版本仍然可能胜出。

### 10. 模板重载的常见陷阱：隐式转换

~~~cpp
void Func(long) {}

template<class T>
void Func(T) {}

Func(1); // 模板版本通常以 T = int 精确匹配；普通函数需要 int -> long 转换
~~~

模板函数可能因为提供更好的匹配而被选中，即使另一个普通函数看起来更“具体”。

面试分析重载题时，建议按以下步骤：

1. 列出候选函数。
2. 判断每个候选是否可行。
3. 比较隐式转换序列。
4. 如果需要，比较模板偏序。
5. 最后应用非模板函数等决胜规则。

## 三、类模板

### 1. 类模板的基本语法

~~~cpp
template<class T>
class Box {
public:
    explicit Box(const T& value)
        : value_(value)
    {
    }

    const T& Get() const
    {
        return value_;
    }

private:
    T value_;
};

Box<int> a(10);
Box<std::string> b("hello");
~~~

类模板为不同模板实参生成不同的类类型，例如 `Box<int>` 和 `Box<double>` 是不同类型。

### 2. 类模板的成员函数如何定义？

可以在类模板内部定义成员函数，也可以在类外定义：

~~~cpp
template<class T>
class Box {
public:
    void Set(const T& value);

private:
    T value_{};
};

template<class T>
void Box<T>::Set(const T& value)
{
    value_ = value;
}
~~~

类外定义时，通常需要重新写出模板参数列表，并用 `Box<T>` 指明当前特化的类模板类型。

### 3. 类模板的模板参数不能总是自动推导吗？

在 C++17 之前，通常需要显式写出类模板实参：

~~~cpp
Box<int> box(10);
~~~

C++17 引入了类模板实参推导（CTAD），在符合规则的情况下，编译器可以从构造函数实参推导类模板参数：

~~~cpp
std::pair p(1, 2.0); // C++17：推导为 std::pair<int, double>
~~~

用户自定义类模板也可以通过构造函数和推导指引参与 CTAD。CTAD 不代表所有类模板都能在任何上下文自动推导。

### 4. 什么是类模板的静态数据成员？

~~~cpp
template<class T>
class Counter {
public:
    static int count;
};

template<class T>
int Counter<T>::count = 0;
~~~

对于不同模板实参，`Counter<int>` 与 `Counter<double>` 通常拥有各自对应的静态数据成员实体。

C++17 起，可以使用符合规则的 `inline static` 在类内定义静态数据成员：

~~~cpp
template<class T>
class Counter {
public:
    inline static int count = 0;
};
~~~

### 5. 类模板的友元和成员模板

类模板可以包含成员函数模板，也可以声明友元模板或友元函数。

~~~cpp
template<class T>
class Wrapper {
public:
    template<class U>
    void Assign(const U& value)
    {
        value_ = static_cast<T>(value);
    }

private:
    T value_{};
};
~~~

成员模板使一个类的某个操作可以对另一组类型参数泛化。需要注意，成员模板本身与所在类模板的参数是不同层次的模板参数。

### 6. 模板类型的可用操作由谁决定？

模板的实例化会检查被使用的操作对当前模板实参是否有效。

~~~cpp
template<class T>
auto DoubleValue(const T& value)
{
    return value + value;
}
~~~

这个函数要求 `T` 支持相应的 `operator+` 表达式。它不需要所有类型都支持加法，只需要实际使用该模板实例的类型满足要求。

传统模板通常通过表达式和编译错误体现这些要求；C++20 Concepts 则可以更显式地表达约束。

## 四、非类型模板参数与模板参数种类

### 1. 什么是非类型模板参数？

模板参数不只有类型，也可以是符合规则的编译期值。

~~~cpp
template<class T, std::size_t N>
struct Array {
    T data[N];
};

Array<int, 10> a;
~~~

这里 `T` 是类型模板参数，`N` 是非类型模板参数（也称非类型模板形参）。

非类型模板参数适合表达数组长度、策略标志、固定数值等编译期信息。

### 2. 非类型模板参数的常见形式

~~~cpp
template<int N>
struct IntConstant {};

template<bool Enabled>
struct Feature {};

template<auto Value>
struct Constant {}; // C++17：auto 非类型模板参数
~~~

C++17 起，`auto` 可用于推导非类型模板参数的类型。

非类型模板参数允许的类型受 C++ 标准版本限制。C++20 又扩展了可用类型范围；在面试中应结合指定标准版本回答，不能把某一版本的规则直接套用到所有版本。

### 3. 模板模板参数是什么？

模板模板参数让一个模板接受另一个模板作为参数。

~~~cpp
template<class T, template<class> class Container>
class Store {
public:
    Container<T> data;
};
~~~

这里的 `Container` 本身是一个模板参数，使用时再以 `T` 实例化。

模板模板参数的匹配规则受模板参数列表形状、默认参数和语言版本影响；实际代码中需要注意标准容器通常不止一个模板参数，例如 allocator 参数。

### 4. 模板参数包是什么？

~~~cpp
template<class... Types>
struct TypeList {};
~~~

`Types...` 是模板参数包，可以容纳零个或多个模板实参。

参数包是可变参数模板的基础。它本身不会自动展开，通常需要在声明、表达式或其他模板结构中通过展开语法使用。

## 五、模板特化与偏特化

### 1. 什么是模板特化？

模板特化为特定模板实参提供专门实现。

~~~cpp
template<class T>
struct TypeInfo {
    static constexpr const char* name = "unknown";
};

template<>
struct TypeInfo<int> {
    static constexpr const char* name = "int";
};
~~~

`TypeInfo<T>` 是主模板，`TypeInfo<int>` 是针对 `int` 的显式特化。

特化常用于某些类型需要不同实现、不同属性或不同编译期行为的场景。

### 2. 什么是全特化？

全特化（显式特化）为模板参数提供完整的特定取值。

~~~cpp
template<class T>
struct Traits {};

template<>
struct Traits<int> {
    using type = int;
};
~~~

这个特化只适用于 `Traits<int>`。

函数模板也允许显式特化，但工程中应特别谨慎：函数模板的重载决议不会把函数模板显式特化当作一个独立重载来处理，实际选择先依据主模板重载决议，再考虑对应特化是否适用。

### 3. 什么是偏特化？

偏特化为一类模板实参模式提供实现，参数没有全部固定下来。

~~~cpp
template<class T>
struct TypeInfo {};

template<class T>
struct TypeInfo<T*> {
    static constexpr bool is_pointer = true;
};
~~~

`TypeInfo<T*>` 是类模板的偏特化，可以匹配多种指针类型，例如 `TypeInfo<int*>` 和 `TypeInfo<double*>`。

### 4. 类模板可以偏特化，函数模板可以偏特化吗？

**类模板可以偏特化，函数模板不支持偏特化。**

~~~cpp
template<class T>
struct Traits {};

template<class T>
struct Traits<T*> {}; // 类模板偏特化
~~~

如果希望函数模板表现出类似偏特化的效果，通常使用函数模板重载：

~~~cpp
template<class T>
void Process(T value)
{
}

template<class T>
void Process(T* value)
{
}
~~~

函数模板显式全特化是允许的，但函数模板偏特化不允许。

### 5. 偏特化如何选择？

当多个类模板特化都匹配某个实参时，编译器按模板偏序规则选择更特化的版本。

~~~cpp
template<class T>
struct Select {};

template<class T>
struct Select<T*> {};

template<class T>
struct Select<const T*> {};
~~~

对于 `Select<const int*>`，`Select<const T*>` 通常比一般的 `Select<T*>` 更特化，因此选择后者。

遇到复杂偏特化题时，不要只按“写得更长”判断。应分析每个模式可以匹配哪些类型，以及它们之间的偏序关系。

### 6. 模板特化与普通重载有什么区别？

- 类模板特化用于为特定模板实参模式提供类定义。
- 函数重载是多个同名函数或函数模板参与重载决议。
- 函数模板显式特化依附于一个主模板，并不作为独立的重载候选参与选择。

如果只是希望对某些函数参数形式采用不同实现，通常函数模板重载更直观。

### 7. 特化的声明位置有什么要求？

显式特化应在相关使用导致隐式实例化之前，按照标准要求在适当作用域中声明。若不同翻译单元对同一模板特化的可见声明不一致，可能违反 ODR 或产生程序行为问题。

面试重点是：模板特化不是随时随地都可以在任意位置补上一份定义；要保证声明可见性和定义的一致性。

## 六、模板实例化与编译模型

### 1. 什么是模板实例化？

模板实例化是编译器根据模板实参形成具体函数或类特化的过程。

~~~cpp
template<class T>
T Square(T x)
{
    return x * x;
}

int a = Square(3);       // 需要形成适用于 int 的实例
double b = Square(2.5);  // 需要形成适用于 double 的实例
~~~

模板定义不意味着编译器会立即为所有可能类型生成代码。实例化通常在程序实际需要某个特化时发生。

### 2. 为什么模板实现通常放在头文件中？

很多模板的实例化需要编译器在使用点看到模板定义，以便针对具体模板实参生成实例。

因此，模板声明和定义通常都放在头文件或被头文件包含的实现文件中。

这不是说模板绝对不能放在 cpp 文件中：如果在某个翻译单元中显式实例化了需要支持的类型，并正确组织声明与链接，就可以把部分实现放在 cpp 文件中。但这要求明确支持哪些模板实参。

### 3. 什么是显式实例化？

~~~cpp
template<class T>
T Add(T a, T b)
{
    return a + b;
}

template int Add<int>(int, int);
~~~

显式实例化定义要求编译器为指定模板实参实例化相应实体。

显式实例化声明通常写成：

~~~cpp
extern template int Add<int>(int, int);
~~~

它可以在合适的工程结构中抑制某些翻译单元重复进行隐式实例化工作，通常与其他翻译单元中的显式实例化定义配合使用。

不要混淆：

- 显式特化：为某个类型模式提供专门定义。
- 显式实例化：要求对已有模板按指定实参实例化。

### 4. 模板定义放头文件会不会违反 ODR？

不会仅仅因为“放在头文件”就违反 ODR。模板定义通常会被多个翻译单元看到，语言规则对模板及相关实体有专门规定；正确组织的头文件模板是标准 C++ 的常见做法。

不过，普通非 inline 函数或变量在多个翻译单元中重复定义仍可能违反 ODR。头文件中定义普通非 inline 函数时，应格外小心。

### 5. 模板错误为什么经常很难读？

模板错误可能发生在：

- 模板参数推导阶段。
- 候选函数的可行性检查阶段。
- 模板特化选择阶段。
- 模板实例化的函数体或成员定义中。
- 依赖名称解析阶段。
- 链接阶段，例如缺少显式实例化定义。

排查时建议先找诊断中最早出现的用户代码位置，再看模板实参实际推导成什么类型，并确认该类型是否满足模板内部使用的表达式要求。

## 七、依赖名称、typename 与 template 关键字

### 1. 什么是依赖名称？

在模板定义中，有些名称的含义取决于模板参数，称为依赖名称。

~~~cpp
template<class T>
void Foo()
{
    typename T::value_type value{};
}
~~~

`T::value_type` 依赖于模板参数 `T`；只有当模板实参确定后，编译器才能判断它指向的具体类型成员是否存在。

### 2. 为什么需要 typename？

在许多模板语境下，依赖限定名称默认不会被直接当作类型名解析，因此需要用 `typename` 明确告诉编译器它是一个类型。

~~~cpp
template<class T>
void Foo()
{
    typename T::value_type value{};
}
~~~

没有 `typename` 时，编译器在需要消除语法歧义的上下文中可能无法把 `T::value_type` 识别为类型。

但并非所有依赖类型名称都必须写 `typename`；在基类列表等已有明确类型语法的上下文中，规则不同。面试中应说明它用于消除依赖名称解析歧义，而不是“每个 T:: 都要加”。

### 3. 为什么需要 template 关键字？

当依赖名称后面跟着模板成员调用时，可能需要显式使用 `template` 关键字，告诉编译器后续名称是模板。

~~~cpp
template<class T>
void Foo(T& object)
{
    object.template GetValue<int>();
}
~~~

这里的 `object` 类型依赖于模板参数，编译器需要 `template` 提示 `GetValue<int>` 是模板成员调用，而不是把尖括号按其他语法解析。

和 `typename` 一样，`template` 只在特定依赖名称语境下需要，不应无条件到处添加。

### 4. 什么是两阶段名称查找？

模板相关名称查找通常分为定义阶段与实例化阶段来理解：

- 非依赖名称通常在模板定义时查找。
- 依赖名称的某些解析与有效性检查要等模板实参确定后完成。
- 依赖于实参的查找会受相关语言规则约束，例如 ADL（实参依赖查找）。

这有助于理解为什么某个名字在模板定义位置可见与否，会影响最终程序结果；也解释了模板定义不能总是依赖“实例化时再看看有没有这个函数”。

### 5. 什么是 ADL（Argument-Dependent Lookup）？

ADL 是实参依赖查找，也称 Koenig lookup。它允许在某些未限定函数调用中，根据实参的类型关联到的命名空间查找函数。

~~~cpp
namespace Math {
    struct Vec {};
    void Process(const Vec&) {}
}

Math::Vec v;
Process(v); // 可通过 ADL 找到 Math::Process
~~~

ADL 在运算符重载、泛型库和自定义交换函数等场景很重要。

常见惯用写法：

~~~cpp
using std::swap;
swap(a, b);
~~~

这让普通查找先引入 `std::swap`，同时允许 ADL 找到与 `a`、`b` 类型相关的更合适的自定义 `swap`。

## 八、可变参数模板与折叠表达式

### 1. 什么是可变参数模板？

可变参数模板允许模板接受数量可变的模板参数。

~~~cpp
template<class... Args>
void PrintAll(const Args&... args)
{
}
~~~

- `Args...` 是模板参数包。
- `args...` 是函数参数包。
- 参数包可以包含零个或多个参数。
- 参数包展开语法会把一个模式应用到包中的每个元素。

### 2. 参数包如何展开？

~~~cpp
template<class... Args>
void PrintAll(const Args&... args)
{
    (std::cout << ... << args) << '\n'; // C++17 折叠表达式
}
~~~

在 C++17 中，可以通过折叠表达式简洁地对参数包执行某个二元运算。

在 C++11/14 中，常见方式是使用递归模板或其他辅助结构逐个处理参数。

### 3. 递归式可变参数模板

~~~cpp
void Print()
{
}

template<class T, class... Args>
void Print(const T& first, const Args&... rest)
{
    std::cout << first << '\n';
    Print(rest...);
}
~~~

这里有一个空参数版本作为递归终止条件。每次递归移除第一个参数，直到参数包为空。

这种模式在 C++11/14 代码中很常见。需要注意，递归函数模板会增加实例化层次和错误诊断复杂度；如果目标标准支持折叠表达式，可以考虑更直接的写法。

### 4. C++17 折叠表达式是什么？

折叠表达式允许把二元运算符应用到参数包中的多个表达式。

~~~cpp
template<class... Args>
auto Sum(const Args&... args)
{
    return (args + ...);
}
~~~

调用 `Sum(1, 2, 3)` 时，相当于把加法按规定结合起来，得到 `1 + (2 + 3)` 这一类折叠结构。

折叠表达式的形式包括：

- 一元右折叠：`(pack op ...)`。
- 一元左折叠：`(... op pack)`。
- 二元右折叠：`(pack op ... op init)`。
- 二元左折叠：`(init op ... op pack)`。

实际写法中，`op` 必须是标准允许的折叠运算符。还要考虑运算符的结合性、操作数类型，以及空参数包时该表达式是否有定义。

### 5. 折叠表达式处理空参数包时要注意什么？

对于某些运算符，一元折叠在空包时有规定的结果，例如逻辑与、逻辑或和逗号运算符有各自的空包规则。其他运算符通常需要非空包，或者使用带初始值的二元折叠。

~~~cpp
template<class... Args>
bool All(Args... args)
{
    return (... && args); // 空参数包时，逻辑与折叠结果为 true
}
~~~

不要把所有折叠表达式都当作能自然处理空参数包。若接口允许零参数调用，应检查所用运算符的空包规则。

### 6. 可变参数模板常见用途

- 实现 `std::make_unique` 一类转发构造函数的接口。
- 泛型日志和格式化接口。
- 容器或包装器的转发构造函数。
- 编译期类型列表与元编程工具。
- 把任意数量参数传递给另一函数。

参数包提供灵活性，但需要留意重载冲突、错误信息和模板实例化开销。

## 九、完美转发与转发引用

### 1. 什么是转发引用？

当函数模板的参数声明为 `T&&`，且 `T` 在该处参与模板实参推导时，它可能是转发引用（forwarding reference）。

~~~cpp
template<class T>
void Wrapper(T&& value)
{
}
~~~

这种形式能够根据实参是左值还是右值，推导出不同的 `T`，从而在类型层面保留值类别信息。

旧资料常称其为“万能引用”，但“转发引用”更能描述用途，也能避免误以为任意 `T&&` 都是这一机制。

### 2. 引用折叠规则是什么？

模板推导中可能出现引用类型与引用组合。C++ 的引用折叠规则可以总结为：

| 组合 | 折叠结果 |
|---|---|
| `T& &` | `T&` |
| `T& &&` | `T&` |
| `T&& &` | `T&` |
| `T&& &&` | `T&&` |

简记：只要组合中出现左值引用，折叠结果就是左值引用；只有两边都是右值引用时，结果才是右值引用。

实际书写中，`T& &` 等是用于解释规则的抽象形式；不能在普通代码里直接声明“引用的引用”。

### 3. 转发引用如何推导？

~~~cpp
template<class T>
void Forward(T&& value);

int x = 10;
Forward(x);  // T 推导为 int&，参数类型经引用折叠成为 int&
Forward(10); // T 推导为 int，参数类型为 int&&
~~~

当实参是左值时，推导会把左值引用信息反映在 `T` 中；当实参是右值时，通常推导出非引用类型。

随后应用引用折叠，形成最终的参数类型。

### 4. 什么是完美转发？

完美转发指模板包装器在转发实参时，尽可能保留其类型与值类别，使下游重载选择与直接传递实参时保持预期一致。

~~~cpp
#include <utility>

template<class T>
void Wrapper(T&& value)
{
    Process(std::forward<T>(value));
}
~~~

`std::forward<T>(value)` 根据推导出的 `T` 有条件地将表达式转换为左值或右值类别。

如果只写 `Process(value)`，具名变量 `value` 是左值表达式，原始右值实参的值类别就不会自动保留。

### 5. std::move 与 std::forward 有什么区别？

| 对比项 | `std::move` | `std::forward<T>` |
|---|---|---|
| 主要目的 | 将表达式转换为可参与移动重载决议的右值类别 | 根据模板推导结果有条件地保留原始值类别 |
| 是否需要模板推导参数 | 通常不需要显式指定类型参数 | 通常使用推导得到的 `T` |
| 对左值的处理 | 即使传入左值，也会转换为右值类别 | 若 `T` 推导为左值引用，则仍转发为左值 |
| 常见场景 | 明确表示可以从某对象移动资源 | 泛型包装器、转发构造函数、通用工厂函数 |

### 6. 为什么不能无脑对所有参数使用 std::move？

~~~cpp
template<class T>
void Wrapper(T&& value)
{
    Process(std::move(value)); // 不一定符合调用者原意
}
~~~

若调用者传入左值，`std::move(value)` 仍会把它转换为右值类别，可能导致下游函数选择移动重载，甚至移动走调用者原本希望保留的对象。

转发包装器通常应使用 `std::forward<T>(value)`；而当函数明确拥有对象并准备把它作为可移动来源时，才适合有意使用 `std::move`。

### 7. 完美转发的常见用途：转发构造函数

~~~cpp
template<class T>
class Wrapper {
public:
    template<class U>
    explicit Wrapper(U&& value)
        : value_(std::forward<U>(value))
    {
    }

private:
    T value_;
};
~~~

这类构造函数可以接受不同值类别的参数，并把它们转发给成员对象的构造函数。

但转发构造函数也可能意外抢占拷贝/移动构造的重载，尤其是模板参数比目标构造函数匹配得更好时。因此，工程中常需要约束它，让它只在真正适用的类型上参与重载决议。

### 8. 转发引用的常见例外

并非所有 `T&&` 都是转发引用。例如：

~~~cpp
template<class T>
struct A {
    void Foo(T&& value); // T 在类模板实例化时已确定，不是转发引用
};
~~~

以及：

~~~cpp
template<class T>
void Foo(const T&& value); // 不是通常意义上的转发引用
~~~

判断要点：该处的 `T` 是否正在参与相应的函数模板实参推导，且参数声明是否符合转发引用形式。固定类型的右值引用仍然只是右值引用。

## 十、SFINAE 与 enable_if

### 1. 什么是 SFINAE？

SFINAE 是 Substitution Failure Is Not An Error 的缩写，通常译为“替换失败不是错误”。

在模板实参替换过程中，如果某个候选模板的相关声明或类型表达式替换失败，在满足 SFINAE 规则的语境下，这个候选会从重载候选集合中移除，而不是立刻让整个程序报错。

~~~cpp
template<class T>
auto Test(T value) -> typename T::value_type;

void Test(...);
~~~

对于不具有 `value_type` 的类型，第一个模板候选可能因替换失败而不参与最终选择，另一个可行候选可能被选中。

SFINAE 并不意味着模板函数体里的任何错误都能被忽略。通常只有发生在规定的立即上下文中的替换失败，才具有 SFINAE 效果。

### 2. 什么是立即上下文（immediate context）？

SFINAE 主要处理模板实参替换直接导致的声明、类型或表达式无效的情况。若替换触发了另一个模板实例化，而错误发生在那个实例化的函数体或其他非立即上下文中，错误不一定会被 SFINAE 吸收。

面试时可以概括为：**SFINAE 不是“所有模板错误都不算错误”，它只对规定上下文中的替换失败提供候选移除机制。**

### 3. std::enable_if 是什么？

`std::enable_if` 是标准库提供的类型工具，常用于在编译期条件成立时提供某个类型，从而控制模板候选是否有效。

概念上：

- 条件为真时，`std::enable_if<true, T>::type` 存在。
- 条件为假时，`std::enable_if<false, T>::type` 不存在。

它通常与 SFINAE 配合，让不满足条件的模板候选在替换阶段被移除。

### 4. enable_if 的常见写法

~~~cpp
#include <type_traits>

template<class T,
         typename std::enable_if<std::is_integral<T>::value, int>::type = 0>
void Process(T value)
{
}
~~~

这个模板只有在 `std::is_integral<T>::value` 为真时，才具有相应的模板参数类型。

C++14 起，标准库提供许多 `_v` 变量模板简写，例如 `std::is_integral_v<T>`；但传统 `enable_if` 形式仍是理解老代码和面试题的重要基础。

### 5. enable_if 的返回类型写法

~~~cpp
template<class T>
typename std::enable_if<std::is_integral<T>::value, T>::type
Process(T value)
{
    return value;
}
~~~

如果条件不满足，返回类型的替换失败可能让这个模板候选被移除。

不过，若模板调用已经选中候选、进入函数体后才发生错误，就不能指望返回类型上的 SFINAE 自动处理函数体内的所有问题。

### 6. enable_if 放在哪里？

常见位置包括：

- 返回类型。
- 模板参数列表中的额外参数。
- 函数参数类型。

不同位置会影响重载设计与声明等价性；尤其要注意，不能仅仅依赖某些默认模板参数写法来声明两个实际上冲突的函数模板。

使用 SFINAE 时，既要验证条件能否让不匹配候选消失，也要确认剩余候选之间的重载关系没有歧义。

### 7. std::void_t 的作用是什么？

C++17 提供 `std::void_t`（常见实现思路也可在较早版本中自行定义），常用于检测某个类型表达式是否有效。

~~~cpp
template<class, class = void>
struct HasValueType : std::false_type {};

template<class T>
struct HasValueType<T, std::void_t<typename T::value_type>>
    : std::true_type {};
~~~

若 `typename T::value_type` 有效，偏特化匹配并继承 `std::true_type`；否则回退到主模板，继承 `std::false_type`。

这类检测惯用法是传统模板元编程中很重要的技术。

### 8. SFINAE 与模板偏特化有什么关系？

SFINAE 可以影响模板候选是否有效；类模板偏特化则根据模板实参模式选择不同的类定义。

二者常一起用于类型特征和模板元编程，但不是同一机制：

- 偏特化解决“哪种模板实参模式使用哪份实现”。
- SFINAE 解决“某个候选在替换后是否仍然有效”。

## 十一、类型萃取与编译期计算

### 1. 什么是类型萃取（type traits）？

类型萃取是一组在编译期查询或转换类型属性的工具，标准库在 `<type_traits>` 中提供了大量设施。

~~~cpp
#include <type_traits>

static_assert(std::is_integral<int>::value, "int is integral");
static_assert(!std::is_integral<float>::value, "float is not integral");
~~~

C++17 起，很多类型萃取可以使用更简洁的变量模板：

~~~cpp
static_assert(std::is_integral_v<int>);
~~~

常见类型萃取包括：

- `std::is_same`：判断两个类型是否相同。
- `std::is_integral`：判断是否为整数类型。
- `std::is_pointer`：判断是否为指针类型。
- `std::remove_reference`：移除引用。
- `std::remove_const`：移除顶层 const。
- `std::decay`：执行类似按值传递中的类型调整。

### 2. 什么是 std::decay？

`std::decay<T>` 通常会模拟按值传递时的类型调整：移除引用和顶层 cv 限定，并对数组、函数类型进行相应退化。

~~~cpp
using A = std::decay_t<const int&>; // int
using B = std::decay_t<int[5]>;     // int*
~~~

`std::decay` 与 `std::remove_cvref` 并不完全相同：后者是 C++20 的工具，主要移除引用和 cv 限定，但不会把数组类型退化为指针。

### 3. 什么是 std::conditional？

`std::conditional` 根据编译期布尔条件，在两个类型中选择一个。

~~~cpp
using Result = std::conditional_t<true, int, double>; // int
~~~

它可以用于根据类型属性选择实现或中间类型，是基础的编译期类型计算工具。

### 4. 什么是 constexpr 与模板元编程的关系？

模板元编程常使用类型系统和模板实例化在编译期进行计算；`constexpr` 则允许满足规则的函数或变量参与常量表达式计算。

两者可以配合使用，但概念不同：

- 模板元编程通过模板、类型和实例化规则表达编译期计算。
- `constexpr` 让符合条件的表达式或函数可以用于常量求值。
- C++17 的 `if constexpr` 能根据编译期条件丢弃不需要的分支，简化部分传统 SFINAE 和特化代码。

### 5. if constexpr 与普通 if 有什么区别？

~~~cpp
template<class T>
void Process(T value)
{
    if constexpr (std::is_integral_v<T>) {
        // 整数类型分支
    } else {
        // 其他类型分支
    }
}
~~~

C++17 的 `if constexpr` 会在编译期根据条件选择分支。模板实例化时，被丢弃的分支不会按普通分支那样对当前实例进行常规实例化检查，因此可以用于不同类型的分支实现。

但这不意味着被丢弃分支中任何语法错误都可忽略；非依赖语法错误仍可能在模板定义阶段报错。

## 十二、CRTP 与静态多态

### 1. 什么是 CRTP？

CRTP 是 Curiously Recurring Template Pattern（奇异递归模板模式），一种让派生类把自身类型作为模板参数传给基类的设计模式。

~~~cpp
template<class Derived>
class Base {
public:
    void Interface()
    {
        static_cast<Derived*>(this)->Implementation();
    }
};

class MyType : public Base<MyType> {
public:
    void Implementation()
    {
    }
};
~~~

这里 `Base<MyType>` 的模板参数是派生类自身类型。基类通过静态转换调用派生类提供的接口。

### 2. CRTP 与虚函数多态有什么区别？

| 对比项 | 虚函数多态 | CRTP 静态多态 |
|---|---|---|
| 主要绑定阶段 | 运行期动态派发 | 编译期根据模板类型确定 |
| 典型接口 | 基类指针/引用调用虚函数 | 模板基类调用派生类实现 |
| 是否需要虚函数机制 | 需要虚函数语义，常见实现使用 vtable | 本身不需要虚函数 |
| 类型关系 | 可通过基类接口处理不同动态类型 | 通常在编译期确定具体派生类型 |
| 灵活性 | 适合运行时异构对象集合 | 适合编译期已知类型的静态接口 |

CRTP 不是虚函数的通用替代品。如果程序需要在运行时把不同派生类型放进同一个基类接口集合，传统运行期多态往往更合适。

### 3. CRTP 的常见用途

- 静态多态接口。
- mixin 风格功能复用。
- 编译期策略与类型定制。
- 在适合的场景下避免虚函数动态派发。

使用 CRTP 也会带来模板代码复杂度、编译时间与错误诊断成本。是否值得采用，应由接口需求与性能目标决定。

## 十三、C++20 Concepts 的基本认识

### 1. Concepts 是什么？

C++20 引入 Concepts，用于为模板参数表达更明确的编译期约束。

~~~cpp
#include <concepts>

template<std::integral T>
T Add(T a, T b)
{
    return a + b;
}
~~~

这里 `std::integral` 是标准概念之一，限制模板参数为满足整数类型概念的类型。

### 2. Concepts 与 SFINAE 有什么区别？

二者都可以影响哪些类型能使用某个模板，但表达方式和诊断体验不同：

- SFINAE 通常通过替换失败来移除不合适的候选，常见于 C++11/14 代码。
- Concepts 直接表达模板约束，意图更清楚，诊断通常更友好。
- Concepts 还参与约束排序与重载决议规则，不只是给 SFINAE 换了一个语法外壳。

对于 C++11/14 项目，仍然需要理解 SFINAE、`enable_if` 和类型萃取；阅读现代 C++20 代码时，则应理解 Concepts 的约束作用。

### 3. 为什么面试仍要掌握 SFINAE？

许多现有代码库和标准库设施使用传统模板技术；游戏引擎、基础库或跨编译器项目也可能需要支持较早的 C++ 标准。

因此，SFINAE 仍是理解模板重载、类型检测、传统泛型库和复杂编译错误的重要基础。Concepts 并不会让既有模板知识失去价值。

## 十四、模板常见面试追问

### Q1：模板是在编译期还是运行期处理的？

模板参数推导、实例化与大量类型检查发生在编译期；实例化后的代码则作为普通程序代码运行。不能说模板本身完全没有运行时成本。

### Q2：函数模板可以偏特化吗？

不可以。函数模板支持重载和显式全特化，不支持偏特化。需要类似偏特化的行为时，通常使用函数模板重载。

### Q3：类模板的全特化与偏特化有什么区别？

全特化固定全部模板实参；偏特化只约束一类实参模式，仍然保留部分模板参数。

### Q4：模板定义为什么通常放在头文件？

因为使用模板实例化具体类型时，编译器通常需要看到模板定义。也可以通过显式实例化等方式集中生成支持的特定类型。

### Q5：普通函数和函数模板同样匹配时，哪个优先？

在转换序列同等且相关决胜规则适用的情况下，非模板函数通常优先。但模板若提供更好的匹配，仍可能胜出。

### Q6：typename 的作用是什么？

在需要消除依赖名称解析歧义的上下文中，`typename` 用于告诉编译器某个依赖限定名称是类型。

### Q7：SFINAE 是什么意思？

替换失败不是错误。在规定的立即上下文中，模板实参替换失败可以使该候选从重载候选集合中移除，而不必立即使整个程序报错。

### Q8：std::enable_if 和 SFINAE 是什么关系？

`enable_if` 是常用的类型工具，可以通过条件决定某个类型是否存在；它常与 SFINAE 配合来控制模板候选是否有效。二者不是同一个概念。

### Q9：T&& 一定是转发引用吗？

不是。只有符合特定模板推导条件的 `T&&` 才是转发引用。固定类型的右值引用、`const T&&` 等情况不能一概当作转发引用。

### Q10：std::move 和 std::forward 的区别是什么？

`std::move` 主要把表达式转换为右值类别；`std::forward<T>` 根据模板推导结果有条件地保留原始值类别，常用于完美转发。

### Q11：折叠表达式是哪个版本引入的？

C++17。它用于把二元运算符应用到参数包中的多个表达式，减少递归式可变参数模板的样板代码。

### Q12：CRTP 是运行时多态吗？

通常不是。CRTP 通过模板参数在编译期确定派生类型，常用于静态多态；虚函数多态则支持通过基类接口按对象动态类型派发。

### Q13：Concepts 会取代 SFINAE 吗？

Concepts 在 C++20 中提供了更直接的约束表达与更好的诊断体验，但 SFINAE 仍是理解旧标准代码、传统模板库和重载规则的重要知识。
