## 一、类与对象基础

### 1. 什么是类？什么是对象？

类（class）是用户自定义类型，用来描述数据成员和成员函数；对象是类类型的一个具体实例。

~~~cpp
class Player {
public:
    int health = 100;

    void TakeDamage(int damage)
    {
        health -= damage;
    }
};

Player player;
player.TakeDamage(10);
~~~

- 数据成员描述对象的状态。
- 成员函数描述对象可以执行的操作。
- 类是类型定义；对象才是具体实例。
- `class` 与 `struct` 的主要语言差别是默认访问权限和默认继承权限。

### 2. class 和 struct 有什么区别？

~~~cpp
class A {
    int x; // 默认 private
};

struct B {
    int x; // 默认 public
};
~~~

主要区别：

1. `class` 的成员默认是 `private`，`struct` 的成员默认是 `public`。
2. `class` 默认采用 private 继承，`struct` 默认采用 public 继承。

二者都可以拥有构造函数、析构函数、虚函数、继承关系、模板等功能。C++ 中的 `struct` 并不只是 C 语言结构体的简单复刻。

### 3. public、protected、private 有什么区别？

| 访问权限 | 类内成员 | 派生类成员 | 普通外部代码 |
|---|---|---|---|
| public | 可以访问 | 在继承关系允许时可以访问 | 可以访问 |
| protected | 可以访问 | 在符合访问规则时可以访问 | 通常不能直接访问 |
| private | 可以访问 | 不能直接访问基类的 private 成员 | 不能直接访问 |

访问控制是编译期的语言规则，并不是运行时的安全边界。

### 4. 什么是 this 指针？

非静态成员函数可以通过隐含的 `this` 指针访问当前对象。

~~~cpp
class Counter {
public:
    void SetValue(int value)
    {
        this->value = value;
    }

private:
    int value = 0;
};
~~~

要点：

- `this` 指向当前正在调用成员函数的对象。
- 普通非静态成员函数中可以使用 `this`。
- 静态成员函数没有 `this`，因为它不依附于某个具体对象。
- 在 const 成员函数中，不能通过 `this` 修改普通的非 mutable 数据成员。

### 5. 静态成员与非静态成员有什么区别？

~~~cpp
class Player {
public:
    static int count;
    int health = 100;
};

int Player::count = 0;
~~~

- 非静态数据成员属于每个对象，每个对象有自己的成员子对象。
- 静态数据成员属于类层面的共享实体，不会因为每创建一个对象就复制一份。
- 静态成员函数没有 `this`，不能直接访问某个对象的非静态成员。
- C++17 起，可以使用 `inline static` 在类内定义静态数据成员。

### 6. sizeof(对象) 会包含什么？

`sizeof` 得到对象的大小，包含其非静态数据成员及实现可能加入的填充等；对于具有虚函数的类，常见 ABI 通常还会为多态支持保存虚表指针等信息。

~~~cpp
struct A {
    char c;
    int x;
};
~~~

即使 `char` 占 1 字节、`int` 占 4 字节，`sizeof(A)` 也不一定等于 5，因为编译器可能为对齐加入 padding。

需要注意：

- 静态数据成员不计入每个对象的大小。
- 成员函数的机器码不作为每个对象的数据成员重复存储。
- 虚表和虚表指针的具体布局不是 C++ 标准规定的 ABI。
- 空类对象的大小通常至少为 1 字节，以保证不同的完整对象可以有不同地址。

## 二、构造函数与析构函数

### 1. 构造函数是什么？

构造函数在对象初始化时负责建立对象的初始状态。

~~~cpp
class Player {
public:
    Player()
        : health(100)
    {
    }

    explicit Player(int initialHealth)
        : health(initialHealth)
    {
    }

private:
    int health;
};
~~~

构造函数的特点：

- 名称与类名相同。
- 没有返回类型。
- 可以重载。
- 可以有默认参数。
- 不能声明为 virtual。
- 构造函数负责初始化对象，而不只是给已有对象赋值。

### 2. 什么是默认构造函数？

默认构造函数是可以在不提供实参的情况下调用的构造函数。

~~~cpp
class A {
public:
    A() {}
};

A a;
~~~

如果类没有任何用户声明的构造函数，编译器会在符合规则时隐式声明默认构造函数。

~~~cpp
class A {
public:
    A(int x) {}
};

// A a; // 错误：没有默认构造函数
A b(10);
~~~

**常见面试陷阱：** 用户声明了带参数的构造函数后，不能再假设编译器一定自动提供无参构造函数。

如果需要，可以显式写出：

~~~cpp
class A {
public:
    A() = default;
    explicit A(int x) {}
};
~~~

### 3. 什么是成员初始化列表？

~~~cpp
class Player {
public:
    Player(int hp, int id)
        : health(hp), playerId(id)
    {
    }

private:
    int health;
    const int playerId;
};
~~~

成员初始化列表直接初始化基类和成员子对象。

以下情况尤其需要或适合使用它：

- 初始化 const 数据成员。
- 初始化引用成员。
- 调用基类构造函数。
- 初始化没有默认构造函数的成员对象。
- 初始化其他成员对象，避免先默认构造再赋值。

### 4. 成员的实际初始化顺序是什么？

**实际顺序由声明顺序决定，而不是初始化列表里的书写顺序。**

~~~cpp
class A {
public:
    A()
        : y(20), x(10)
    {
    }

private:
    int x;
    int y;
};
~~~

这里先初始化 `x`，再初始化 `y`，尽管初始化列表把 `y` 写在前面。

更危险的例子：

~~~cpp
class A {
public:
    A()
        : y(2), x(y + 1)
    {
    }

private:
    int x;
    int y;
};
~~~

`x` 先初始化，此时 `y` 还没有完成初始化。用 `y` 的值初始化 `x` 是错误的设计，可能导致未定义行为。

正确做法是让初始化列表顺序与成员声明顺序一致，并避免读取尚未初始化的成员。

### 5. 构造函数执行时，对象按什么顺序初始化？

通常的初始化顺序是：

1. 虚基类（在最派生类对象的构造过程中）。
2. 直接基类，按基类列表的声明顺序。
3. 非静态数据成员，按成员声明顺序。
4. 构造函数体中的语句。

析构时，相关对象子部分按相反顺序销毁。

构造函数体开始执行之前，基类和成员子对象已经完成初始化。

### 6. 析构函数是什么？

析构函数在对象生命周期结束时执行清理工作。

~~~cpp
class A {
public:
    ~A()
    {
        // 清理本对象持有的资源
    }
};
~~~

要点：

- 析构函数名称为 `~类名`。
- 没有返回类型，不能带普通函数参数，也不能重载。
- 一个类最多有一个析构函数。
- 析构函数可以是 virtual。
- 析构函数不能正常抛出异常；析构期间让异常逃逸，尤其是在栈展开时，可能导致程序调用 `std::terminate`。

现代 C++ 通常通过 RAII，在析构函数中释放由对象持有的资源。

### 7. 构造与析构顺序题

~~~cpp
struct Member {
    Member()  { std::cout << "M+"; }
    ~Member() { std::cout << "M-"; }
};

struct Base {
    Base()  { std::cout << "B+"; }
    ~Base() { std::cout << "B-"; }
};

struct Derived : Base {
    Member m;

    Derived()  { std::cout << "D+"; }
    ~Derived() { std::cout << "D-"; }
};
~~~

创建并销毁 `Derived d;`，输出顺序为：

~~~text
B+ M+ D+ D- M- B-
~~~

原因是构造从基类到派生类；析构从派生类到基类，成员在析构函数体之后按声明顺序的逆序销毁。

## 三、拷贝构造与拷贝赋值

### 1. 什么是拷贝构造函数？

拷贝构造函数用一个同类型对象初始化一个新对象。

~~~cpp
struct A {
    int value = 0;

    A() = default;
    A(const A& other)
        : value(other.value)
    {
    }
};

A a;
A b(a); // 拷贝构造
A c = a; // 也是拷贝构造
~~~

这里的 `A c = a;` 是初始化，不是对已存在对象进行赋值。

### 2. 什么是拷贝赋值运算符？

拷贝赋值运算符给一个已经存在的对象赋予另一个对象的状态。

~~~cpp
A a;
A b;

b = a; // 拷贝赋值
~~~

常见签名为：

~~~cpp
A& operator=(const A& other);
~~~

通常返回 `*this` 的引用，以支持连续赋值：

~~~cpp
a = b = c;
~~~

### 3. 拷贝构造与拷贝赋值的区别

| 对比项 | 拷贝构造 | 拷贝赋值 |
|---|---|---|
| 使用场景 | 初始化新对象 | 修改已有对象 |
| 典型语法 | `A b = a;` | `b = a;` |
| 目标对象 | 尚未完成初始化的新对象 | 已经存在的对象 |
| 是否可能需要先清理目标原资源 | 通常不需要，因为目标对象尚未完成构造 | 经常需要，具体取决于资源管理策略 |

### 4. 哪些情况会调用拷贝构造？

~~~cpp
A a;
A b(a);
A c = a;

void foo(A value);
foo(a);
~~~

在没有发生适用的复制消除、且相关构造函数可用时，按值初始化参数等场景可能调用拷贝构造或移动构造。

不能机械地认为每次“看起来像复制”的代码都一定发生实际拷贝：编译器优化与 C++17 的纯右值规则会影响实际行为。

### 5. 编译器会生成默认拷贝构造吗？

如果没有用户声明的拷贝构造函数，编译器通常会隐式声明拷贝构造函数；但它可能被定义为删除状态，或者因成员、基类的性质而不可用。

隐式拷贝一般是逐成员拷贝：

- 基础类型成员按值复制。
- 类类型成员调用其对应的拷贝构造。
- 指针成员只复制地址，不会自动复制指针指向的资源。

因此，默认拷贝不意味着递归复制所有指针所指向的对象。

### 6. 默认构造函数和拷贝构造函数有什么关系？

~~~cpp
struct A {
    A(const A&) {}
};

// A a; // 错误：没有默认构造函数
~~~

用户声明了构造函数（包括用户声明的拷贝构造函数）后，不能再假设编译器自动生成默认构造函数。

如果既需要无参构造，又需要自定义拷贝构造，就要显式声明二者。

~~~cpp
struct A {
    A() = default;
    A(const A&) {}
};
~~~

### 7. 什么是浅拷贝与深拷贝？

~~~cpp
struct Buffer {
    int* data;
};
~~~

如果默认拷贝 `Buffer`，复制的是 `data` 里的地址；两个对象可能指向同一块动态内存。

这通常称为浅拷贝。

深拷贝则会为新对象分配独立资源，并复制相应数据。是否应该深拷贝取决于类的语义；共享资源也可以通过明确的共享所有权设计来管理。

### 8. 为什么裸指针成员容易导致重复释放？

~~~cpp
struct Buffer {
    int* data = nullptr;

    explicit Buffer(int value)
        : data(new int(value))
    {
    }

    ~Buffer()
    {
        delete data;
    }
};
~~~

若直接使用编译器生成的拷贝操作，两个 `Buffer` 对象会拥有相同的 `data` 地址。析构时可能对同一块内存重复 `delete`，导致未定义行为。

解决方案通常有三类：

1. 实现正确的深拷贝和资源管理操作。
2. 使用 `std::unique_ptr` 表达独占所有权，并明确类型不可拷贝。
3. 使用 `std::shared_ptr` 等明确表达共享所有权（仅在语义确实需要共享时）。

**面试要点：** 不能把“默认拷贝”理解成“深拷贝”。

## 四、移动语义与特殊成员函数

### 1. 什么是右值引用？

~~~cpp
int x = 10;
int& lref = x;
int&& rref = 20;
~~~

右值引用可以绑定到右值，是 C++11 移动语义和完美转发的重要基础。

但要注意：**有名字的右值引用变量本身是左值表达式。**

~~~cpp
void foo(A&& value)
{
    // value 这个表达式是左值
}
~~~

这也是为什么移动构造函数内部经常需要对成员使用 `std::move`。

### 2. 什么是移动构造函数？

移动构造函数用一个对象初始化新对象，并允许从源对象转移资源，而不是复制资源内容。

~~~cpp
struct Buffer {
    std::unique_ptr<int[]> data;

    explicit Buffer(std::size_t n)
        : data(std::make_unique<int[]>(n))
    {
    }

    Buffer(Buffer&& other) noexcept
        : data(std::move(other.data))
    {
    }
};
~~~

对于 `std::unique_ptr`，移动后所有权转移给目标对象，源对象仍然处于有效但通常不再拥有该资源的状态。

移动操作的具体语义由类定义决定；语言并不保证所有“移动”都比复制更快。

### 3. 什么是移动赋值运算符？

~~~cpp
A& operator=(A&& other) noexcept;
~~~

移动赋值处理一个已经存在的目标对象。通常需要：

1. 处理目标对象原本持有的资源。
2. 接管源对象的资源。
3. 保证源对象在操作后仍能安全析构。
4. 正确处理自移动赋值，或明确其支持边界。

使用智能指针、容器等标准资源管理类型通常比手写裸资源转移更安全。

### 4. std::move 到底做了什么？

~~~cpp
std::string a = "hello";
std::string b = std::move(a);
~~~

`std::move` 本身不移动任何资源。它主要将表达式转换为适合进行移动重载决议的右值类别（通常是 xvalue），随后是否发生移动取决于可用的构造函数、赋值运算符和具体类型。

移动之后，`a` 仍然是一个有效对象，但其具体值通常不应作额外假设；对标准库对象，应遵循对应类型对 moved-from 状态的规定。

### 5. 什么是完美转发？

完美转发通常使用转发引用、模板类型推导和 `std::forward` 保留实参的值类别。

~~~cpp
template<class T>
void Wrapper(T&& value)
{
    Process(std::forward<T>(value));
}
~~~

这里的 `T&&` 在模板类型推导的特定条件下是转发引用（也常称万能引用）。

注意：并非所有 `T&&` 都是转发引用。若 `T` 已经是固定类型或没有发生对应的模板推导，它通常就是普通右值引用。

### 6. 什么是 Rule of Three / Five / Zero？

- **Rule of Three：** 若类需要自定义析构函数、拷贝构造或拷贝赋值中的一个，通常需要认真审视另外两个是否也需要自定义。
- **Rule of Five：** C++11 引入移动语义后，还应考虑移动构造和移动赋值。
- **Rule of Zero：** 优先把资源交给 `std::string`、标准容器、智能指针等 RAII 类型管理，使自己的类不必显式编写这些特殊成员函数。

现代 C++ 设计通常优先遵循 Rule of Zero。

### 7. 编译器会自动生成哪些特殊成员函数？

通常所说的特殊成员函数包括：

- 默认构造函数。
- 拷贝构造函数。
- 拷贝赋值运算符。
- 移动构造函数。
- 移动赋值运算符。
- 析构函数。

这些函数的隐式声明、删除与生成条件并不完全相同，不能简化成“编译器永远生成全部六个”。

重要规则（面试常问）：

- 用户声明了任何构造函数后，通常不再隐式声明默认构造函数。
- 用户声明了拷贝构造或拷贝赋值等操作时，隐式移动操作的生成会受到限制。
- 用户声明了移动构造或移动赋值时，隐式拷贝操作会受到限制，部分情况下会被定义为删除。
- 用户声明析构函数也会影响隐式移动操作的生成。
- 成员或基类不可拷贝、不可移动时，相应特殊成员函数也可能被删除。

遇到具体代码时，应结合所有声明与成员类型判断，而不是只记单条口诀。

### 8. = default 与 = delete

~~~cpp
struct A {
    A() = default;
    A(const A&) = delete;
};
~~~

- `= default`：显式要求使用编译器默认生成的实现（前提是该操作可以生成）。
- `= delete`：明确禁止该函数被使用。

它们常用于控制类型的可构造性、可拷贝性和可移动性。

### 9. noexcept 与移动构造有什么关系？

容器扩容时，若元素类型可移动，标准库实现通常会考虑移动元素；但为了满足异常保证，某些操作会在移动可能抛异常而复制可用时选择复制。

因此，正确声明不抛异常的移动操作可以帮助标准库选择更合适的路径。

**不要为了性能而无条件给移动操作添加 noexcept。** 如果函数实际可能抛出异常，却声明为 `noexcept`，异常逃逸时程序会调用 `std::terminate`。

## 五、继承

### 1. 什么是继承？

继承允许派生类基于已有基类扩展状态与行为。

~~~cpp
class Animal {
public:
    void Eat() {}
};

class Dog : public Animal {
public:
    void Bark() {}
};
~~~

`Dog` 可以使用继承而来的 public 接口，并增加自己的成员。

### 2. public、protected、private 继承有什么区别？

| 继承方式 | 基类 public 成员在派生类接口中的可见性 | 基类 protected 成员在派生类接口中的可见性 |
|---|---|---|
| public 继承 | public | protected |
| protected 继承 | protected | protected |
| private 继承 | private | private |

基类的 private 成员仍然是基类私有成员，派生类不能直接访问它们；但这些成员仍属于基类子对象的一部分。

public 继承通常表达“派生类可以被当作基类使用”的 is-a 关系。

### 3. 派生类构造函数如何调用基类构造函数？

~~~cpp
class Base {
public:
    explicit Base(int value) {}
};

class Derived : public Base {
public:
    Derived()
        : Base(10)
    {
    }
};
~~~

构造派生类对象时，必须先构造基类子对象。如果基类没有可用的默认构造函数，派生类就需要显式调用合适的基类构造函数。

### 4. 构造和析构的继承顺序

~~~cpp
struct Base {
    Base() { std::cout << "Base"; }
    ~Base() { std::cout << "~Base"; }
};

struct Derived : Base {
    Derived() { std::cout << "Derived"; }
    ~Derived() { std::cout << "~Derived"; }
};
~~~

构造顺序：`Base`，然后 `Derived`。

析构顺序：`~Derived`，然后 `~Base`。

派生类对象销毁时，先执行派生类析构函数体，再销毁其成员，最后销毁基类子对象。

### 5. 什么是函数重写（override）？

当派生类声明与基类虚函数匹配的函数时，可以重写基类虚函数。

~~~cpp
struct Base {
    virtual void Update(int value) {}
};

struct Derived : Base {
    void Update(int value) override {}
};
~~~

建议使用 `override`，让编译器检查该函数是否确实重写了基类虚函数。

注意：函数名相同不等于重写成功。参数列表、cv 限定、引用限定等条件都会影响匹配；返回类型也必须符合重写规则（允许特定的协变返回类型）。

### 6. 重载、重写、隐藏有什么区别？

| 概念 | 主要含义 |
|---|---|
| 重载（overload） | 同一作用域中同名函数拥有不同参数列表，由重载决议选择 |
| 重写（override） | 派生类重写基类的虚函数，支持动态派发 |
| 名称隐藏（name hiding） | 派生类声明同名成员后，基类同名成员可能在普通名称查找中被隐藏 |

例如：

~~~cpp
struct Base {
    void Foo(int) {}
    virtual void Bar() {}
};

struct Derived : Base {
    void Foo(double) {} // 名称隐藏：Base::Foo(int) 不会自动加入本层重载集合
    void Bar() override {} // 重写虚函数
};
~~~

如果确实需要在派生类作用域里重新引入基类的重载，可以使用：

~~~cpp
using Base::Foo;
~~~

### 7. 什么是 final？

~~~cpp
struct Base {
    virtual void Update() final {}
};

struct Derived final : Base {};
~~~

- 类声明为 `final` 后，不能再被继承。
- 虚函数声明为 `final` 后，派生类不能继续重写它。

`final` 可以表达设计意图，也有助于编译器进行某些优化。

## 六、多态与虚函数

### 1. 什么是多态？

C++ 面向对象语境中，常见的多态包括：

- 编译期多态：函数重载、模板等。
- 运行期多态：通过继承与虚函数，在运行时根据实际动态类型选择重写实现。

~~~cpp
struct Animal {
    virtual void Speak() const
    {
        std::cout << "Animal";
    }

    virtual ~Animal() = default;
};

struct Dog : Animal {
    void Speak() const override
    {
        std::cout << "Dog";
    }
};

Dog dog;
Animal* animal = &dog;
animal->Speak(); // Dog
~~~

指针的静态类型是 `Animal*`，但它指向的对象动态类型是 `Dog`。由于 `Speak` 是虚函数，调用会进行动态派发。

### 2. 静态类型与动态类型有什么区别？

- 静态类型：编译期由表达式声明等信息确定的类型。
- 动态类型：多态对象在运行时的实际最派生类型。

~~~cpp
Animal* p = new Dog;
~~~

这里 `p` 的静态类型是 `Animal*`，所指完整对象的动态类型是 `Dog`。

动态派发只适用于符合规则的虚函数调用；普通非虚函数调用根据静态类型进行名称查找和绑定。

### 3. 虚函数是什么？

在基类成员函数前使用 `virtual`，可以让符合重写规则的派生类实现参与运行时动态派发。

~~~cpp
struct Base {
    virtual void Run() {}
};
~~~

如果通过基类指针或引用调用该虚函数，通常会根据对象动态类型选择最终重写实现。

虚函数的语义由 C++ 标准规定；虚函数表（vtable）、虚表指针（vptr）是主流 ABI 常用的实现方式，不是标准强制要求的具体内存布局。

### 4. 虚函数表和虚表指针是什么？

在常见的编译器 ABI 实现中：

- 虚函数表（vtable）保存支持虚函数动态派发所需的函数入口等信息。
- 虚表指针（vptr）通常保存在多态对象或其相应子对象布局中，用于关联相关虚表。
- 通过基类指针调用虚函数时，编译器生成的代码通常会利用这些信息找到最终调用目标。

必须区分语言保证与实现细节：

- 标准保证虚函数的动态派发语义。
- 标准没有规定 vtable 的具体结构、名称、存储位置或函数入口排列。
- 对象大小是否增加、增加多少，以及多重继承时 vptr 如何安排，都取决于实现和 ABI。

### 5. 类里只要有虚函数，对象大小一定增加一个指针吗？

不能作为标准层面的绝对结论。

常见 ABI 通常会让多态对象包含虚表指针等实现数据，因此 `sizeof` 常常会增大。但 C++ 标准没有规定必须使用 vptr，也没有规定一个类恰好增加一个指针大小。

此外，多重继承、虚继承、空基类优化和对象对齐都会影响最终布局。

### 6. 为什么基类析构函数经常需要声明为 virtual？

~~~cpp
struct Base {
    virtual ~Base() = default;
};

struct Derived : Base {
    ~Derived() override = default;
};

Base* p = new Derived;
delete p; // 基类析构函数是 virtual，能够正确销毁派生类对象
~~~

如果通过基类指针删除派生类对象，而基类析构函数不是虚函数，通常会导致未定义行为。

因此，**当一个类设计为通过基类指针删除派生类对象时，基类通常应提供 public virtual 析构函数。**

如果基类不打算支持这种删除方式，也可以考虑 protected 非虚析构函数，以在接口层面禁止通过基类指针删除。

### 7. 构造函数可以是虚函数吗？

不可以。

创建对象时，派生类部分尚未完成构造，无法像普通运行期虚函数调用那样对完整的最终对象执行动态派发。

如果需要类似“根据类型创建对象”的行为，可以考虑虚拟工厂、工厂函数或其他多态创建模式。

### 8. 析构函数可以是虚函数吗？

可以，而且多态基类通常应该有虚析构函数。

~~~cpp
struct Base {
    virtual ~Base() = default;
};
~~~

析构函数可以是纯虚函数，但纯虚析构函数仍然必须提供定义，因为销毁派生类对象时最终仍要执行基类析构部分。

### 9. 构造函数或析构函数中调用虚函数会怎样？

~~~cpp
struct Base {
    Base()
    {
        Show();
    }

    virtual void Show()
    {
        std::cout << "Base";
    }

    virtual ~Base()
    {
        Show();
    }
};

struct Derived : Base {
    void Show() override
    {
        std::cout << "Derived";
    }
};
~~~

在基类构造函数或基类析构函数执行期间，对该对象调用虚函数时，不会派发到尚未构造或已经析构的更派生部分；上例中的调用会执行 `Base::Show()`。

这是因为对象的构造与析构按层次逐步进行，不能把构造函数体中看到的对象当作已经完整构造的最终派生对象。

### 10. 什么是纯虚函数与抽象类？

~~~cpp
struct Shape {
    virtual double Area() const = 0;
    virtual ~Shape() = default;
};
~~~

`= 0` 声明纯虚函数。

包含至少一个纯虚函数、且没有被最终重写到不再抽象状态的类，是抽象类，不能直接创建该类的对象。

~~~cpp
// Shape s; // 错误：Shape 是抽象类
~~~

抽象类可以拥有数据成员、构造函数、普通成员函数和析构函数，也可以提供纯虚函数的定义。

### 11. 什么是虚函数的协变返回类型？

~~~cpp
struct Base {
    virtual Base* Clone() const;
};

struct Derived : Base {
    Derived* Clone() const override;
};
~~~

重写虚函数时，返回类型在满足协变规则的条件下，可以从基类指针或引用改为派生类指针或引用。

这不是任意返回类型变化；需要满足语言对协变返回类型的要求。

## 七、对象切片与多重继承

### 1. 什么是对象切片（Object Slicing）？

~~~cpp
struct Base {
    virtual void Speak() const
    {
        std::cout << "Base";
    }

    virtual ~Base() = default;
};

struct Derived : Base {
    int extra = 10;

    void Speak() const override
    {
        std::cout << "Derived";
    }
};

Derived d;
Base b = d; // 对象切片
b.Speak();  // Base
~~~

把派生类对象按值复制到基类对象时，目标只包含一个独立的基类对象，派生类特有的部分不会被保留，这称为对象切片。

避免切片的常见方法是通过基类引用或指针使用多态对象，或使用合适的值类型设计。

### 2. 为什么多态接口通常用引用或指针？

~~~cpp
void Speak(const Animal& animal)
{
    animal.Speak();
}
~~~

引用参数不会创建一个新的基类值对象，因此不会因为参数按值复制而切掉派生类部分。

指针与引用也能表达不拥有对象的多态访问关系。若涉及对象所有权，则需要另外设计资源管理方式。

### 3. 什么是多重继承？

~~~cpp
struct Flyable {
    virtual void Fly() = 0;
    virtual ~Flyable() = default;
};

struct Swimmable {
    virtual void Swim() = 0;
    virtual ~Swimmable() = default;
};

struct Duck : Flyable, Swimmable {
    void Fly() override {}
    void Swim() override {}
};
~~~

多重继承允许一个类直接继承多个基类。

它可以表达多个接口或能力，但也会带来名称冲突、基类子对象布局复杂、类型转换歧义等问题。

### 4. 多重继承为什么可能出现二义性？

~~~cpp
struct A {
    int value = 1;
};

struct B : A {};
struct C : A {};
struct D : B, C {};
~~~

`D` 中存在两份 `A` 子对象。

~~~cpp
D d;
// d.value; // 二义性：来自 B::A 还是 C::A？
~~~

可以通过明确的基类路径消除部分访问歧义：

~~~cpp
d.B::value;
d.C::value;
~~~

如果设计语义上应该共享同一个共同基类子对象，可以考虑虚继承。

### 5. 什么是虚继承？

~~~cpp
struct A {
    int value = 1;
};

struct B : virtual A {};
struct C : virtual A {};
struct D : B, C {};
~~~

在这个菱形继承结构中，`D` 只包含一个共享的虚基类 `A` 子对象。

虚继承用于解决菱形继承中共同基类子对象重复的问题。

注意：虚继承会让构造顺序、对象布局和访问路径更复杂；不应该仅仅因为名字重复就机械地使用虚继承。

### 6. 虚基类由谁初始化？

在构造最派生类对象时，虚基类由最派生类负责初始化。

~~~cpp
struct A {
    explicit A(int) {}
};

struct B : virtual A {
    B() : A(1) {}
};

struct C : virtual A {
    C() : A(2) {}
};

struct D : B, C {
    D() : A(3), B(), C() {}
};
~~~

构造 `D` 对象时，`A(3)` 负责初始化唯一的虚基类 `A`。`B` 和 `C` 构造函数中对 `A` 的初始化在构造最派生类 `D` 时不负责最终初始化这个虚基类。

### 7. 多重继承中的 this 指针有什么值得注意的地方？

在常见 ABI 实现中，同一个完整对象的不同基类子对象可能位于不同偏移处。

因此，从派生类对象转换到某个基类子对象时，指针数值可能需要调整；调用虚函数时，实现也可能需要调整 `this` 指针。

不要假设不同基类子对象的地址一定与完整对象地址相同，也不要自行依赖具体 ABI 的对象布局。

## 八、类型转换与 RTTI

### 1. static_cast、dynamic_cast、const_cast、reinterpret_cast 有什么区别？

| 转换方式 | 主要用途 | 重要限制 |
|---|---|---|
| `static_cast` | 允许的常规显式转换、相关基类/派生类转换等 | 不进行运行期多态类型检查 |
| `dynamic_cast` | 对多态类层次进行运行期安全检查；也支持相关向上转换 | 运行期检查要求和目标类型有关；常见向下转换要求源类型是多态类 |
| `const_cast` | 添加或移除 cv 限定 | 不可通过它合法修改原本声明为 const 的对象 |
| `reinterpret_cast` | 某些低层次、重新解释类型的转换 | 不能保证转换后的指针可安全解引用或满足目标类型要求 |

转换操作应以语义为依据，不要为了让代码编译而随意使用 `reinterpret_cast`。

### 2. dynamic_cast 怎么使用？

~~~cpp
struct Base {
    virtual ~Base() = default;
};

struct Derived : Base {
    void Run() {}
};

Base* base = new Derived;

if (Derived* derived = dynamic_cast<Derived*>(base)) {
    derived->Run();
}

delete base;
~~~

对指针执行失败的运行期转换会得到空指针；对引用执行失败的相应转换会抛出 `std::bad_cast`。

向下转换或交叉转换通常需要源类型是多态类，也就是包含或继承至少一个虚函数的类。向上转换一般可以通过普通隐式转换完成。

### 3. 什么是 RTTI？

RTTI（Run-Time Type Information，运行时类型信息）是 C++ 提供的运行期类型信息机制，常见接口包括：

- `dynamic_cast`
- `typeid`

~~~cpp
Base* p = new Derived;
std::cout << typeid(*p).name();
delete p;
~~~

如果表达式的静态类型是多态类的 glvalue，`typeid` 可以报告所指对象的动态类型；否则通常基于静态类型判断。`typeid(...).name()` 返回的字符串形式由实现决定，不应依赖它在不同编译器之间完全一致。

### 4. 什么时候优先考虑虚函数，而不是 dynamic_cast？

如果程序主要是根据对象实际类型执行不同操作，通常优先考虑虚函数，把行为放在多态接口中。

如果确实需要根据具体派生类型访问额外能力、处理异构类型集合或实现特殊的交叉转换，`dynamic_cast` 可能合适。

这属于设计判断，不是“dynamic_cast 永远不能用”的绝对规则。

## 九、运算符重载

### 1. 什么是运算符重载？

运算符重载允许为用户自定义类型定义运算符的行为。

~~~cpp
struct Vec2 {
    float x = 0;
    float y = 0;

    Vec2 operator+(const Vec2& rhs) const
    {
        return {x + rhs.x, y + rhs.y};
    }
};
~~~

~~~cpp
Vec2 a{1, 2};
Vec2 b{3, 4};
Vec2 c = a + b;
~~~

要点：

- 不能创建新的运算符符号。
- 不能改变运算符的优先级、结合性或操作数个数。
- 至少一个操作数需要是用户定义类型（或其相关类型）。
- 某些运算符必须作为成员函数重载，另一些既可使用成员函数也可使用非成员函数；具体受语言规则限制。

### 2. 前置 ++ 与后置 ++ 为什么通常这样写？

~~~cpp
struct Counter {
    int value = 0;

    Counter& operator++()
    {
        ++value;
        return *this;
    }

    Counter operator++(int)
    {
        Counter old = *this;
        ++(*this);
        return old;
    }
};
~~~

- 前置 `++x` 通常返回递增后的对象引用。
- 后置 `x++` 用额外的 `int` 形参区分重载，通常返回递增前的旧值。

这里的额外 `int` 只是用于区分后置版本的占位参数。

### 3. 为什么 operator= 通常返回引用？

~~~cpp
A& operator=(const A& rhs)
{
    if (this != &rhs) {
        // 复制 rhs 的状态
    }
    return *this;
}
~~~

返回 `A&` 可以支持连续赋值，并避免为赋值表达式额外构造一个返回值。

上例仅用于说明常见签名；资源管理类应根据自身语义实现完整且异常安全的赋值操作，或优先使用编译器生成的操作与 RAII 成员。

## 十、类与对象高频追问

### Q1：构造函数可以是虚函数吗？

不能。构造阶段对象的派生部分尚未完成构造，不能对最终完整对象执行通常意义上的虚函数动态派发。

### Q2：析构函数可以是虚函数吗？

可以。多态基类若允许通过基类指针删除派生类对象，通常应提供 public virtual 析构函数。

### Q3：拷贝构造和拷贝赋值的区别是什么？

拷贝构造用于初始化新对象，拷贝赋值用于修改已有对象。

### Q4：编译器生成的默认拷贝是深拷贝吗？

不是。它通常逐成员拷贝，指针成员复制的是地址值，并不会自动复制指向的资源。

### Q5：std::move 会执行移动吗？

不一定。它主要进行值类别转换，让移动构造或移动赋值有机会参与重载决议；最终行为取决于类型与可用操作。

### Q6：有名字的 T&& 变量是什么值类别？

表达式 `value` 是左值，即使它的声明类型是 `T&&`。需要转发时通常使用 `std::forward<T>(value)`；明确要把资源作为可移动来源时可以使用 `std::move(value)`。

### Q7：为什么建议使用 override？

它让编译器验证函数是否确实重写了基类虚函数，能够发现参数、cv 限定等不匹配问题。

### Q8：虚函数表是 C++ 标准规定的吗？

不是。虚函数的动态派发行为由标准规定，vtable 和 vptr 是常见实现方式，其具体布局由 ABI 和编译器实现决定。

### Q9：什么是对象切片？

派生类对象按值转换为基类对象时，目标只保留基类子对象部分，派生类特有部分丢失。

### Q10：虚继承解决什么问题？

它让菱形继承结构中的最派生对象共享一个虚基类子对象，避免共同基类重复出现。

### Q11：为什么析构顺序和构造顺序相反？

构造时先建立基类和成员子对象，再执行派生类构造；销毁时先执行派生类析构，再依次销毁成员和基类子对象。

### Q12：类声明了自定义析构函数，会影响移动操作吗？

会。用户声明析构函数会影响编译器隐式移动构造和移动赋值的生成。遇到具体类时，应检查其所有特殊成员函数声明及各成员的可移动性。
